## 为什么

当前系统已经提供了报表和语音任务入口，但 Hermes 仍然只是一个占位适配器，并没有真正执行任务。现在需要把 Hermes 初始化并接入当前项目，使演示系统从“模拟任务流”升级为“真实可执行的自动化任务层”，支持报表生成、播报稿生成和每日总结。

## 变更内容

- 将 Hermes 初始化为本项目中的一等运行组件，并且仅在当前工作区内运行。
- 用真实执行适配器替换现有 Hermes 占位实现，使后端能够调用 Hermes 处理任务。
- 增加 Hermes 的工作区本地配置、按任务初始化和环境校验流程。
- 定义报表生成、语音播报稿生成和每日总结的任务契约。
- 通过现有任务 API 和前端任务中心展示 Hermes 的执行结果和失败信息。
- 补充运行说明和验证步骤，确保本项目在本地即可启动 Hermes。

## 能力

### 新增能力
- `hermes-bootstrap-config`：初始化 Hermes 运行配置、必需环境变量、工作区本地状态目录和启动校验。
- `hermes-task-execution`：在当前工作区内通过 Hermes 执行后台任务，并保存任务输出、状态和错误。
- `hermes-operator-workflows`：提供基于 Hermes 的报表生成、播报稿生成和每日总结工作流。

### 修改能力

无。

## 影响范围

- 受影响代码：`services/api/app/services/hermes.py`、任务编排、任务结果持久化、启动脚本以及前端任务展示。
- 受影响接口：`/api/tasks`、`/api/tasks/{task_id}`，以及分析后自动派生任务的行为。
- 新增依赖或系统：工作区本地 Hermes 运行方式、项目级 Hermes 配置、按任务初始化的资源目录、产物输出目录和运行文档。
