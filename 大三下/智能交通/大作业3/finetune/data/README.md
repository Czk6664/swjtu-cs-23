# TravelQA 微调数据

运行以下命令离线生成数据：

```powershell
python finetune/build_dataset.py
```

生成文件：

| 文件 | 用途 |
| --- | --- |
| `sft.jsonl` | 全量 Alpaca 格式样本，便于检查和导入其他训练框架 |
| `train.jsonl` | LoRA 训练集，当前配置默认读取此文件 |
| `val.jsonl` | LoRA 验证集 |
| `stats.json` | 样本数量、类别分布、随机种子和质量审计摘要 |

每行至少包含 `instruction`、`input`、`output` 三个字段；附加的 `category` 和
`source` 用于审计样本类别和来源，`group_id` 用于把同一事实或同一工具场景的
释义变体放在同一数据划分中，避免训练集与验证集发生语义泄漏。

结构化公共数据样本覆盖公交、轨道交通、停车、收费站和开放目录元数据。天气与路径
规划只保留少量显式标记的工具结果解释样本，以及“先调用工具再回答”的行为样本；
这些示例不代表实时事实。工具不可用和拒答样本用于训练边界。

构建器会拒绝包含 `None`、`/example/` 占位公告 URL、无工具结果输入的路线或天气答案，
以及工具类高重复输出。新都公交源文件中未公开具体时刻的 `定班制` 线路保留在原始归档，
但不会进入 SFT。开放目录的下载格式按逗号分隔字段解析，不依赖正则猜测。
离线样例公告只用于跑通 RAG，不进入 SFT 训练集。

数据构建过程完全离线，不会下载模型。
