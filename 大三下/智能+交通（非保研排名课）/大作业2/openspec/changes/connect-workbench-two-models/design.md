## Context

当前工作台页面已经具备完整的信息架构与 Airtable 风格视觉设计，但仍停留在静态展示状态：检测指标、预测指标、风险等级和模块说明均为预设文本，页面无法真正接收用户输入，也无法触发 YOLO11n 和 STAEformer 两个模型的运行。为了让高阶方案从“可展示”升级为“可演示”，需要让工作台具备双模型调用能力。

本次改动涉及前端页面、模型调用桥接层和结果回显逻辑，属于跨模块变更。由于现有两个模型分属不同工程：大作业2中的 YOLO11n 基于图像输入进行交通标志检测，大作业1中的 STAEformer 基于历史流量数据进行多步预测，因此本次设计重点是定义一条最小可行的本地调用链路，而不是构建完整在线服务。

系统使用者主要是课程项目展示者和答辩评审者。当前阶段最重要的是保证可演示性、结果可解释性以及页面交互顺畅性。

## Goals / Non-Goals

**Goals:**
- 让工作台页面能够真正触发交通目标识别模型和交通流预测模型。
- 为两个模型定义统一且可落地的本地调用桥接方式。
- 支持前端输入、运行中状态显示、结果回显和错误提示。
- 保持工作台整体风格继续遵循根目录 `design.md` 的 Airtable 风格系统。
- 优先实现最小可演示版本，便于课程汇报和答辩使用。

**Non-Goals:**
- 不在本次设计中重构 YOLO11n 或 STAEformer 核心模型结构。
- 不要求引入完整数据库、登录系统或线上 API 服务。
- 不要求两个模型共享训练数据或做联合训练。
- 不要求一次性实现生产级任务调度、缓存和并发控制。

## Decisions

### Decision 1: 采用“静态前端 + 本地桥接 API”模式

工作台前端继续保留当前 HTML/CSS 展示层，但新增一个轻量本地桥接服务，用来接收页面请求并调用两个模型。

**Rationale**
- 最符合当前课程项目节奏，工作量可控。
- 能最大化复用现有页面设计和模型脚本。
- 比直接在浏览器中嵌入模型逻辑更稳妥，也比完整重做后端更轻量。

**Alternatives considered**
- 纯静态页面 + 假数据：无法满足“页面可以调用两个模型”的目标。
- 复杂全栈服务：实现成本过高，不适合当前阶段。

### Decision 2: 检测模型采用“图像上传/路径输入 -> YOLO11n 推理 -> 结构化 JSON 结果”流程

检测模块桥接接口接收一张图像或图像路径，调用大作业2中的 YOLO11n 推理脚本，并统一返回：

- 图像路径
- 检测到的类别列表
- 边界框数量
- 预测结果图路径
- 关键统计指标

**Rationale**
- 这与现有检测流程最兼容。
- 页面只需要读取结构化结果即可，不必关心模型内部细节。

### Decision 3: 预测模型采用“案例选择/数据集选择 -> STAEformer 结果读取 -> 趋势 JSON 返回”流程

预测模块优先不重新训练，而是桥接读取已有 STAEformer 结果文件，或者调用简单预测脚本读取已有模型输出，返回：

- 使用的数据集名称
- MAE/RMSE/MAPE
- 多步预测值或趋势摘要
- 模型名称

**Rationale**
- 大作业1已有现成结果，优先保证联动演示成功。
- 比重新做训练触发更稳，更适合本地工作台联动。

**Alternatives considered**
- 页面直接启动完整训练流程：耗时长，不适合作为演示入口。
- 只显示固定指标：无法体现“调用模型”。

### Decision 4: 前端交互采用“双输入区 + 统一结果区”布局

页面新增两个独立的输入入口：

- 检测模型输入区：上传图像 / 选择样例图
- 预测模型输入区：选择预测案例 / 数据集

调用后结果统一汇总到结果区和态势区。

**Rationale**
- 两个模型输入类型不同，分开输入更自然。
- 统一结果区更利于展示模块协同。

### Decision 5: 融合结果采用规则式解释

页面不在当前阶段引入额外融合模型，而是依据检测结果和预测结果的结构化输出，生成态势摘要、风险等级和文字解释。

**Rationale**
- 可解释性强，适合答辩。
- 与当前高阶方案设计保持一致。

## Risks / Trade-offs

- [两个模型工程路径不同] → 使用统一桥接层屏蔽路径差异，并通过配置文件或常量集中管理。
- [预测模块缺少实时在线推理链路] → 先支持读取已有结果或轻量调用脚本，确保可演示，后续再增强。
- [本地调用依赖环境配置] → 在实现时补充一键启动说明和最小依赖说明。
- [页面交互增多可能破坏原有展示简洁性] → 保持输入区和结果区结构清晰，延续 Airtable 风格卡片布局。
- [Windows 编码与路径问题可能再次出现] → 统一使用 UTF-8 文件、相对路径和安全解码逻辑。

## Migration Plan

1. 保留现有静态工作台页面结构与视觉风格。
2. 新增本地桥接服务或统一脚本，定义检测调用接口和预测调用接口。
3. 为前端增加表单、按钮、加载状态和结果回显区域。
4. 用现有主实验结果和预测结果先打通联调，确认页面能正确触发两个模块。
5. 最后补充运行说明，确保课程展示时可重复演示。

## Open Questions

- 预测模块第一版是否只支持读取已有结果文件，还是需要支持真正执行一次推理。
- 工作台最终是否需要在单机环境下“一键启动”，还是分为页面和桥接脚本两步运行。
- 是否需要在第一版中加入检测样例图库，降低答辩现场上传图片失败的风险。
