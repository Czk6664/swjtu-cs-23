# 大小模型协同的智能交通管理决策系统 —— 设计文档

> 本文档为期末作业（capstone）的设计稿。当前阶段**只完善设计，暂不落代码**。
> 已锁定决策：独立 `期末作业/` 包；数据飞轮采用 **Parquet + 文件** 持久化；存储不复用根应用的内存态。

---

## 1. 项目概述

### 1.1 目标

将本课程三个大作业整合为一个**可持续自我优化**的智能交通管理决策系统：

- **大作业1（交通流预测，STAEformer）**、**大作业2（交通标志检测，YOLO/TT100K）** 作为
  **小模型（专才）**，负责高频、廉价、结构化的感知与预测；
- **大作业3（DeepSeek + 本地 RAG 出行问答系统）** 提供**对话式自然语言接口**与**本地知识库**，
  是大模型层的载体——它已实现 意图路由 → 检索/工具调用 → 大模型组织回答 的骨架；
- 引入**大模型（通才 LLM）** 作为决策与编排层，负责路由、融合、解释、生成（在大作业3 已有骨架上扩展）；
- 用**数据飞轮（Data Flywheel）** 把系统运行产生的数据回流，定期重训并优化小模型与 RAG 知识库，形成闭环。

一句话：**小模型做事、大模型做决策、数据飞轮让小模型越用越准。**

### 1.2 与既有工作的关系

| 来源 | 在本系统中的角色 | 模型规模 | 可复用产物 |
|------|------------------|----------|-----------|
| `大作业1` | 交通流预测 | 小（专才） | `results/*.json` 指标、STAEformer 训练/推理代码、METRLA/PEMS 数据 |
| `大作业2` | 交通标志/目标检测 | 小（专才） | YOLO 训练/验证/预测脚本、TT100K 12 类映射、`results.csv`、混淆矩阵 |
| `大作业3` | 对话式出行问答 + RAG 知识库（DeepSeek/Dify） | 大模型层载体 | 意图路由 `router.py`、RAG 知识库、LLM provider 抽象、天气/路径/预测/检测工具、微调脚本 |
| 根 `services/api` | FastAPI 编排 + WSL-Hermes 异步任务 | — | 请求流、任务管理器、报告/语音生成管线 |
| 根 `apps/web` | React 操作台 UI | — | 场景分析、任务轮询、图表展示 |

> 复用优先：根后端的 `DecisionService` 当前是**规则桩**，且代码里已标注"待替换为真实 LLM 调用"，
> OpenAI 配置（`OPENAI_BASE_URL/KEY/MODEL`）也已接好。本系统正是这个升级 + 飞轮闭环。

## 2. 大小模型协同架构

### 2.1 按"成本/能力"分工

```
   用户自然语言提问
          │  (大作业3 对话接口)
          ▼
 ┌─────────────────────────────────────────────┐      ┌──────────────────┐
 │            大模型编排层 (LLM)                 │◀────▶│ RAG 知识库(大作业3)│
 │  route → fuse → decide → explain → curate     │      │ 成都交管发布栏等   │
 └───┬───────────────────┬───────────────────────┘      └──────────────────┘
     │ 调用               │ 调用
 ┌───▼────────┐    ┌──────▼──────┐
 │ 预测小模型 │    │ 检测小模型  │   ← 专才，高频、廉价、结构化（大作业1 / 大作业2）
 │ STAEformer │    │   YOLO      │
 └───┬────────┘    └──────┬──────┘
     │                    │
     ▼                    ▼
  推理输出 + 置信度 + 遥测 ──────────▶  数据飞轮（采集/挖掘/重训/晋升）
       (问答日志 + 检索命中 + 用户反馈 一并入飞轮)
```

### 2.2 大模型的五项职责

1. **Route 路由** —— 根据请求决定调用哪些小模型/知识库（如"只看拥堵"→ 仅预测；"路口风险"→ 预测+检测；
   "限行规定"→ RAG 知识库）。复用大作业3 已实现的意图路由。
2. **Fuse 融合** —— 把预测、检测与 RAG 检索到的知识融合为统一的态势判断/答案（含风险等级）。
3. **Decide & Explain 决策与解释** —— 给出建议动作 + 风险等级 + **可解释、可溯源的理由**（替换根 `DecisionService` 桩）。
4. **Generate 生成** —— 报告 / 语音播报 / 每日总结（复用根 WSL-Hermes 任务管线）。
5. **Curate 策展（飞轮）** —— 标记低置信、模型分歧、异常样本与低质问答，喂给飞轮做重训/重建知识库的数据。

### 2.3 大模型 vs 小模型边界（设计原则）

- 小模型**不做自然语言推理**，只产出结构化数值（预测序列、检测框+类别+置信度）。
- 大模型**不做密集感知**，只在需要"判断/解释/编排/标注/对话"时按需调用，控制成本。
- 二者通过**薄适配器**解耦：重训出的新 checkpoint 用**配置切换**，不改编排代码。

## 3. 模块设计（独立 `期末作业/` 包，提议结构）

> 当前阶段不创建，待用户决定开始实现后再落地。

```text
期末作业/
├── orchestration/        # 大模型层（可直接基于大作业3 的 router/rag/app 扩展）
│   ├── router.py         # 选择调用哪些小模型/知识库（复用大作业3 意图路由）
│   ├── fusion.py         # 融合 预测+检测+RAG 知识
│   ├── decision.py       # LLM 决策（含理由），替换根 DecisionService 桩
│   └── prompts/          # 决策/解释/标注 提示词模板
├── models/               # 小模型适配器（不拷贝权重进来，按路径引用）
│   ├── forecast.py       # 包 大作业1 STAEformer 推理 + checkpoint
│   ├── detection.py      # 包 大作业2 YOLO 推理 + checkpoint
│   └── dialog_rag.py     # 接 大作业3 出行问答：DeepSeek + 本地 RAG 知识库
├── flywheel/             # 数据飞轮（核心新增）
│   ├── collector.py      # 推理 + 遥测落 Parquet
│   ├── miner.py          # 难例/漂移 选择规则
│   ├── labeler.py        # 自动(LLM) + 人工复核 标注
│   ├── trainer.py        # 重训触发 + 任务（复用 Hermes/异步任务模式）
│   ├── evaluator.py      # 基准评估 + 回归门控
│   └── registry.py       # 模型版本注册表 + 回滚
├── data/                 # Parquet 遥测 + 数据集快照（大文件 gitignore）
├── configs/              # 阈值、调度、模型路径、数据集 的 YAML
├── scripts/              # run_pipeline.py / trigger_retrain.py / evaluate.py
└── design.md / docs/     # 本设计 + 报告
```

设计原则：把**编排逻辑**与**每个小模型**隔离在 `models/` 适配器之后，换 checkpoint 只改配置。

## 4. 数据飞轮（数据飞轮）—— 核心贡献

这是本系统**唯一全新**的部分，也是期末作业的重点。

### 4.1 闭环

```
 部署小模型 ─▶ 对实时/回放交通数据推理
      ▲                       │
      │                       ▼
 重训 & 评估           采集 推理结果 + 遥测
      ▲                       │
      │                       ▼
 策展数据集 ◀── 挖掘难例（低置信 / 模型分歧 / 漂移 / 新类标志 /
 (自动+LLM+人工标注)      操作员纠正 / 用户问答低分反馈）
```

### 4.2 六个环节

| 环节 | 职责 | 关键点 |
|------|------|--------|
| **采集 Collection** | 每次推理/问答落盘：输入引用、输出、置信度、时间戳、模型版本 | 落 **Parquet**（按 日期/模型 分区） |
| **难例挖掘 Mining** | 选出值得重训/重建知识库的样本 | 低检测置信；预测误差超阈（待真值到达）；**大小模型分歧**；OOD/新标志；操作员纠正；问答低分/检索未命中 |
| **策展标注 Curation** | 自动 LLM 标注 + 可选人工复核 | 每个数据集快照**版本化**，重训可复现 |
| **重训触发 Retrain** | 定时 + 阈值（漂移/难例累积） | 复用根 `hermes.py` + `task_manager.py` 的异步任务承载长任务 |
| **门控晋升 Promotion** | 重训→评估→对比生产 checkpoint→优于且无安全回归才晋升 | **绝不自动上线**；保留旧 checkpoint 可回滚 |
| **监控 Monitoring** | 跟踪各模型随时间的精度 + 数据/概念漂移 | 证明飞轮在"变好"而非"变差" |

### 4.3 设计原则

> **飞轮必须可观测、可回滚。** 每次重训都能追溯到一个数据集快照，并能与上一版对比，一条命令回滚。

### 4.4 存储方案（Parquet + 文件，已锁定）

无数据库服务，全部落本地文件：

```text
期末作业/data/
├── telemetry/                              # 推理遥测（列式 Parquet，按日期/模型分区）
│   ├── model=forecast/date=2026-05-26/part-*.parquet
│   ├── model=detection/date=2026-05-26/part-*.parquet
│   └── model=dialog_rag/date=2026-05-26/part-*.parquet   # 问答日志: 问题/意图/检索命中/答案/反馈
├── snapshots/                              # 版本化数据集快照
│   ├── detection_v3/                       # 实际样本 + manifest
│   │   ├── manifest.json                   # 来源、样本数、标注方式、生成时间、哈希
│   │   └── ...
│   └── forecast_v2/...
└── registry/
    └── models.json                         # 模型注册表（见 4.6）
```

**遥测 Parquet 建议字段（每条推理一行）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `inference_id` | str (uuid) | 主键 |
| `model_name` | str | forecast / detection / dialog_rag |
| `model_version` | str | 对应 registry 里的版本 |
| `ts` | timestamp | 推理时间 |
| `input_ref` | str | 输入数据引用（路径/帧号/场景 id），不存大 blob |
| `output` | str (json) | 结构化输出（预测序列 / 检测框列表 / 事件） |
| `confidence` | float | 置信度或代理指标 |
| `ground_truth_ref` | str | nullable，真值到达后回填 |
| `big_model_verdict` | str (json) | nullable，大模型对此样本的判断/纠正 |
| `flagged_reason` | str | nullable，被难例挖掘选中的原因 |

> 选 Parquet 的理由：列式利于"按模型/时间段批量分析与漂移统计"，零数据库部署，pandas/pyarrow 直读。

### 4.5 难例挖掘规则（初版，写进 `configs/`）

- **检测**：`confidence < τ_det`（如 0.35）或 NMS 后框抖动大；预测类不在 12 类内（疑似新标志）。
- **预测**：真值到达后 `|pred - truth|` 的 MAE/RMSE 超过滚动基线 + k·σ。
- **协同分歧**：大模型融合判断与小模型原始输出**结论相反**（如小模型判低风险、大模型判高风险）。
- **问答质量**：RAG 检索未命中（相似度低于阈值）、用户对答案打低分/追问纠正 → 补充知识库或微调样本。
- **现场纠正**：操作员在 UI 上的人工纠正，直接进高优先级标注队列。

### 4.6 模型注册表（`registry/models.json`）

```jsonc
{
  "detection": {
    "production": "v2",
    "versions": {
      "v2": { "checkpoint": "runs/.../best.pt", "dataset_snapshot": "detection_v2",
              "metrics": { "mAP50": 0.71 }, "status": "production", "trained_at": "..." },
      "v3": { "checkpoint": "runs/.../best.pt", "dataset_snapshot": "detection_v3",
              "metrics": { "mAP50": 0.74 }, "status": "staging", "trained_at": "..." }
    }
  }
}
```

晋升门控：`v3.metrics 优于 v2 且 安全子集无回归` → 把 `production` 指向 `v3`，`v2` 转 `archived`（保留回滚）。

## 5. 端到端数据流（一次决策请求）

1. 操作台/外部触发 → 根 `services/api` 的 `analyze-scene`，转发到 `期末作业` 编排层。
2. `router` 决定调用的小模型集合。
3. `models/*` 适配器加载**注册表当前 production checkpoint** 推理；同时 `collector` 落遥测 Parquet。
4. `fusion` + `decision`（LLM）产出 决策 + 风险 + 理由。
5. 如需报告/语音 → 复用根 WSL-Hermes 异步任务生成。
6. `miner` 后台从遥测里挑难例 → `labeler` 标注 → 累积进数据集快照。
7. 触发条件满足 → `trainer` 重训 → `evaluator` 门控 → `registry` 晋升或丢弃。
8. 下次请求第 3 步自动用上新 checkpoint。闭环完成。

## 6. 实验与评估方案（报告用）

- **协同有效性**：对比"仅小模型规则决策" vs "大小模型协同决策"在若干场景上的决策质量/可解释性。
- **飞轮有效性（核心）**：模拟数据流入，跑 N 轮飞轮，画出检测 mAP50 / 预测 RMSE **随飞轮轮次的曲线**，
  证明单调提升；并展示一次"重训劣化被门控拦截、未上线"的负例，体现可回滚。
- **漂移监控**：构造一段分布漂移数据，展示监控指标报警 → 触发重训 → 指标恢复。
- **成本**：统计大模型调用次数/Token，论证"小模型高频 + 大模型按需"的成本优势。
