## ADDED Requirements

### Requirement: 课程报告首页结构
系统必须提供一个单页课程报告首页，以适合课堂展示的顺序呈现项目主题、研究定位、模块总览和 Demo 价值。

#### Scenario: 用户打开本地首页
- **WHEN** 用户在浏览器中打开首页入口文件
- **THEN** 页面展示完整的单页原型，并包含明显的首屏、摘要模块和适用于汇报的导航提示

### Requirement: 协同决策架构展示
系统必须说明大小模型在智能交通管理决策流程中的协同分工，覆盖感知、预测、研判、预警和诱导阶段。

#### Scenario: 用户浏览架构区域
- **WHEN** 用户滚动到系统架构区域
- **THEN** 页面展示大小模型如何分工以及输出如何流向交通管理决策

### Requirement: 作业成果映射
系统必须将已完成的课程作业成果映射到课程报告网站中，使其成为最终系统能力的支撑证据。

#### Scenario: 用户查看已完成工作
- **WHEN** 用户浏览成果模块或能力模块
- **THEN** 页面清楚标识大作业 1 和大作业 2 已完成，并说明它们如何支撑课程报告系统

### Requirement: 交互式 Demo 叙事
系统必须至少提供一种轻量前端交互，用于在不依赖后端服务的前提下模拟系统状态变化，支持 Demo 讲解。

#### Scenario: 用户触发一次交互
- **WHEN** 用户点击阶段切换器、场景标签或预警控制
- **THEN** 页面更新可见内容，以反映不同的交通状态、预警等级或决策阶段

### Requirement: 与项目风格指南保持一致
系统必须应用根目录 `design.md` 中定义的视觉方向，包括白色主背景、深蓝文本、蓝色强调、圆角卡片和语义化设计 Token。

#### Scenario: 用户查看核心视觉元素
- **WHEN** 首页渲染按钮、卡片、区块容器和文本
- **THEN** 这些元素遵循统一的设计 Token 体系，并与提供的风格指南保持一致

### Requirement: 具备响应式展示能力
系统必须在桌面端和移动端宽度下都保持可读和可操作，以便在常见设备上进行课程展示。

#### Scenario: 用户在窄屏设备上浏览
- **WHEN** 视口宽度缩小到移动端范围
- **THEN** 页面布局合理堆叠、文本保持清晰，交互控件仍可使用
