## 背景

当前智能交通 Demo 已经具备后端任务 API、内存任务管理器和前端任务中心，但 Hermes 集成仍然只是占位：任务入队后，后端返回的是模拟结果，而不是 Hermes 的真实执行结果。这使得界面流程虽然完整，却无法真正完成报表生成、播报稿输出和每日总结等自动化能力。

Hermes 需要被引入为真实运行依赖，但又不能破坏现有 Demo 的主流程。项目当前采用本地优先架构，使用 FastAPI 做编排，并把任务产物保存到 `services/api/.task_state`。同时，用户要求 Hermes 只能在当前工作区内运行，而不是依赖全局共享环境。因此，这次设计需要解决三件事：工作区内初始化、后端安全调用 Hermes、按任务类型独立初始化资源。

## 目标 / 非目标

**目标：**
- 为 Hermes 建立明确的项目级配置和启动校验。
- 约束 Hermes 只能在当前项目工作区内运行，并把状态保存在项目目录中。
- 用真实后端执行链路替换占位适配器。
- 支持按任务类型初始化 Hermes 资源，使报表、语音和每日总结各自独立运行。
- 在不改变现有任务 API 外观的前提下，补充更丰富的执行信息和错误信息。
- 统一 Hermes 任务产物的输出目录和格式。

**非目标：**
- 本次不引入云部署或分布式任务队列。
- 不依赖付费外部 API 才能完成 Hermes 工作流。
- 不在这一阶段构建完整自动调度平台，只实现运行钩子和任务契约。
- 不让 Hermes 替代当前主分析链路；Hermes 只作为任务自动化层。

## 设计决策

### 1. Hermes 作为后端管理的任务运行时

FastAPI 仍然是系统唯一入口，Hermes 由后端任务层调用，而不是前端直接触发。

原因：
- 运行环境和敏感配置保留在服务端；
- 复用现有任务管理和 API；
- 前端只负责触发和观察，不需要承担 Hermes 细节。

### 2. Hermes 固定在当前仓库内运行

每一次 Hermes 调用都以当前项目根目录作为工作目录，只读取或写入项目内部管理的配置、模板和产物目录。

原因：
- 符合“只在当前工作区运行”的要求；
- 任务产物、提示词和状态都能留在项目中，可审查、可版本化；
- 避免依赖机器上的其他 Hermes 状态。

### 3. Hermes 通过独立适配器执行

`HermesAdapter` 负责把 `TaskType` 和任务载荷转换成具体 Hermes 调用，并把 Hermes 返回结果归一化到任务记录中。

原因：
- 将 Hermes 相关逻辑集中隔离；
- 便于以后增加新任务类型；
- 更利于处理超时、失败和兜底逻辑。

### 4. 初始化采用“启动预检 + 按任务准备资源”

系统会先执行 Hermes 预检，校验命令、目录和工作区配置；在实际执行任务时，再按任务类型准备对应的提示词、载荷文件和输出目标。

原因：
- 能尽早暴露环境问题；
- 各任务工作流互不影响，职责清晰；
- 不需要为所有任务提前准备完整资源。

### 5. 产物继续落地到项目目录

报表、播报稿和每日总结等 Hermes 产物继续保存在 `.task_state` 目录下；按任务初始化时生成的临时文件、提示词和载荷文件也保存在项目内部状态目录。

原因：
- 与现有本地优先架构保持一致；
- 方便调试、复查和展示；
- 不需要额外引入数据库或对象存储。

## 风险 / 权衡

- [风险] 演示机器上未安装 Hermes -> 增加预检、清晰报错和安装文档。
- [风险] Hermes 误读或误写工作区外的内容 -> 强制设置工作目录和产物路径，仅允许项目内目录。
- [风险] 不同任务输出格式不一致 -> 为每种工作流定义固定输出契约，并由适配器统一归一化。
- [风险] 长任务阻塞演示体验 -> 继续走现有异步任务机制，不在 HTTP 请求中同步等待 Hermes。
- [风险] Windows 下命令调用方式与官方示例不同 -> 以 PowerShell 场景为主进行实现和验证。

## 迁移计划

1. 增加 Hermes 配置项、工作区本地路径和启动预检。
2. 实现真实 Hermes 适配器，并强制所有执行固定在当前工作区。
3. 为 `report`、`voice` 和 `daily-summary` 三类任务增加独立初始化资源和工作流映射。
4. 在任务响应和前端任务中心中展示 Hermes 执行信息和错误原因。
5. 更新启动脚本和运行文档，保证在本地可复现。
6. 验证 Hermes 不可用时的兜底逻辑，必要时通过 `HERMES_ENABLED=false` 回滚。

回滚策略：
- 将 `HERMES_ENABLED` 设为 `false`，系统回退到非 Hermes 执行路径；
- 若真实集成不稳定，可保留初始化代码，但暂时让所有任务走兜底逻辑。
