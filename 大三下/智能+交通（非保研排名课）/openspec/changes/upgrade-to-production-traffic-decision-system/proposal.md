## 为什么

当前 `课程设计/` 中的网站已经能够完成课程汇报展示，但它仍然是静态原型，尚未具备真实数据流、模型调用、后端接口和任务自动化能力。下一阶段需要把它升级为可实际运行的完整系统，使交通感知、预测、研判、播报和日报生成形成真正可演示、可部署、可扩展的闭环。

## 变更内容

- 将当前静态课程报告网站升级为可交互的前端应用，支持场景提交、结果查询、决策展示和任务触发。
- 新建后端服务层，对外提供统一 API，负责请求处理、业务编排、结果缓存、文件导出和语音播报接口。
- 建立模型服务接入层，把大作业 1 的交通流预测能力、大作业 2 的目标识别能力以及大模型决策能力整合为统一推理链路。
- 增加任务自动化与运营助手层，部署 Hermes Agent 处理表格生成、语音播报、每日总结和定时任务。
- 为系统补齐部署、配置、日志、任务状态和扩展能力，使其从课程原型升级为可持续迭代的 Demo 系统。

## 能力

### 新增能力
- `traffic-decision-frontend-app`：提供真实可交互的前端界面，支持查看预测结果、识别结果、决策摘要、播报状态和导出文件。
- `traffic-decision-backend-api`：提供统一后端 API，负责请求处理、业务编排、数据聚合、文件导出和任务状态管理。
- `traffic-model-orchestration`：将交通流预测、目标识别和大模型决策整合成可调用的推理流程，并输出结构化结果。
- `hermes-agent-operations`：集成 Hermes Agent 作为后台任务助手，处理日报、表格生成、语音播报和日常运营任务。

### 修改能力

无。

## 影响范围

该变更将从现有 `课程设计/` 静态页面扩展到完整项目结构，包括前端应用目录、后端服务目录、模型封装层、任务调度以及 Agent 集成配置。系统将新增 API 约定、模型调用配置、任务队列或后台作业机制，以及 Hermes Agent 的接入方式；同时也会影响现有课程原型页面，因为它将从静态展示入口演变为真实业务前端。
