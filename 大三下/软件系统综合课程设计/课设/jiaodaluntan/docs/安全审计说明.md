# 安全审计说明

## SQL 注入

当前后端主要使用 Spring Data JPA 方法名查询和 JPQL 参数绑定。以帖子搜索为例，`PostRepository.searchPublished` 使用 `:status` 和 `:keyword` 参数，而不是拼接 SQL 字符串。

安全结论：

- JPQL 参数绑定会把用户输入作为查询参数处理。
- 未发现 `createNativeQuery` 或明显的字符串拼接 SQL 入口。
- 后续如果新增 `nativeQuery`，必须使用命名参数或位置参数绑定。

## XSS

前端接入真实接口后，帖子、评论、用户名、举报原因、奖励描述等内容都可能来自用户输入，因此必须作为不可信数据处理。

渲染规则：

1. 动态文本优先使用 `textContent`。
2. 如果保留模板字符串，动态文本必须通过统一转义函数。
3. 链接、按钮 action、data 属性等属性值只能使用数字 ID、受控枚举或经过转义的值。
4. 搜索 `innerHTML` 时，每个动态插值都必须能说明来源和转义方式。

## 输入验证

后端 DTO 使用 Bean Validation：

- `@NotBlank`
- `@Size`
- `@Email`
- `@Pattern`
- `@Min`
- `@Max`

Controller 使用 `@Valid` 触发校验。

## 权限边界

系统使用 Spring Security + JWT。后台接口通过 `@PreAuthorize` 限制角色：

- `hasRole('ADMIN')`
- `hasAnyRole('MODERATOR', 'ADMIN')`

前端权限提示只用于用户体验，最终权限以后端判断为准。
