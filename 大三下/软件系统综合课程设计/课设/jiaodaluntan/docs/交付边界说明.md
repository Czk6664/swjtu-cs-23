# 交付边界说明

本文档用于说明课程设计提交时哪些内容属于源码和正式文档，哪些内容属于本地运行产物或过程资料。

## 正式交付内容

| 类型 | 路径 |
|---|---|
| 项目说明 | `README.md` |
| 架构设计 | `DESIGN.md` |
| 前端源码 | `frontend/` 中除 `node_modules/`、`dist/`、日志外的文件 |
| 后端源码 | `backend/src/`、`backend/pom.xml`、`backend/src/main/resources/` |
| 数据库初始化 | `init-database.sql`、`backend/src/main/resources/schema.sql` |
| 项目文档 | `docs/` |
| OpenSpec 过程记录 | `openspec/` |

## 本地运行产物

以下文件不属于正式源码交付，应被 `.gitignore` 忽略：

| 类型 | 示例 |
|---|---|
| 前端依赖 | `frontend/node_modules/` |
| 前端构建产物 | `frontend/dist/` |
| 后端构建产物 | `backend/target/` |
| 运行日志 | `*.log`、`*.out.log`、`*.err.log` |
| JVM 崩溃日志 | `hs_err_pid*.log` |
| 临时文件 | `.codex-write-check.tmp`、`*.tmp` |
| IDE 配置 | `.idea/`、`.vscode/`、`*.iml` |

## 过程资料

`.planning/`、`openspec/changes/` 和课程报告文档属于项目过程资料。它们可以帮助说明设计演进和任务执行历史，但不应与运行日志或编译产物混为一类。

## 清理原则

1. 清理前先区分源码、正式文档、过程资料和运行产物。
2. 不删除用户手写文档、OpenSpec artifacts、规划资料或课程报告。
3. 可以清理已确认的日志、构建产物、依赖目录和临时文件。
4. 若不确定文件来源，先记录到清单中，不直接删除。

## 检查命令

```powershell
git status --short
git ls-files | rg "(node_modules|target|dist|\\.log$|\\.out\\.log$|\\.err\\.log$|hs_err_pid)"
Get-ChildItem -Recurse -File -Include *.log,*.out.log,*.err.log,hs_err_pid*.log
```
