## ADDED Requirements

### Requirement: 一键可复现的本地启动
系统 SHALL 提供单一启动入口,能在干净环境中并行拉起前后端、自动初始化可用数据,并在就绪后给出访问地址,无需逐条手工命令。

#### Scenario: 干净环境首次启动
- **WHEN** 用户在装有 JDK 17+、Maven、Node 的干净环境运行启动脚本
- **THEN** 系统并行启动后端与前端,后端自动初始化版块、默认管理员与示例帖,并在 `/api/sections` 返回 200 后打印前端与后端访问地址

#### Scenario: 默认数据可复现
- **WHEN** 删除本地 H2 数据文件后重新启动
- **THEN** 系统重新生成相同的默认版块、默认管理员(`admin`)与示例数据,演示状态可复现且数据文件不进入版本库

### Requirement: 端口冲突自愈
系统 SHALL 在启动前处理端口占用,使重复启动或残留进程不会导致 `port already in use` 而中断。

#### Scenario: 端口被残留进程占用
- **WHEN** 启动时后端或前端端口被上一次未退出的进程占用
- **THEN** 启动脚本检测并清理该残留进程后再启动,或给出明确的占用进程信息与处置提示,而非直接失败退出

#### Scenario: 后端端口可配置
- **WHEN** 需要更换后端监听端口
- **THEN** 前端开发代理目标随之对齐(通过配置/变量而非硬编码),前端仍能正常访问后端 API
