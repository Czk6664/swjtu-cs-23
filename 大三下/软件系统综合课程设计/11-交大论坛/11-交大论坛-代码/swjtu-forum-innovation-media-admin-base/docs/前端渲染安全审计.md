# 前端渲染安全审计

## 审计范围

审计对象为 `frontend/assets/app.js` 和 `frontend/assets/runtime/**/*.js`。当前前端采用 Vite MPA 入口，页面动态内容由 runtime 模块根据后端 JSON 渲染。

## 渲染策略

| 数据类型 | 来源 | 渲染策略 |
|---|---|---|
| 帖子标题、正文、版块名 | 后端接口/用户输入 | 必须经过 `escapeHtml()` 或 DOM `textContent` |
| 评论内容 | 后端接口/用户输入 | 必须经过 `escapeHtml()` 或 DOM `textContent` |
| 用户名、学院、专业 | 后端接口/用户输入 | 必须经过 `escapeHtml()` |
| 举报原因、处理备注 | 后端接口/用户输入 | 必须经过 `escapeHtml()` |
| 奖励名称、奖励描述 | 后台配置/后端接口 | 必须经过 `escapeHtml()` |
| data 属性中的 ID | 后端数字 ID | 仅允许数字或后端 ID 字段，不能拼入任意文本 |
| 固定按钮 action | 前端常量 | 可信常量 |

## `innerHTML` 使用结论

项目仍保留模板字符串渲染，以控制本次质量提升的改动范围。安全边界是：模板中的动态文本必须通过 `escapeHtml()`，动态操作标识仅使用数字 ID、布尔值或前端常量。

审计重点：

- `postCard()` 对标题、正文、版块、作者、标签和推荐原因执行转义。
- 详情页、个人中心、成长中心、积分商城、后台治理、用户管理和推荐策略中的用户可控文本均应走转义 helper。
- 状态卡 `buildStateCard()` 对标题、消息和按钮文案执行转义。
- 受保护操作的 `data-*` 属性只使用实体 ID、布尔值或固定 action。
