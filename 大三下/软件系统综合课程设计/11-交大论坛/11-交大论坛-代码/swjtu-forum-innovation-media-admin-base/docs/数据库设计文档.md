# 交大校园论坛系统数据库设计文档

## 一、文档范围

本文档描述当前课程答辩版本已经落地并由 Spring JPA 实体实际使用的核心数据表，重点覆盖 Phase 1 的游客浏览、普通用户个人中心、管理员用户与帖子管理闭环。

- 数据库：`swjtu_forum`
- 字符集：`utf8mb4`
- 存储引擎：`InnoDB`
- Phase 1 真实脚本：`backend/src/main/resources/schema.sql`
- 初始化入口：`init-database.sql`

## 二、Phase 1 核心表

### 2.1 用户与角色

`users` 保存账户基础资料、角色与成长字段。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `username` / `email` | 登录与联系标识，均唯一 |
| `role` | `USER`、`MODERATOR`、`ADMIN` |
| `enabled` | 是否允许继续登录和使用 |
| `student_id` / `college` / `major` / `bio` | 个人中心资料 |
| `level` / `exp` / `points` / `consecutive_days` | 成长体系基础数据 |

Phase 1 关联点：

- `/auth/me`、登录注册、个人资料维护
- 管理员用户列表、封禁/解封
- 版块版主绑定 `sections.moderator_id`

### 2.2 版块

`sections` 保存论坛版块，并用 `moderator_id` 关联版主用户。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 版块名称，唯一 |
| `description` / `icon` | 前端展示信息 |
| `post_count` | 帖子数量缓存 |
| `moderator_id` | 版主管理范围 |
| `sort_order` | 首页与列表排序 |

Phase 1 关联点：

- 首页版块列表
- 发帖/编辑帖选择版块
- 管理员版块维护
- 版主/管理员帖子权限判断

### 2.3 帖子

`posts` 是论坛主表，直接支撑首页、详情页、个人中心、管理员全站帖子管理。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 作者 |
| `section_id` | 所属版块 |
| `title` / `content` / `cover_image` | 帖子主体 |
| `view_count` / `like_count` / `comment_count` / `collect_count` | 展示统计 |
| `heat_score` | 热门排序分值 |
| `status` | `0` 待审核, `1` 已发布, `2` 已隐藏, `3` 已驳回 |
| `created_at` / `updated_at` | 审计时间 |

Phase 1 关联点：

- 游客只能浏览 `status = 1` 的公开帖子
- 普通用户可查看和编辑自己的帖子
- 管理员可查看全站帖子并修改标题、正文、版块、状态，或直接删除

### 2.4 标签关系

`tags`、`post_tags`、`user_tags` 共同支撑帖子标签和用户兴趣标签。

- `tags`：标签字典
- `post_tags`：帖子与标签多对多
- `user_tags`：用户兴趣标签多对多

其中 `tags` 还保留 `category`、`use_count` 字段，便于后续推荐与运营统计继续扩展。

Phase 1 中，管理员编辑帖子时也会维护 `post_tags`。

### 2.5 评论与互动

`comments`、`post_likes`、`comment_likes`、`post_favorites` 构成已上线的互动闭环。

`comments` 关键字段：

| 字段 | 说明 |
| --- | --- |
| `post_id` / `user_id` | 评论所属帖子与作者 |
| `parent_id` | 回复链路 |
| `status` | `1` 显示, `2` 隐藏 |

其他关系表：

| 表名 | 说明 |
| --- | --- |
| `post_likes` | 帖子点赞 |
| `comment_likes` | 评论点赞 |
| `post_favorites` | 帖子收藏 |

Phase 1 关联点：

- 帖子点赞、评论点赞、收藏
- 管理端隐藏/恢复评论
- 删除帖子时依赖外键级联清理关联互动数据

### 2.6 浏览记录

`post_browse_history` 是 Phase 1 新增闭环表，用于支撑“个人中心 > 浏览记录”。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 浏览用户 |
| `post_id` | 浏览帖子 |
| `created_at` | 首次浏览时间 |
| `last_viewed_at` | 最近一次浏览时间 |

约束：

- `UNIQUE (user_id, post_id)`，同一用户对同一帖子只保留一条记录

Phase 1 关联点：

- 认证用户打开帖子详情时由后端写入
- 个人中心按 `last_viewed_at` 倒序读取

### 2.7 管理日志

`operation_logs` 记录管理员/版主执行的关键管理动作。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `actor_id` | 操作者 |
| `action` | 动作编码，如 `UPDATE_POST`、`DELETE_POST` |
| `target_type` / `target_id` | 目标对象 |
| `detail` | 可展示的文本详情 |

Phase 1 关联点：

- 用户封禁/解封
- 帖子审核、编辑、删除
- 版块创建/更新/删除

## 三、当前版本中已存在但非 Phase 1 主讲重点的表

下列表已经被实体层使用，并在 `schema.sql` 中一并对齐，便于本地初始化和后续阶段演进：

| 表名 | 用途 |
| --- | --- |
| `points_history` | 用户积分与经验变更历史 |
| `reward_items` | 奖励项配置 |
| `redemption_requests` | 用户积分兑换申请 |

这些表主要服务成长/运营功能，不替代 Phase 1 的用户中心和管理员帖子治理主链路。

## 四、关系说明

核心关系如下：

1. `users` 1 对多 `posts`
2. `sections` 1 对多 `posts`
3. `users` 1 对多 `comments`
4. `posts` 1 对多 `comments`
5. `posts` 多对多 `tags`，通过 `post_tags`
6. `users` 多对多 `tags`，通过 `user_tags`
7. `users` 1 对多 `post_browse_history`
8. `users` 1 对多 `operation_logs`（作为 actor）

删除策略：

- 删除帖子时，评论、点赞、收藏、标签关系、浏览记录通过外键级联删除
- 删除用户时，其帖子与互动数据通过外键级联清理；若用户是版主或日志操作者，则相关外键采用 `SET NULL` 的场景会保留业务记录

## 五、答辩可直接说明的 Phase 1 数据闭环

1. 游客浏览：公开帖子直接来自 `posts` 与 `sections`
2. 普通用户个人中心：`users`、`posts`、`post_favorites`、`post_browse_history`
3. 管理员用户管理：`users`、`operation_logs`
4. 管理员帖子管理：`posts`、`sections`、`post_tags`、`operation_logs`
5. 管理员删除帖子后的可见性变化：依赖 `posts` 删除与关联表级联清理

以上结构与当前实体、接口和页面实现一致，可直接作为课程演示与数据库说明基线。
