# 管理员专属后台重构说明

本文档专门说明 `http://127.0.0.1:5173/admin_overview/code.html` 这个管理员专属后台的重构方向。

目标风格：高信息密度数据仪表盘。  
顶部栏：保留交大论坛现有顶部栏，不重做。  
页面内部：新增管理员后台专属左侧边栏。  
主题色：以交大蓝 `#0075B8` 和白色为主，不照搬深色参考图。

## 1. 页面定位

`admin_overview/code.html` 应该是管理员进入后台后的核心运营控制台，不是普通论坛页面，也不是产品介绍页。

它应承担以下职责：

- 快速展示论坛整体运营状态。
- 集中呈现待审帖子、待处理举报、待审核兑换等后台待办。
- 用数据图表展示帖子、用户、评论、举报、板块活跃度。
- 为内容治理、用户管理、推荐策略等后台功能提供高效入口。
- 让管理员在一个屏幕内看到尽可能多的有效信息。

最终效果应类似 BI/运营仪表盘，而不是宣传型落地页。

## 2. 视觉方向

参考风格是 Data-Dense Dashboard，但需要做校园论坛化和交大蓝主题化。

### 2.1 保留部分

- 高信息密度。
- 多卡片、多图表、多表格组合。
- 左侧后台导航。
- KPI 指标卡片。
- 图表和表格并列。
- 悬浮高亮、筛选动效、加载状态。
- 操作区紧凑但清晰。

### 2.2 不照搬部分

- 不使用深色大面积背景。
- 不做金融后台或交易平台风格。
- 不使用过强霓虹蓝。
- 不使用英文商业指标，例如 Revenue、Orders、Avg. Order。
- 不做营销页式 Hero。

### 2.3 本项目应采用的视觉主题

```text
背景：#F5F9FC / #FFFFFF
主色：#0075B8
强调蓝：#0B8ED8
成功绿：#22C55E
警示橙：#F59E0B
风险红：#EF4444
正文深色：#1F2D3D
次级文字：#6B7A8C
边框：#D8E8F3
卡片底色：#FFFFFF
```

整体气质应是：

```text
清爽、专业、紧凑、数据感强、像真实校园论坛运营后台。
```

## 3. 总体布局

顶部栏保持原有交大论坛顶栏，不做大改。

在顶部栏下方，`admin_overview` 页面内部重构为：

```text
┌─────────────────────────────────────────────────────────────┐
│ 原有交大论坛顶部栏：Logo / 搜索 / 导航 / 用户信息              │
├──────────────┬──────────────────────────────────────────────┤
│ 后台左侧边栏  │ 管理后台主内容区                               │
│              │                                              │
│ 总览          │ KPI 指标区                                    │
│ 内容治理      │ 趋势图 / 板块分布 / 风险状态                    │
│ 用户管理      │ 待办列表 / 举报队列 / 兑换审核                  │
│ 板块运营      │ 最新操作日志 / 活跃用户 / 热门帖子              │
│ 推荐策略      │                                              │
│ 积分奖励      │                                              │
│ 操作日志      │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

左侧边栏是管理员后台专属导航，不影响论坛前台导航。

## 4. 左侧边栏设计

左侧边栏用于后台功能切换，建议固定在页面左侧。

### 4.1 导航项

建议包含：

- 总览
- 内容治理
- 用户管理
- 板块运营
- 推荐策略
- 积分奖励
- 操作日志
- 系统状态

### 4.2 视觉要求

- 背景使用很浅的蓝灰或白色，不使用深色。
- 当前选中项使用交大蓝填充或左侧蓝色竖线。
- 每个导航项带统一线性图标。
- 图标风格要一致，不能混用不同画风。
- 左侧边栏宽度建议 220 到 260px。

### 4.3 交互要求

- hover 时背景轻微变蓝。
- 当前页面高亮。
- 小屏幕时收起为图标栏或抽屉。
- 不刷新整页即可切换模块是理想状态；短期可以跳转到对应页面。

## 5. 主内容区结构

主内容区应采用高信息密度网格布局。

推荐结构：

```text
┌────────────────────────────────────────────────────┐
│ 页面标题区：管理员工作台 / 最近更新时间 / 刷新按钮   │
├────────────────────────────────────────────────────┤
│ KPI 卡片  KPI 卡片  KPI 卡片  KPI 卡片  KPI 卡片    │
├──────────────────────────────────┬─────────────────┤
│ 近 7 日发帖趋势图                 │ 举报/风险环形图   │
├──────────────────────────────────┼─────────────────┤
│ 今日待办表格                      │ 板块活跃排行      │
├──────────────────────────────────┼─────────────────┤
│ 最新后台操作日志                  │ 热门帖子/标签      │
└──────────────────────────────────┴─────────────────┘
```

重点是让管理员一屏内看到尽可能多的信息，但不能乱。

## 6. KPI 指标区

KPI 卡片放在主内容区顶部。

建议指标：

- 用户总数
- 今日新增用户
- 帖子总数
- 今日新增帖子
- 评论总数
- 待审帖子
- 待处理举报
- 待审核兑换
- 封禁用户
- 今日活跃用户

每张卡片包含：

- 指标名称
- 当前数值
- 趋势变化
- 状态颜色

示例：

```text
待审帖子
14
+3 较昨日
```

颜色规则：

- 正常增长：绿色
- 需要关注：橙色
- 风险升高：红色
- 普通指标：交大蓝

## 7. 图表模块

图表应轻量、清晰、信息密度高。

### 7.1 发帖趋势图

展示近 7 日或近 14 日发帖量。

形式：

- 柱状图
- 折线图
- 柱线混合图

交互：

- hover 显示具体日期和数值。
- 点击某一天可筛选当天帖子。
- 支持 7 日 / 30 日切换。

### 7.2 板块活跃分布

展示各板块帖子数量、评论量、活跃用户。

适合形式：

- 横向条形图
- 排名列表
- 小型热力条

板块应使用真实校园论坛语义：

- 课程互助
- 考研保研
- 二手闲置
- 犀浦生活
- 失物招领
- 社团招新

### 7.3 举报风险图

展示举报类型占比。

可分为：

- 广告引流
- 违规交易
- 隐私信息
- 不文明内容
- 重复刷屏

形式：

- 环形图
- 堆叠条
- 风险列表

## 8. 待办表格

待办区域建议使用紧凑表格，而不是大卡片堆叠。

表格字段：

```text
类型 | 标题/对象 | 用户 | 板块 | 风险 | 时间 | 操作
```

操作按钮：

- 通过
- 驳回
- 隐藏
- 查看

交互要求：

- 行 hover 高亮。
- 点击操作不整页刷新。
- 操作成功后该行淡出或状态更新。
- 高风险行左侧加颜色标识。
- 表格上方提供筛选：全部、待审、举报、兑换。

## 9. 最新操作日志

操作日志要像正式系统，不要像普通动态。

字段：

```text
时间 | 操作人 | 动作 | 对象 | 备注
```

示例：

```text
10:25  admin  通过帖子  《期末复习资料整理》  内容合规
10:21  admin  驳回举报  #32  证据不足
09:58  admin  封禁用户  rent_spam_01  重复转租广告
```

要求：

- 日志只读。
- 支持查看更多。
- 敏感操作用橙色或红色标签标记。

## 10. 快捷管理区

在主区域右侧或下方加入快捷入口。

建议入口：

- 内容治理台
- 用户管理
- 推荐策略
- 板块运营
- 积分奖励
- 操作日志

每个入口显示：

- 名称
- 当前待办数量
- 简短说明
- 进入按钮

## 11. 数据来源

后台总览页必须接真实接口。

建议使用：

```text
GET /admin/analytics
GET /admin/posts/pending
GET /admin/reports?status=0
GET /admin/redemptions/pending
GET /admin/logs
GET /admin/users
GET /admin/posts
```

快捷操作：

```text
PATCH /admin/posts/{id}/status
PATCH /admin/reports/{id}/review
PATCH /admin/redemptions/{id}/review
```

不允许：

- 写死 KPI 数据。
- 写死待办列表。
- 用静态 HTML 假装后台。

## 12. 状态处理

### 12.1 加载中

显示紧凑骨架屏或小型 loading spinner。

### 12.2 空状态

空状态要小，不占大面积。

示例：

```text
暂无待审帖子
暂无待处理举报
暂无兑换申请
```

### 12.3 请求失败

不要只显示：

```text
请求失败 (500)
```

应显示：

```text
后台数据加载失败
失败模块：待办列表
操作：重试 / 返回论坛首页
```

### 12.4 权限不足

应显示：

```text
当前账号没有管理员权限
普通用户可以返回论坛首页继续浏览、发帖和评论
```

按钮：

- 返回论坛首页
- 切换账号登录

## 13. 动效要求

动效应服务于数据展示和操作反馈。

推荐：

- KPI 数字 count-up。
- 图表柱状条进入时增长。
- 表格行 hover 高亮。
- 筛选切换时平滑过渡。
- 操作成功后行淡出。
- Toast 淡入淡出。

避免：

- 大面积炫光。
- 粒子背景。
- 夸张弹跳。
- 长时间动画。

后台要快，不要炫。

## 14. 响应式要求

桌面端：

- 左侧边栏固定。
- 主内容区多列网格。
- 表格信息密度高。

平板端：

- 左侧栏缩窄。
- KPI 变成 2 到 3 列。
- 图表上下排列。

移动端：

- 左侧栏收起。
- 表格改成紧凑卡片。
- 只保留核心待办和关键指标。

## 15. 重构优先级

### P0

- 保留原顶部栏。
- 新增后台左侧边栏。
- 首屏改为管理员工作台。
- KPI 区接真实数据。
- 待办表格接真实数据。
- 操作按钮局部更新。
- 修复请求失败和权限不足状态。

### P1

- 发帖趋势图。
- 举报风险图。
- 板块活跃排行。
- 最近操作日志。
- 快捷入口区。
- 筛选动画。

### P2

- 图表点击筛选。
- 批量审核。
- 后台全局搜索。
- 操作日志筛选。
- 运营报告打印。

## 16. 验收标准

完成后应满足：

- `admin_overview/code.html` 顶部栏仍是交大论坛原有顶部栏。
- 页面内部有独立后台左侧边栏。
- 主区域是高信息密度数据仪表盘。
- 主题是白色和交大蓝，不是深色金融后台。
- KPI、图表、待办、日志同时存在。
- 待办数据来自真实接口。
- 点击审核操作后不整页刷新。
- 普通用户无法进入管理后台。
- 页面没有宣传式文案。
- `npm run build` 通过。

## 17. 最终效果

最终界面应像一个真实的西南交大论坛运营后台：顶部仍保留论坛品牌，内部是管理员专属的高密度数据工作台。管理员可以一屏看到关键指标、趋势图、待办表格、风险提醒和操作日志，并能快速进入内容治理、用户管理、推荐策略等模块。
