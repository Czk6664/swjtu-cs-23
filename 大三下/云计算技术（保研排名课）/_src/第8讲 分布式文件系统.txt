三种存储：块存储、文件存储、对象存储
01
块存储（Block Storage）
将存储空间划分为固定大小的块（Block），提供裸设备
级别的访问接口。
类比：一块未格式化的本地硬盘
访问方式：设备路径（如Linux下的/dev/sda）
代表：AWS EBS、Ceph RBD
文件存储（File Storage）
提供文件和目录的层级树状结构，通过文件路径访问数据。
类比：一个网络共享文件夹
访问方式：符合POSIX的文件路径（如/data/file.txt）
代表：NFS、HDFS、CephFS

🗂File Storage

GFS 架构关键创新点(1/2)
04
1.单一Master设计：大幅简化设计架构，避免了复杂的分布式一致性协议（如
Paxos/Raft用于元数据），但通过内存映射和操作日志解决性能瓶颈。
2. 控制流与数据流分离：Client仅找Master问路，数据传输绝不经过Master，
避免Master成为网络瓶颈。
3. 大Chunk策略（64MB）：远大于普通操作系统的4KB，极大减少了Master
的元数据管理压力

GFS追加写入流程
05
为什么关注追加（Record Append）？
GFS专门优化了追加写入，允许数百个客户端并发向同一文件追加，而不需加分布式锁。
传统写入：随机修改
需分布式锁· 高冲突
高延迟· 低吞吐
GFS 追加：Record Append
数百客户端无锁并发
极高吞吐· 适合日志场景

GFS追加写入流程
05
写入流程设计：流水线（Pipeline）机制
Ø
授权主副本：Master在3个副本中指定一个为Primary（主），负责确定写入顺序。
Ø
数据链式推送：Client不直接向3个副本同时发数据，而是发给最近的副本A，A推给B，B推给C
（充分利用节点全双工带宽）。
Ø
执行写入顺序：数据推送完成后，Client通知Primary执行，Primary定好顺序后通知所有
Secondary副本按相同顺序落盘。

01 HDFS概述
HDFS（Hadoop Distributed File System）是Apache Hadoop大数据生态的
底层基石。其设计深度借鉴了GFS论文，用Java实现。
HDFS设计的核心取舍
设计目标
放弃的特性
超大文件处理（TB/PB 级别）
不适合海量小文件存储
流式数据访问（一次写入，多次读取）
不支持低延迟数据随机访问
高容错与低成本（运行在普通硬件）
强一致性随机修改（仅支持追加）
计算向数据移动（数据本地性）
计算与存储完全分离架构

Block与机架感知
04
默认大Block（128MB起步）
为什么HDFS采用远大于操作系统的块大小？
ü 最小化寻道时间开销：如果寻道时间是10ms，传输速率100MB/s。为了让寻道时间占比降
到1%以下，块至少要是100MB。
ü 减少元数据：极大减轻了NameNode的内存负担。

128 MB

▸块越大，寻道占比越低
▸同时大幅减少NN 元数据

HDFS HA（高可用）架构方案
08
采用Active/Standby双机热备架构解决单点问题：
1. Active NameNode：负责提供所有读写服务。
2. Standby NameNode：热备份，时刻准备接管。
3. JournalNode集群：取代传统的本地硬盘，用于Active和Standby之间实
时同步
EditLog日志（基于Paxos变体，过半数写入成功机制）。
4. ZooKeeper与ZKFC：用于自动脑裂保护和故障切换。ZKFC监控NN心跳，一旦Active无响
应，立刻通过Zookeeper发起选举，将Standby推举为新的Active。

纠删码（Erasure Coding, EC）
09
l 传统3副本的痛点：存储开销高达200%（存1TB需要3TB硬盘），成本高昂。
l EC技术原理：类似于RAID 5/6。将数据分片并计算出奇偶校验块。
l 典型策略（RS-6-3）：6份数据块+ 3份校验块= 9块。任意丢失3块均可恢复。
l 收益：存储开销从200%大幅下降至50%，极度适合访问量较低的冷数据（如日志归档）。
💰3 副本：200% 存储开销
1TB 数据→ 3TB 硬盘
✨EC 编码：50% 存储开销
1TB 数据→ 1.5TB 硬盘

Amazon S3存储分层降本模型
03
ü S3 Standard（标准层）：毫秒延迟，针对热数据，存储费贵。
ü S3 IA（低频层）：毫秒延迟，存储便宜，但在读取时按GB收取数据取回费。
ü S3 Glacier（归档层）：存储白菜价，但提取需要数分钟到数小时解冻。
ü Intelligent-Tiering（智能分层）：利用机器学习自动监控访问模式进行上下层转移。

RADOS（可靠自主分布式对象存储）
03
RADOS层是完全无单点的自动修复网络。在RADOS看来，所有上层的数据（不管是100GB的
块设备，还是一个多媒体文件），全都被无情地切分成默认4MB大小的RADOS Object。
上层：虚拟机磁盘镜像my_vm_disk (100GB)
切片：被Librados客户端切分为25,600 个4MB 的RADOS Object
底座：均匀打散存入RADOS 底层的千百块物理磁盘（OSD）中
100 GB ÷ 4 MB = 25,600 个RADOS Object
上层任意大小数据→ 切片均匀打散到全集群千百块磁盘

CRUSH算法
04
HDFS需要NameNode的内存记录“每一个Block存在哪台机器”。当数据达到EB级（亿万个
对象），任何中心节点的内存都会被撑爆，且每次寻址的网络开销极大。
CRUSH（Controlled Replication Under Scalable Hashing）算法是Ceph的核心专利。它让
客户端不查任何表，仅靠本地计算就能算出数据该存到哪块硬盘。
客户端寻址核心逻辑（伪代码）：
1. 哈希：PG_ID = Hash(Object_Name) % PG_Total_Num
2. CRUSH：OSD_List = CRUSH(PG_ID, Cluster_Map, Rule_Set)
3. 直连：Client 直接连接OSD_List[0] 写入数据

CRUSH的智能特性
04
伪随机与确定性：同样的输入，任何客户端在任何时候计算出的磁盘分布绝对一致。

Ceph 三大存储接口(2/3)：RBD / CephFS
05
RBD（块设备）—— 私有云虚拟机标配
原理：将RADOS存储池映射成Linux下的块设备（如/dev/rbd0）。
杀手锏：支持秒级创建快照（Snapshot）和克隆（Clone）。在OpenStack中，用RBD启动上
百个虚拟机只需几秒钟（因为利用了写时复制COW机制）。
CephFS（文件系统）—— 高性能共享盘
原理：提供高度兼容POSIX的文件系统，支持多台机器同时mount并实时读写。
杀手锏：MDS集群采用动态子树分区策略。如果某个目录下文件访问量激增（热点），Ceph会
自动把该目录的元数据管理权分摊给其他MDS节点。
