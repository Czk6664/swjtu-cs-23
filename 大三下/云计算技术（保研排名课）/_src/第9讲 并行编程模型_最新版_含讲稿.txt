Amdahl定律的局限性
Amdahl假设：问题规模是固定的。
现实大数据场景：机器多了，我
们要处理更多的数据（如
100TB）！
Gustafson定律的核心主张
假设执行时间固定，随着处理器
增多，系统可以处理更大规模的
问题，加速比呈现近线性增长。
加速比S(N) = N - f × (N - 1)

Map函数：数据打散与重塑
输入：键值对<K1, V1>
输出：零个或多个中间键值对

动作：过滤、提取、转换。

为什么要引入Combiner？
既然网络传输是Shuffle的瓶颈，我们能否在数据离开Map节点前，“就地”先合
并一次？
Combiner的作用
运行在Map端的“迷你Reduce”。
优化前Map输出：("hello",1), ("hello",1), ("hello",1) -> 
传3条记录
Combiner优化后：("hello",3) -> 只传1条记录！
致命陷阱：滥用的代价
Combiner绝不能改变最终结果。它只适用于满足
交换律和结合律的操作。
适用：Sum（求和）、Max（最大值）
不适用：Average（平均值），因为Avg(Avg(1,3), 
5) ≠ Avg(1,3,5)

100个任务中，99个都只花了1分钟，偏偏最后1个任务因为所在机器硬盘老化，跑了10分钟。整个作业的时
间就被这1个人拖累成了10分钟！

1. 不去停掉这个慢任务。
2. 在其他空闲机器上，同时启动一个
一模一样的“替补任务”。
3. 哪个先跑完，就用哪个的结果，并
立刻杀掉另一个。

核心代码片段展示
# ──Map：每个节点只保留局部TopN，大幅减少Shuffle 传输量──
def topn_map(shard, N):
heap = []
for item, score in shard:
heapq.heappush(heap, (score, item))
if len(heap) > N:
heapq.heappop(heap)   # 弹出最小值，堆中始终保留最大的N 个
return heap
# ──Reduce：汇总所有局部冠军，选出全局TopN ──
def topn_reduce(candidates, N):
return heapq.nlargest(N, candidates)  # 从所有局部TopN 中选全局TopN

Reduce-Side Join（通用但笨重）
思路：利用Shuffle的按Key分组机制。
Map端：分别为两个表的数据打上标签
（如Tag="User"和Tag="Order"），统一
以关联键（User_ID）作为Key输出。
Reduce端：相同User_ID的数据相聚，再
根据标签拆分拼接。
缺点：所有数据都要经过Shuffle，极其消
耗性能。

users  = [(1,"Alice"), (2,"Bob"), (3,"Charlie")]
orders = [(1,"手机"),  (1,"图书"), (2,"运动鞋"), (3,"笔记本")]
# ══Reduce-Side Join：两表都以user_id 为Key，Shuffle 自动聚合══
# Map：打tag 标明来源，以user_id 为Key
def join_map(tag, uid, info):
return (uid, (tag, info))   # Key=user_id，Value=(表名, 内容)
# Shuffle：按user_id 分组（框架自动完成）
grouped = defaultdict(list)
for uid, name    in users:  grouped[uid].append(join_map("user",  uid, name))
for uid, product in orders: grouped[uid].append(join_map("order", uid, product))
# Reduce：按tag 分拣，拼接用户与订单
for uid, records in grouped.items():
user = next(info for _, (tag, info) in records if tag == "user")
items = [info for _, (tag, info) in records if tag == "order"]
print(f"用户{uid} {user} 购买了{items}")

YARN的资源调度策略
03
集群资源有限，多个部门抢资源怎么办？
2026/5/18
竢

1. FIFO Scheduler（先进先出）
机制：谁先提交，谁占用全部资源，排队执行。
缺点：大作业会“饿死”排在后面的紧急小作业。
2. Capacity Scheduler（容量调度器）
机制：多租户共享。预先划分队列（如：生产组60%，测试组40%）
亮点：资源借用机制。如果测试组暂时没任务，生产组可以借用这40%的资源；一旦测试组
来任务了，生产组必须归还。
3. Fair Scheduler（公平调度器）
机制：动态平分资源。1个人跑占100%，2个人跑各占50%。保障每个人都能得到一定资源。

# pi_mpi.py —— 运行：mpiexec -n 4 python pi_mpi.py
from mpi4py import MPI
import random
comm = MPI.COMM_WORLD
rank, size = comm.Get_rank(), comm.Get_size()
N_TOTAL = 10_000_000
N_LOCAL = N_TOTAL // size
random.seed(rank * 42)
hits = sum(1 for _ in range(N_LOCAL)
if random.random()**2 + random.random()**2 <= 1.0)
total_hits = comm.reduce(hits, op=MPI.SUM, root=0)
if rank == 0:
pi_est = 4.0 * total_hits / N_TOTAL
print(f"π ≈ {pi_est:.6f}")

# wordcount_mr.py —— 纯 Python 模拟 MapReduce
from collections import defaultdict
def split_input(documents, num_shards=3):
return [documents[i::num_shards] for i in range(num_shards)]
def map_phase(shard):
out = []
for doc in shard:
for word in doc.lower().split():
out.append((word, 1))
return out
def shuffle_phase(map_outputs):
grouped = defaultdict(list)
for partial in map_outputs:
for k, v in partial:
grouped[k].append(v)
return dict(grouped)
def reduce_phase(grouped):
return {k: sum(vs) for k, vs in grouped.items()}
docs   = ["Hello World", "Hello Cloud", "Cloud Computing is 
great"]
shards  = split_input(docs)
map_out = [map_phase(s) for s in shards]
grouped = shuffle_phase(map_out)
final   = reduce_phase(grouped)
print(final)
# {'hello':2, 'world':1, 'cloud':2, 'computing':1, 'is':1, 'great':1}

# speedup_mp.py —— multiprocessing 加速比对比
from multiprocessing import Pool
import time, math
def heavy(chunk):
return [math.sqrt(x*x + math.sin(x)) for x in chunk]
def benchmark(n, chunks):
t0 = time.time()
if n == 1:
[heavy(c) for c in chunks]
else:
with Pool(n) as pool:
pool.map(heavy, chunks)
return time.time() - t0
N = 10_000_000
data = list(range(N))
chunks = [data[i:i+N//8] for i in range(0, N, N//8)]
t1 = benchmark(1, chunks)
print(f"{'workers':<8}{'time(s)':<10}{'speedup':<10}")
for w in [1, 2, 4, 8]:
t = benchmark(w, chunks)
print(f"{w:<8}{t:<10.2f}{t1/t:<10.2f}")

# 串行比例 f, 处理器数量 n
def amdahl_speedup(f, n):
return 1.0 / (f + (1 - f) / n)
# 假设代码中存在10%的不可并行部分 (f=0.1)
print(amdahl_speedup(0.1, n=4))   # 4核加速比: 
3.08倍
print(amdahl_speedup(0.1, n=16))  # 16核加速
比: 6.40倍
print(amdahl_speedup(0.1, n=256)) # 256核加速
比: 9.66倍
print(amdahl_speedup(0.1, n=无穷大)) # 理论极
限: 10倍
