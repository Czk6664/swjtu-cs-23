# 实验一：基础数字签名

## 1. 实验目标

本实验完成最基本的数字签名流程：

```text
生成密钥对 -> 私钥签名 -> 公钥验签 -> 篡改测试 -> 错误公钥测试
```

通过该实验可以理解数字签名的三个核心输入与输出：

- 输入消息：需要被保护的数据，本实验使用 `M1`。
- 私钥：只有发送方 Alice 持有，用于生成签名。
- 公钥：接收方或验证方持有，用于验证签名。
- 输出签名值：一段二进制数据，证明消息确实由对应私钥签出。
- 验证结果：`True` 表示签名、消息、公钥三者匹配，`False` 表示至少一项不匹配。

对应代码文件为 `basic_signature.py`，主程序调用位置在 `main.py` 的 `experiment_1`。

## 2. 实验原理

数字签名不是“加密消息”，而是对消息生成一个不可伪造的认证值。签名过程使用发送方私钥，验签过程使用发送方公钥。

本实验采用：

- 签名算法：`RSA-PSS`
- 摘要算法：`SHA256`
- 密钥长度：`RSA 2048 bit`

RSA-PSS 是现代推荐的 RSA 签名填充方案。它在签名时引入随机盐，因此同一条消息使用同一把私钥多次签名，得到的签名值通常也不同。这说明实验中不能要求签名值固定，只需要判断验签是否通过。

验签时会重新根据消息、公钥和算法参数检查签名。如果消息改动、公钥不匹配或签名被破坏，验证都会失败。

## 3. 核心函数

### `sign_basic(private_key, message, algorithm="RSA-PSS")`

功能是使用私钥对消息签名：

```python
private_key.sign(
    message,
    rsa_pss_padding("SHA256"),
    get_hash_algorithm("SHA256"),
)
```

这里传入的是原始消息 bytes。`cryptography` 会在签名过程中内部计算 SHA256 摘要，再执行 RSA-PSS 签名。

### `verify_basic(public_key, message, signature, algorithm="RSA-PSS")`

功能是使用公钥验证签名：

```python
public_key.verify(
    signature,
    message,
    rsa_pss_padding("SHA256"),
    get_hash_algorithm("SHA256"),
)
```

如果验证成功，函数返回 `True`；如果抛出 `InvalidSignature`，说明签名不匹配，函数返回 `False`。

## 4. 实验流程

1. Alice 生成 RSA 密钥对：`SK_A` 和 `PK_A`。
2. 准备实验消息 `M1`，并统一编码为 bytes。
3. 调用 `sign_basic(SK_A, M1)` 生成签名 `Sig`。
4. 调用 `verify_basic(PK_A, M1, Sig)` 验证正确消息。
5. 将消息中的学号从 `20260001` 改为 `20260002`，得到 `M1'`。
6. 调用 `verify_basic(PK_A, M1', Sig)` 验证篡改消息。
7. 生成另一把错误公钥 `PK_B` 或 `wrong_public`。
8. 调用 `verify_basic(PK_B, M1, Sig)` 验证错误公钥场景。
9. 额外准备 `Mbin = M1 + b"\x00"`，验证程序能正确处理包含 NUL 字节的二进制消息。

## 5. 数据流图

```text
Alice:
M1 + SK_A
   |
   v
RSA-PSS Sign
   |
   v
Sig

Verifier:
M1 + Sig + PK_A
   |
   v
RSA-PSS Verify
   |
   v
True / False
```

## 6. 测试用例与预期结果

| 用例 | 操作 | 预期结果 | 原因 |
|---|---|---|---|
| A1 | `Verify(PK_A, M1, Sig)` | 通过 | 消息、签名、公钥完全匹配 |
| A2 | `Verify(PK_A, M1', Sig)` | 失败 | 消息内容被修改，签名不再对应新消息 |
| A3 | `Verify(PK_B, M1, Sig)` | 失败 | 签名由 `SK_A` 生成，不能被错误公钥验证 |
| A4 | 对 `Mbin` 签名并验签 | 通过 | 程序按 bytes 处理消息，不受字符串结束符影响 |

## 7. 结果分析

正确流程中，`PK_A` 能验证 `SK_A` 生成的签名，说明公私钥对匹配。消息被篡改后，即使只改变一个字符，验签也失败，说明数字签名可以检测数据完整性破坏。使用错误公钥验签失败，说明签名与发送者身份绑定。

因此，本实验验证了数字签名的两个基本能力：

- 数据完整性：消息改动会导致验签失败。
- 身份认证：只有对应私钥生成的签名才能被相应公钥验证。

## 8. 报告可写结论

RSA-PSS 数字签名能够将消息内容与发送方私钥绑定。接收方使用发送方公钥进行验证时，只要消息、签名或公钥任一项不匹配，验签都会失败。因此，基础数字签名可以实现消息完整性检测和发送方身份认证。
