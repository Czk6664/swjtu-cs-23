## 一、为什么要做风险管理？

先看几个企业的真实困惑（课件原话）：
- "安全投资逐年增加，但看不到收益" → 因为没按风险优先级规划。
- "按国家要求做了安全工作，但安全事件仍出现" → 因为没突出控制**高风险**。
- "有限的资金应优先投向哪？" → 因为没有风险报告做依据。

**结论**：好的风险管理能让机构以**最具成本效益**的方式，把已知风险维持在**可接受水平**。它不是要消灭所有风险（做不到也不划算），而是**抓主要矛盾**。

> 类比：得流感了，你可以等病发再吃药，也可以提前打疫苗。**两者结合**才是最佳风险管理。

**风险管理是一个持续的 PDCA 循环**（Plan-Do-Check-Act，计划-执行-检查-处理）。

## 二、核心术语（本章地基，必须背熟）

### 2.1 九个术语一览

| 术语 | 定义 |
|------|------|
| **资产 (Asset)** | 任何对组织**有价值、要保护**的东西 |
| **威胁源 (Threat Agent)** | 发起威胁的主体（黑客、间谍、自然）|
| **威胁 (Threat)** | 可能导致安全事故的活动 |
| **脆弱性 (Vulnerability)** | 资产的弱点/隐患（风险**内因**）|
| **控制措施 (Countermeasure)** | 防范威胁、降低风险的手段 |
| **可能性 (Likelihood)** | 威胁源利用脆弱性造成后果的可能性 |
| **影响 (Impact)** | 造成后果的程度大小 |
| **风险 (Risk)** | 威胁源利用脆弱性对资产造成不良后果的可能性 |
| **残余风险 (Residual Risk)** | 采取措施后**仍存在**的风险 |

### 2.2 资产的多种分类
资产可以是：物理的/逻辑的、硬件的/软件的、**有形的/无形的（如品牌、名誉）**、静态的/动态的、技术的/管理的。
> 重点：资产**不只是设备和数据**，品牌、名誉、人员也是资产。

### 2.3 威胁举例
操作失误、滥用授权、行为抵赖、身份假冒、口令攻击、密钥分析、漏洞利用、拒绝服务、窃取数据、物理破坏、**社会工程**。

### 2.4 脆弱性举例
系统代码缺陷、设备配置错误、操作流程缺陷、维护人员安全意识不足。
> 重点：**脆弱性本身不构成危害**，但满足条件时会被威胁源利用。

### 2.5 它们怎么组成"风险"？（关系图，必考）

```
威胁源 ──采用──> 威胁方式 ──利用──> 脆弱性 ──作用于──> 资产 ──产生──> 不良影响
                                                                    ↑
                                                            （控制措施在此切断链条）
```

一句话例子：
> 网站存在 **SQL 注入漏洞（脆弱性）**，普通**攻击者（威胁源）**用**自动化工具（威胁方式）**很容易控制**网站（资产）**，修改内容，从而损害**政府部门声誉（影响）**——这整件事就是**风险**。

### 2.6 残余风险
采取措施后剩下的风险。有些是**综合考虑成本与效益后故意不控制**的（控制成本 > 损失）。但要**持续监控**，一旦变成不可接受就再处理。

## 三、风险评估 vs 风险管理（容易混）

| | 风险管理 | 风险评估 |
|------|---------|---------|
| 目标 | 把风险降到可接受水平 | 确定风险并排优先级 |
| 范围 | 包括评估、决策、控制所有阶段 | 风险管理中的**一个阶段** |
| 周期 | 持续（PDCA）| 按需要 |

> 一句话：**风险评估是风险管理的起点和基础环节**。风险评估通常每 1-3 年做一次全面评估。

## 四、风险管理工作流程：四阶段 + 两贯穿（必考）

依据国标 GB/Z 24364《信息安全风险管理指南》：

**四个阶段（按顺序）：**

1. **建立背景**：确定对象和范围、组建团队、制定计划、获得支持；调研分析系统。
2. **风险评估**：识别威胁、脆弱性、控制措施；分析可能性和影响；判定风险等级。
3. **风险处理**：判断哪些风险可接受、确认处理目标、选择处置措施并实施。
4. **批准监督**：决策层**批准**风险管理活动；**监督**环境变化是否引入新风险。

**两个贯穿（全程进行）：**
- **监控审查**：及时发现变化、偏差、延误。
- **沟通咨询**：与领导、各部门、用户充分沟通；培训人员提高意识和技能。

## 五、四类风险处置方法（必考）

| 方法 | 含义 | 适用场景 |
|------|------|---------|
| **降低风险** | 采取保护措施减小风险 | **首选**，安全投入 < 损失价值时 |
| **转移风险** | 转给第三方（如保险、外包）| 低概率但高影响的风险 |
| **规避风险** | 干脆不用这个资产 | 损失无法接受又难降低时 |
| **接受风险** | 不进一步处理，承担后果 | 采取措施后必须接受的残余风险 |

**降低风险可以从风险的五个方面入手：**
- **减少威胁源**（法律制裁犯罪，威慑）
- **降低威胁能力**（身份鉴别，抵御冒充）
- **减少脆弱性**（打补丁、关无用端口）
- **防护资产**（建立安全域）
- **降低负面影响**（容灾备份、应急响应、业务连续计划）

## 六、系统生命周期中的风险管理

风险管理要**贯穿整个生命周期**，五个阶段每个都要做：

**规划 → 设计 → 实施 → 运维 → 废弃**

| 阶段 | 主要风险管理活动 |
|------|----------------|
| 规划 | 明确安全方针、需求分析、安全实现论证 |
| 设计 | 安全技术选择、安全产品选择 |
| 实施 | 安全测试、人员培训、授权运行 |
| 运维 | 安全运行管理、变更管理、风险再评估 |
| 废弃 | 安全报废处理（防报废设备泄密）|

> 核心思想：**越早做风险管理，后期处理同类问题成本越低。**

## 七、风险评估实施流程（重点）

### 7.1 国家政策要求
- 2003 年 27 号文：要重视信息安全风险评估。
- 2006 年国信办 5 号文：规定了风险评估的内容和原则。
- 电子政务项目要在试运行期间做风险评估，作为验收依据。

### 7.2 风险评估、检查评估、等级保护测评的关系
- **等保测评**：符合**国家**安全要求的符合性测评。
- **安全检查**：符合**行业主管**安全要求的符合性测评。
- **风险评估**：以被评估系统的**特定安全需求**为目标，做风险识别、分析、评价。

### 7.3 评估流程（四阶段 / 简化版 4R）
- 阶段1：评估准备（Readiness）
- 阶段2：风险识别（Realization）—— 资产识别、威胁识别、脆弱性识别、已有措施确认
- 阶段3：风险计算/评价（Calculation）
- 阶段4：风险处理/报告（Report）

> 类比：风险评估 = "健康体检 + 专项检查"。资产=身体，威胁=病毒，脆弱性=身体情况，控制措施=预防措施，结果=病情诊断和药方。

### 7.4 资产/威胁/脆弱性的赋值
国标 GB/T 20984 推荐用 **1~5 级**赋值：
- 资产：从机密性、完整性、可用性三方面赋值，再综合（常用**最大原则**：取最大值）。
- 威胁：按出现频率赋值。
- 脆弱性：按被利用后造成损害的严重程度赋值。

### 7.5 风险计算公式
```
风险值 = R(A, T, V) = R( L(T,V), F(Ia, Va) )
```
- A=资产, T=威胁, V=脆弱性
- L=威胁利用脆弱性导致安全事件的可能性
- F=安全事件造成的损失
- Ia=资产价值, Va=脆弱性严重程度

## 八、定性 vs 定量 vs 半定量分析（必考）

### 8.1 定性分析
用"高/中/低"等**文字等级**描述，靠经验判断。
- **优点**：简单、易达成一致、不需量化金额、便于非专业人员参与。
- **缺点**：主观性强、难做成本效益分析。
- 典型方法：因素分析法、逻辑分析法、历史比较法、德尔斐法、**矩阵法**（可能性×影响查表）。

### 8.2 定量分析
用**具体金额、数字**描述。
- **优点**：客观、可做投资收益分析、精度随历史数据积累提高。
- **缺点**：计算复杂耗时、可能把复杂事物简单化失真。

#### ALE 期望年度损失法（经典定量方法，必背公式）

```
SLE = AV × EF              单次损失 = 资产价值 × 暴露系数
ALE = SLE × ARO = AV × EF × ARO   年度损失 = 单次损失 × 年发生率
ROSI = 控制前ALE − 控制后ALE − 年控制成本   安全投资收益
```

| 符号 | 含义 |
|------|------|
| AV | 资产价值 |
| EF | 暴露系数（一次损失百分比）|
| SLE | 单一预期损失 |
| ARO | 年发生率 |
| ALE | 年度预期损失 |

### 8.3 半定量分析
定性和定量结合，如**相乘法**（可能性数值 × 影响数值 = 风险值）。

### 8.4 综合评估方法
如**层次分析法（AHP）**、基于模糊综合评价、灰色理论、机器学习的方法。

## 九、风险评估工具

- **风险评估与管理工具**：基于标准（NIST SP 800-30、ISO 27005）、基于知识、基于模型。
- **系统基础平台工具**：脆弱性扫描器、渗透测试工具。
- **辅助工具**：检查列表、IDS、安全审计工具、各种知识库/漏洞库。

> **渗透测试**：完全模拟黑客攻击，对重点目标深入探测，发现最脆弱环节。目的不是找出所有问题，而是直观反映系统安全状况，提高单位重视程度。

## 十、国产化替代（本章后半部分）

### 10.1 什么是国产化替代？
就是**替代被国外垄断的产品**，做"自主可控"。

### 10.2 为什么要做？
- 华为、中兴事件说明：**核心技术受制于人，产业可能一天之内瘫痪**。
- 棱镜门说明：机密数据放在国外数据库有泄露风险。

### 10.3 替代什么？（"正面战场"）

| 领域 | 国外垄断 | 国产替代 |
|------|---------|---------|
| **CPU** | Intel、AMD | 龙芯、飞腾、申威 |
| **操作系统** | Windows、安卓、iOS | 国产 Linux（麒麟、统信、深度等）|
| **数据库** | "IOE"（IBM、Oracle、EMC）| 达梦、金仓、南大通用、神通 |
| **应用软件** | Office、Adobe | 金蝶等 |

### 10.4 信创产业
**信创 = 信息技术应用创新行业**，从云计算、软件、硬件、安全等方面推进自主可控，逐步实现"去美化"，是国家战略。

## 十一、本章小结

- 风险管理是**持续的 PDCA** 过程，目标是把风险维持在可接受水平、抓主要矛盾。
- 核心术语：资产、威胁、威胁源、脆弱性、控制措施、风险、残余风险——要会画**关系链**。
- 流程：**建立背景 → 风险评估 → 风险处理 → 批准监督**，加上**监控审查、沟通咨询**两贯穿。
- 四类处置：**降低、转移、规避、接受**。
- 风险分析：定性（高中低）、定量（**ALE = AV×EF×ARO**）、半定量（相乘法）。
- 风险管理要**贯穿系统生命周期**。
- **国产化替代**：CPU、操作系统、数据库（IOE）是重点。

> **配套作业**：作业1（网络空间安全发展、风险与安全加固基础）。
