## 一、五重保护机制 —— 一句话记忆

ISC2（国际信息系统安全认证组织）把信息安全划分为 **5 重屏障**，用通俗话说就是让攻击者：

> **进不来 → 拿不走 → 改不了 → 看不懂 → 跑不掉 → 打不垮！**

| 通俗说法 | 对应技术 |
|---------|---------|
| 进不来 | 访问控制、防火墙、身份鉴别 |
| 拿不走 | 访问控制、加密 |
| 改不了 | 数据完整性 |
| 看不懂 | 加密（机密性）|
| 跑不掉 | 审计、抗抵赖 |
| 打不垮 | 备份恢复、高可用 |

## 二、OSI 安全体系结构（GB/T 18794，本章核心）

### 2.1 两个基本概念（一定要分清）

- **安全服务**：加强系统安全的一类**服务/功能**——"我要达到什么效果"。
- **安全机制**：保护系统安全的**技术手段**——"我用什么方法实现"。

> 关系：一个服务可由多个机制实现，一个机制也可支持多个服务。可以用一个**矩阵**来描述它们的对应关系。

### 2.2 五种安全服务（必背）

| 服务 | 子类 | 作用 |
|------|------|------|
| **鉴别** | 对等实体鉴别、数据源鉴别 | 确认身份真实 |
| **访问控制** | — | 防非授权使用资源 |
| **数据机密性** | 连接/无连接/选择字段/业务流机密性 | 防泄露 |
| **数据完整性** | 可恢复/不可恢复/选择字段/无连接完整性 | 防篡改 |
| **抗抵赖** | 数据源证明、交付证明的抗抵赖 | 防赖账 |

### 2.3 八种安全机制（必背）

| 机制 | 作用 |
|------|------|
| ① **加密** | 提供机密性，也为其他机制做补充；可配在多个协议层 |
| ② **数字签名** | 不可伪造、不可抵赖；签名 + 验证 |
| ③ **访问控制** | 按权限访问，非法访问有报警/审计 |
| ④ **数据完整性** | 发送端加附加码，接收端验证 |
| ⑤ **鉴别交换** | 用密码技术"握手"确认身份，防重放 |
| ⑥ **通信业务流填充** | 填充无用流量，防流量分析（要配合机密性才有效）|
| ⑦ **路由选择控制** | 选安全可靠的路由 |
| ⑧ **公证机制** | 第三方公证完整性、原发性、时间、目的地 |

**另有 5 种普遍安全机制**：可信功能模块、安全标记、事件检测、安全审计跟踪、安全恢复。

### 2.4 服务与机制、协议层的关系
- 不同安全服务在不同协议层（网络接口层/网络层/传输层/应用层）实现。
- 比如"抗抵赖"只在**应用层**实现；"连接机密性"各层都能做。

## 三、信息系统安全体系框架（技术/组织/管理三体系）

完整的安全体系由三大体系共同构建：

| 体系 | 内容 |
|------|------|
| **技术体系** | 物理安全技术、系统安全技术、网络安全技术、应用安全技术 |
| **组织机构体系** | 机构（决策层/管理层/执行层）、岗位、人事 |
| **管理体系** | 法律管理、制度管理、培训管理 |

> 核心理念：**三分技术，七分管理；管理与技术并重。**

**安全技术层次（五层）**：物理层、系统层、网络层、应用层、管理层。

## 四、加密机制（核心技术）

### 4.1 对称密码
- 加解密用**同一把密钥**。
- 优点：使用方便、速度快、错误扩散小。
- 缺点：**密钥分发问题**——n 个人需要 **n(n-1)/2** 把密钥。
- 两类：
  - **序列密码（流密码）**：逐比特加密，错误扩散低。
  - **分组密码**：固定长度分组加密，扩散性好，对插入/修改有免疫性，但加密速度慢。

### 4.2 公钥（非对称）密码
- 一对密钥：**公钥 + 私钥**。
- 典型算法：
  - **RSA**（1977）：一个算法实现签名和加密。私钥用于签名和解密，公钥用于验证和加密。
  - **ECC**（椭圆曲线，1985）：更小的密钥长度、更快，功能同 RSA。
- 两种用法：
  - **公钥加密 → 私钥解密**：保密。
  - **私钥签名 → 公钥验证**：身份鉴别。

### 4.3 消息鉴别 MAC（Message Authentication Code）
- 作用：验证消息**完整性 + 来源**。
- 双方共享密钥 K，用 K 算出 MAC 一起发送；接收方重新算 MAC 比对。
- 缺点：没有保密作用，需要共享密钥。

## 五、数字签名机制（重点）

### 5.1 数字签名的定义
> 附加在数据单元上的数据（或对数据的密码变换），使接收者能确认**来源**和**完整性**，并防止被他人伪造。

### 5.2 图解数字签名过程（课件鲍勃&苏珊的例子）
1. 鲍勃有公钥和私钥，把公钥发给朋友们。
2. 鲍勃给苏珊回信，先用 **Hash 函数**生成信件**摘要**。
3. 鲍勃用**私钥对摘要签名**（不是加密），生成"数字签名"。
4. 把签名附在信后一起发给苏珊。
5. 苏珊用鲍勃的**公钥解密签名**，得到摘要 → 证明信是鲍勃发的。
6. 苏珊再对信件本身算 Hash，与上一步摘要对比 → 一致说明没被改。

### 5.3 数字签名的 5 个作用
身份鉴别、防假冒、抗抵赖、防篡改、具有法律效力（与手工签名同等效力）。

### 5.4 先签名还是先加密？
**应先签名后加密**。如果先加密后签名，攻击者截获后可去掉签名换成自己的，造成混乱。

### 5.5 数字信封
- 问题：用 RSA 对整个消息签名/加密太慢。
- 解决：用**一次性对称密钥 K1** 加密消息（快），再用对方公钥加密 K1（封装），只对短的 K1 做非对称运算。这就是"数字信封"。

## 六、访问控制机制

- **目标**：防止对资源的未授权访问，使资源在授权范围内使用。
- **最小特权原则**：只给完成职责所需的最小权限。
- 模型分类：
  - **自主访问控制（DAC）**：访问矩阵、ACL、能力表。
  - **强制访问控制（MAC）**：BLP（保密性）、Biba（完整性）、Clark-Wilson、Chinese Wall。
  - **基于角色的访问控制（RBAC）**。
（详见 CH6）

---

## 七、数据完整性机制

**定义**：防止对交换数据的修改、插入、替换、删除，或被改后能检测出来。

**四种提供完整性的方式：**
1. **通过密码学**（对称→密封；非对称→数字签名）。
2. **通过上下文**（数据重复、预共识上下文）。
3. **通过探测和确认**（正馈等幂运算）。
4. **通过阻止**（访问控制，阻止物理访问）。

**几种典型实现机制（逐步改进）：**
1. 基于数据校验（CRC）—— 缺点：攻击者可同时改数据和 CRC。
2. 校验码 + 对称加密 —— 解决上面问题，但有密钥分发问题。
3. 非对称 + 对称结合 —— 解决密钥分发，用一次性密钥防重放。
4. 基于 RSA 数字签名 —— 无保密作用、速度慢。
5. 基于 MAC —— 无保密作用。
6. **基于消息摘要（Hash）** —— 不需共享密钥、有效率高，是常用方案。

> 关键安全要求：对给定消息 m1 及其摘要 H(m1)，找到另一个 m2≠m1 且 H(m2)=H(m1) 在计算上不可行（抗碰撞）。

## 八、鉴别交换机制

- 以**交换信息**的方式确认实体真实身份，对抗**假冒威胁**。
- 三种途径：你**知道**的（口令）、你**拥有**的（智能卡）、你**是**的（生物特征）。
- 分类：单向/双向/第三方鉴别；本地/远程鉴别。
- **鉴别 vs 认证**：
  - **鉴别（Authentication）**：验证身份真伪。
  - **认证（Certification）**：资格审查（评估系统是否满足安全要求）。
（详见 CH5）

## 九、其他机制

- **通信业务流填充**：填充流量防业务量分析（要配合机密服务才有效）。
- **路由选择控制**：动态/预选安全路由，发现非法处理时另选路由。
- **抗抵赖机制**：生成、收集、维护证据，解决"做没做过"的争议。
  - 直接数字签名法（凭自身特性）vs 仲裁数字签名（借第三方公证）。
- **公证机制**：第三方公证完整性、信源、时间、目的地等。
- **安全审计和报警**：事后审计检测安全策略执行情况；审计跟踪的存在对攻击有**威慑作用**。

## 十、本章小结

- 五重屏障：**进不来、拿不走、改不了、看不懂、跑不掉、打不垮**。
- **OSI 安全体系**：5 种**服务**（鉴别、访问控制、机密性、完整性、抗抵赖）+ 8 种**机制**。
- 安全体系框架 = **技术 + 组织 + 管理**三体系，"三分技术七分管理"。
- 核心技术：**对称/公钥密码、MAC、数字签名、完整性、鉴别、访问控制**。
- 数字签名 = **私钥签名 + 公钥验证 + Hash 摘要**，作用有 5 个，**先签名后加密**。
