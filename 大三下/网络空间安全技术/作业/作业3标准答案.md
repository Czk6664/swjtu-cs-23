## 四、简答题（共5题）

### 1. 比较包过滤、应用代理、状态检测和完全内容检测防火墙的工作层次、优点与不足。

**答：**
- **包过滤防火墙**：
  - 工作层次：网络层
  - 优点：速度快、配置简单、对用户透明
  - 不足：不维护连接状态、应用层控制弱、不能识别应用层攻击
- **应用代理防火墙**：
  - 工作层次：应用层
  - 优点：安全性高，能深度检测应用层内容
  - 不足：性能差、支持应用有限、对用户不透明
- **状态检测防火墙**：
  - 工作层次：2-4层
  - 优点：性能好、支持应用广、跟踪连接状态
  - 不足：对应用层内容检测有限
- **完全内容检测防火墙**：
  - 工作层次：2-7层
  - 优点：检测全面，能防范混合威胁
  - 不足：性能开销大、配置复杂

### 2. 简述企业典型防火墙部署中内网、外网和DMZ三类区域的访问策略。

**答：**
- **外部网络访问DMZ**：允许外部用户访问DMZ区指定服务器的指定服务（如Web、邮件）。
- **外部网络访问内网**：禁止外部用户直接访问内部网络。
- **内部网络访问DMZ**：允许内部用户按权限访问DMZ区服务器。
- **内部网络访问外网**：允许内部用户按策略访问互联网。
- **DMZ访问内网**：严格限制，仅允许必要通信。

### 3. 说明防火墙的主要局限，并提出与IDS、WAF、日志审计等联动的改进思路。

**答：**
- **主要局限**：
  1. 防外不防内，难以防范内部攻击。
  2. 不能防范绕过防火墙的攻击。
  3. 对应用层攻击检测有限。
  4. 对0day攻击无能为力。
- **联动改进**：
  - 与IDS联动：IDS检测内部攻击和绕过防火墙的攻击，防火墙阻断恶意流量。
  - 与WAF联动：WAF专门防护Web应用层攻击，弥补防火墙对应用层检测的不足。
  - 与日志审计联动：集中分析防火墙日志，发现异常行为，优化安全策略。

### 4. 比较异常检测与特征检测的基本思想、优点和缺点。

**答：**
- **异常检测**：
  - 基本思想：建立正常行为模型，识别偏离正常模式的行为。
  - 优点：能检测未知攻击（0day）。
  - 缺点：误报率高，正常行为模型建立困难。
- **特征检测**：
  - 基本思想：匹配已知攻击特征（签名）。
  - 优点：检测准确，误报率低。
  - 缺点：不能检测未知攻击，需要持续更新特征库。

### 5. 比较HIDS、NIDS和网络节点IDS的部署方式与适用场景。

**答：**
- **HIDS（主机入侵检测系统）**：
  - 部署方式：安装在单台主机上。
  - 适用场景：监控关键服务器，能检测加密通信解密后的内容，映射到具体用户。
- **NIDS（网络入侵检测系统）**：
  - 部署方式：部署在网络节点，监听网段流量。
  - 适用场景：监控整个网段，检测网络攻击。
- **网络节点IDS**：
  - 部署方式：部署在特定网络节点，监控特定流量。
  - 适用场景：监控关键网络节点，如数据库服务器前。

## 五、思考案例题（共3题）

### 案例1：企业边界防火墙与DMZ规划

**（1）画出或描述内网、外网、DMZ、防火墙和路由器的逻辑关系。**

**答：**
逻辑结构：
- 外部网络（互联网） → 路由器 → 外部防火墙 → DMZ区（Web、邮件、文件服务器） → 内部防火墙 → 内部网络（OA、财务、研发）。
- DMZ区位于内外防火墙之间，作为缓冲区。

**（2）为外部用户访问官网、内部用户访问互联网、外部用户访问内网分别制定访问控制策略。**

**答：**
- **外部用户访问官网**：允许外部用户访问DMZ区Web服务器的80/443端口。
- **内部用户访问互联网**：允许内部用户通过NAT访问互联网，限制访问时间和带宽。
- **外部用户访问内网**：禁止外部用户直接访问内部网络，特殊需求通过VPN接入。

**（3）说明NAT/MAP在该场景中的作用，并指出仍需哪些补充安全措施。**

**答：**
- **NAT/MAP作用**：
  1. 隐藏内部网络结构，使用私有IP。
  2. 解决公网IP不足。
  3. 通过端口映射让外部用户访问DMZ服务器。
- **补充安全措施**：
  1. 部署WAF防护Web攻击。
  2. 部署IDS检测内部攻击。
  3. 实施日志审计和监控。
  4. 定期漏洞扫描和渗透测试。

### 案例2：校园门户Web攻击防护

**（1）为什么传统包过滤或状态检测防火墙可能无法充分识别这类攻击？**

**答：**
传统包过滤或状态检测防火墙主要工作在网络层和传输层，检查IP地址、端口、协议等报头信息，不分析应用层内容。SQL注入和XSS攻击藏在正常的HTTP请求中（端口80/443），传统防火墙无法识别应用层攻击特征。

**（2）说明WAF可采用哪些检测思路，如特征识别、算法识别、模式匹配或自学习。**

**答：**
WAF可采用以下检测思路：
- **特征识别**：匹配已知攻击特征（如SQL注入的`1=1`）。
- **算法识别**：对攻击类型归类做模式化，进行语义理解。
- **模式匹配**：将攻击行为归纳成模式来匹配。
- **自学习技术**：学习正常访问模式，偏离的就预警。

**（3）如何在降低误报的同时保证业务连续性？**

**答：**
- **分阶段部署**：先监控模式运行，调整规则后再开启阻断。
- **白名单机制**：对正常业务流量设置白名单。
- **例外规则**：对误报高的规则进行例外处理。
- **持续优化**：定期分析日志，优化检测规则。
- **高可用部署**：WAF部署为集群，避免单点故障。

### 案例3：入侵检测部署与告警处置

**（1）应如何组合部署NIDS、HIDS或网络节点IDS？请说明位置和理由。**

**答：**
- **NIDS部署**：在核心交换机处镜像流量，监控整个内网流量，检测端口扫描、异常外联等网络攻击。
- **HIDS部署**：在关键服务器（如数据库服务器、域控制器）上安装，监控主机内部活动，检测加密通信解密后的内容。
- **网络节点IDS部署**：在数据库服务器前部署，监控数据库访问流量。

**（2）对于异常外联、端口扫描和失败登录，分别适合使用异常检测还是特征检测？**

**答：**
- **异常外联**：适合异常检测，建立正常外联模型，检测异常外联行为。
- **端口扫描**：适合特征检测，匹配端口扫描的特征（短时间内大量端口连接尝试）。
- **失败登录**：适合特征检测，匹配暴力破解特征（短时间内多次失败登录）。

**（3）发生告警后，如何进行响应、归并、联动和后续取证？**

**答：**
- **响应**：确认告警真实性，评估影响范围，采取抑制措施（如隔离受感染主机）。
- **归并**：将相关告警归并为一个事件，避免告警风暴。
- **联动**：与防火墙联动阻断恶意流量，与日志系统联动收集证据。
- **取证**：保存原始日志、流量镜像、主机快照，分析攻击路径和手法，完善安全措施。
