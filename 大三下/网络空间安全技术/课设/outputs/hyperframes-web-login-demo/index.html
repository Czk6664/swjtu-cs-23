项目背景：登录入口是 Web 安全的第一道关口

本设计不是网络安全综述，而是围绕可运行登录系统做安全加固。

口令泄露明文或弱哈希存储会在数据库泄露后直接暴露账号口令。
暴力破解攻击者可通过脚本连续尝试口令，消耗认证入口并撞出弱口令。
异常无感知异地、夜间、高频登录如果不记录，事后很难解释和追踪。
缺少审计没有日志就没有证据，安全事件发生后无法定位原因。
课程设计目标

在注册/登录流程中加入口令哈希、失败限制、账号锁定、日志记录、异常审计和告警输出，并用本人构造的数据与脚本验证效果。

密码哈希存储：数据库中不保存任何明文口令

PBKDF2-SHA256 + 26 万次迭代 + 随机盐，降低数据库泄露后的口令风险。

加盐每个用户独立随机盐，相同口令不会产生相同哈希。
慢哈希26 万次迭代抬高离线爆破成本。
恒定时间比较校验时使用 Werkzeug 的安全比较函数。

异常审计规则：从登录日志中识别四类异常行为

规则由本人设计并集中配置，答辩时可修改阈值重新验证。

暴力尝试5 分钟内失败次数 ≥ 5，生成 brute_force 告警，并触发账号锁定。
异地登录模拟10 分钟内同一账号出现 ≥ 2 个不同 IP，生成 multi_ip 告警。
非工作时间登录23:00--06:00 成功登录，生成 off_hours 告警。
高频登录60 秒内请求次数 ≥ 10，生成 high_frequency 告警。
