# 实验六：先加密后签名

## 1. 实验目标

本实验实现 `Encrypt then Sign`，即先将明文加密成密文，再对密文和关键元数据进行数字签名。

实验要完成：

- Alice 生成随机 AES 会话密钥。
- 使用 AES-256-GCM 加密明文。
- 使用 Bob 公钥 RSA-OAEP 加密会话密钥。
- 构造外层密文包。
- Alice 使用私钥对外层字段签名。
- Bob 先验签，再解密。
- 测试密文篡改、错误公钥、错误私钥等情况。

对应代码文件为 `secure_signature.py` 中的 `encrypt_then_sign()` 和 `verify_then_decrypt()`。

## 2. 实验原理

先加密后签名的核心思想是：

```text
Cipher = Encrypt(PK_B, M1)
Sig = Sign(SK_A, Cipher + metadata)
```

接收方 Bob 的处理顺序是：

```text
Verify(PK_A, Cipher + metadata, Sig)
Decrypt(SK_B, Cipher)
```

这种方式的特点是，接收方可以在解密前判断密文是否确实来自 Alice。如果验签不通过，Bob 可以直接拒绝，不必尝试解密。

## 3. 外层签名范围

本实验签名覆盖以下字段：

```python
{
    "algorithm_suite": "...",
    "encrypted_key_b64": "...",
    "nonce_b64": "...",
    "ciphertext_b64": "...",
    "tag_b64": "...",
    "metadata": {...}
}
```

签名覆盖密文、加密会话密钥、nonce、Tag 和元数据。只要这些字段被改动，验签就会失败。

## 4. 数据包结构

最终密文签名包格式如下：

```python
{
    "format": "encrypt-then-sign-v1",
    "algorithm_suite": "RSA-OAEP-SHA256+AES-256-GCM",
    "encrypted_key_b64": "...",
    "nonce_b64": "...",
    "ciphertext_b64": "...",
    "tag_b64": "...",
    "metadata": {...},
    "sign_alg": "RSA-PSS",
    "hash_alg": "SHA256",
    "signature_b64": "..."
}
```

其中：

- `ciphertext_b64` 是 AES-GCM 密文。
- `tag_b64` 是 AES-GCM 完整性标签。
- `encrypted_key_b64` 是用 Bob 公钥加密后的 AES 会话密钥。
- `signature_b64` 是 Alice 对外层密文字段的签名。

## 5. 核心函数

### `encrypt_then_sign(sender_private_key, receiver_public_key, plaintext, metadata)`

函数流程：

1. 使用随机 AES 会话密钥加密明文。
2. 使用 Bob 公钥加密 AES 会话密钥。
3. 将密文、Tag、nonce、加密会话密钥和元数据组成外层包。
4. 使用 Alice 私钥对外层关键字段签名。
5. 将签名加入包中并返回。

### `verify_then_decrypt(receiver_private_key, sender_public_key, signed_cipher_package)`

函数流程：

1. 取出外层待签名字段。
2. 使用 Alice 公钥验签。
3. 如果验签失败，直接返回，不执行解密。
4. 如果验签成功，用 Bob 私钥解密 AES 会话密钥。
5. 用 AES-GCM 解密密文并验证 Tag。
6. 返回验签结果、解密结果、明文和错误原因。

## 6. 实验流程

1. Alice 准备明文 `M1` 和元数据。
2. Alice 调用 `encrypt_then_sign(SK_A, PK_B, M1, metadata)`。
3. Bob 调用 `verify_then_decrypt(SK_B, PK_A, package)`。
4. 篡改密文 1 字节，再执行验签和解密。
5. 使用错误发送方公钥验签。
6. 使用正确发送方公钥验签，但使用错误接收方私钥解密。
7. 记录验签结果和解密结果。

## 8. 测试用例与预期结果

| 用例 | 操作 | 验签结果 | 解密结果 | 原因 |
|---|---|---|---|---|
| F1 | 正常流程 | 通过 | 成功 | 外层签名和密文均有效 |
| F2 | 篡改密文 1 字节 | 失败 | 失败 | 密文在签名范围内 |
| F3 | 使用错误发送方公钥 | 失败 | 失败 | 签名不能被错误公钥验证 |
| F4 | 使用错误接收方私钥 | 通过 | 失败 | 签名有效，但无法解密会话密钥 |

## 9. 结果分析

实验六与实验五的主要区别是验签时机。实验五必须先解密才能验签，而实验六可以先验签再解密。

当密文被篡改时，外层签名立即失败，程序无需进入解密阶段。当使用错误发送方公钥时，验签也会失败。使用错误接收方私钥时，签名仍然可以通过，因为签名验证只依赖 Alice 公钥；但解密会话密钥需要 Bob 私钥，错误私钥无法完成解密。

## 10. 报告可写结论

先加密后签名可以在解密前确认密文来源，适合需要先筛选来源再处理密文的场景。实验表明，密文、加密会话密钥或元数据一旦被篡改，外层签名立即失效；即使签名通过，接收方仍需要正确私钥才能解密得到明文。
