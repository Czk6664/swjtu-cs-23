# 实验二：摘要后签名与完整性检测

## 1. 实验目标

本实验在基础签名的基础上，显式引入消息摘要，观察摘要在数字签名中的作用。

实验要完成：

- 计算原始消息 `M1` 的 SHA256 摘要。
- 对摘要值进行数字签名。
- 接收方重新计算消息摘要并验签。
- 修改消息得到 `M1'`，重新计算摘要并再次验签。
- 比较 `Hash(M1)` 与 `Hash(M1')` 是否相同。

对应代码文件为 `digest_signature.py`，主程序调用位置在 `main.py` 的 `experiment_2`。

## 2. 实验原理

实际数字签名通常不会直接对任意长度的大消息做数学签名，而是先计算消息摘要：

```text
H = Hash(M)
Sig = Sign(SK_A, H)
```

接收方验证时执行：

```text
H' = Hash(M_received)
Verify(PK_A, H', Sig)
```

如果消息没有被修改，则 `H' == H`，验签通过；如果消息发生变化，则摘要值会改变，验签失败。

本实验使用 `SHA256`，输出长度固定为 256 bit，也就是 32 bytes。无论原始消息多长，摘要长度都固定。

## 3. SHA256 的完整性检测作用

哈希函数具有雪崩效应：输入只要发生极小变化，输出摘要也会发生明显变化。

例如：

```text
M1  = ... 学号=20260001
M1' = ... 学号=20260002
```

这两条消息只改变了最后一位学号，但 `SHA256(M1)` 与 `SHA256(M1')` 会完全不同。数字签名绑定的是摘要，因此摘要改变后，原签名无法通过验证。

## 4. 核心函数

### `sign_with_digest(private_key, message, hash_alg="SHA256", sign_alg="RSA-PSS")`

该函数先计算消息摘要：

```python
digest = hash_bytes(message, hash_alg)
```

再使用 `Prehashed` 模式对摘要签名：

```python
private_key.sign(
    digest,
    rsa_pss_padding(hash_alg),
    utils.Prehashed(get_hash_algorithm(hash_alg)),
)
```

`Prehashed` 的含义是：传入签名算法的数据已经是摘要，不需要库再对它重复哈希。

### `verify_with_digest(public_key, message, signature, hash_alg="SHA256", sign_alg="RSA-PSS")`

验证函数重新计算收到消息的摘要：

```python
digest = hash_bytes(message, hash_alg)
```

然后用同样的 `Prehashed` 模式验证签名。如果消息被篡改，新摘要和签名内部绑定的摘要不一致，验签失败。

### `compare_digest_before_after(original, tampered, hash_alg="SHA256")`

该函数分别计算原消息和篡改消息的摘要，并返回：

- 原始摘要十六进制值。
- 篡改后摘要十六进制值。
- 两个摘要是否相同。
- 摘要片段，便于报告展示。

## 5. 实验流程

1. 准备原始消息 `M1`。
2. 调用 `sign_with_digest(SK_A, M1)`：
   - 计算 `Hash(M1)`。
   - 对摘要生成签名 `Sig`。
3. 调用 `verify_with_digest(PK_A, M1, Sig)` 验证原始消息。
4. 将消息学号从 `20260001` 改为 `20260002`，得到 `M1'`。
5. 调用 `verify_with_digest(PK_A, M1', Sig)` 验证篡改消息。
6. 调用 `compare_digest_before_after(M1, M1')` 比较两个摘要。
7. 在报告中记录 `Hash(M1)`、`Hash(M1')`、验签结果和摘要是否相同。

## 7. 测试用例与预期结果

| 用例 | 操作 | 预期结果 | 原因 |

## 8. 结果分析

本实验说明摘要在数字签名中起到桥梁作用。签名算法实际保护的是消息摘要，而摘要又由完整消息计算得到。因此，签名间接保护了完整消息内容。

如果攻击者修改消息但不能重新生成合法签名，接收方重新计算出的摘要就无法与原签名匹配，验签失败。这就是数字签名实现完整性检测的基本机制。

## 9. 报告可写结论

消息摘要把任意长度消息压缩为固定长度的唯一性表示。数字签名对摘要进行保护，接收方通过重新计算摘要并验签即可发现消息篡改。实验中仅修改学号一位，SHA256 摘要已经完全不同，原签名无法验证通过，体现了数字签名的完整性保护能力。
