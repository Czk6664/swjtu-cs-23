# 实验四：带元数据的数字签名

## 1. 实验目标

本实验将消息内容与元数据一起绑定到数字签名中，理解签名数据包设计和抗重放的基本思想。

实验要完成：

- 构造消息和元数据。
- 将消息与元数据按固定规则序列化。
- 对序列化后的整体数据生成签名。
- 接收方按相同规则重建待验签数据并验签。
- 修改时间戳、算法标识、接收方标识等元数据，观察验签失败。

对应代码文件为 `metadata_signature.py`，主程序调用位置在 `main.py` 的 `experiment_4`。

## 2. 实验原理

基础数字签名只绑定消息内容。但真实系统中，签名通常还需要绑定上下文信息，例如：

- 谁发送的：`sender_id`
- 发给谁：`receiver_id`
- 使用什么算法：`algorithm_suite`
- 什么时候签名：`timestamp`
- 是否为一次性消息：`nonce`

如果这些字段没有纳入签名，攻击者可能复制旧消息、替换接收者、伪造算法说明，造成重放攻击或上下文混淆。

因此，本实验将消息和元数据一起序列化后签名：

```text
SignedBytes = Serialize({
    message_b64,
    metadata
})

Sig = Sign(SK_A, SignedBytes)
```

任何字段变化都会导致 `SignedBytes` 变化，从而导致验签失败。

## 3. 元数据字段设计

本实验元数据结构如下：

```python
{
    "sender_id": "Alice",
    "receiver_id": "Bob",
    "algorithm_suite": "RSA-PSS+SHA256",
    "timestamp": "2026-04-22T03:00:00+00:00",
    "nonce": "随机十六进制字符串"
}
```

字段作用：

| 字段 | 作用 |
|---|---|
| `sender_id` | 标识签名发送方 |
| `receiver_id` | 标识预期接收方，防止签名被转给其他对象 |
| `algorithm_suite` | 绑定算法选择，防止算法降级或说明被篡改 |
| `timestamp` | 记录签名时间，可用于有效期判断 |
| `nonce` | 随机数，用于区分不同签名包，降低重放风险 |

## 4. 规范序列化的重要性

签名要求发送方和接收方对同一份逻辑数据得到完全相同的字节串。如果 JSON 字段顺序不同、空格不同，最终字节串就不同，验签也会失败。

因此本项目使用 canonical JSON：

```python
json.dumps(
    obj,
    sort_keys=True,
    separators=(",", ":"),
    ensure_ascii=False,
).encode("utf-8")
```

它保证：

- 字段按键名排序。
- 不输出多余空格。
- 中文按 UTF-8 编码保留。
- 同一结构总是得到同一字节串。

## 5. 核心函数

### `build_metadata(sender_id, algorithm)`

生成元数据，包括发送者、接收者、算法标识、UTC 时间戳和随机 nonce。

### `serialize_signed_content(message, metadata)`

将消息转为 Base64，再与元数据组合后执行规范 JSON 序列化：

```python
{
    "message_b64": "...",
    "metadata": {...}
}
```

### `sign_with_metadata(private_key, message, metadata)`

对序列化结果签名，生成签名包：

```python
{
    "format": "metadata-signature-v1",
    "message_b64": "...",
    "metadata": {...},
    "sign_alg": "RSA-PSS",
    "hash_alg": "SHA256",
    "signature_b64": "..."
}
```

### `verify_metadata_signature(public_key, package)`

验证函数会：

1. 检查元数据字段是否存在。
2. 检查时间戳和 nonce 格式。
3. 重新序列化 `message + metadata`。
4. 使用公钥验证签名。

## 6. 实验流程

1. 构造消息 `M1`。
2. 调用 `build_metadata("Alice", "RSA-PSS+SHA256")` 生成元数据。
3. 调用 `sign_with_metadata(SK_A, M1, metadata)` 生成签名包。
4. 调用 `verify_metadata_signature(PK_A, package)` 验证正常包。
5. 修改 `timestamp`，再次验签。
6. 修改 `algorithm_suite`，再次验签。
7. 修改 `receiver_id`，再次验签。
8. 记录各场景结果。

## 7. 测试用例与预期结果

| 用例 | 操作 | 预期结果 | 原因 |
|---|---|---|---|
| D1 | 正常签名包 | 通过 | 消息和元数据未变化 |
| D2 | 修改时间戳 | 失败 | 时间戳在签名范围内 |
| D3 | 修改算法标识 | 失败 | 算法字段在签名范围内 |
| D4 | 修改接收方 ID | 失败 | 接收方身份在签名范围内 |

## 8. 结果分析

本实验说明数字签名不只能保护消息正文，也可以保护消息的上下文。如果时间戳、随机数、算法标识或接收者身份被修改，签名都会失效。

`timestamp` 和 `nonce` 的组合可以支持抗重放设计：接收方可以检查消息是否过期，也可以记录已经见过的 nonce，拒绝重复出现的数据包。当前代码主要演示字段绑定，实际生产系统还需要维护 nonce 缓存和时间窗口。

## 9. 报告可写结论

带元数据的签名包能够将消息内容和上下文信息整体绑定。实验中仅修改时间戳、算法标识或接收方 ID，验签即失败，说明这些字段已经被签名保护。这种设计可以防止签名被挪用、算法说明被篡改，并为抗重放机制提供基础。
