# 实验三：文件分离式数字签名

## 1. 实验目标

本实验实现“原文件 + 独立签名文件 + 公钥”的验证模式。该模式常见于：

- 软件安装包发布。
- 离线文档签发。
- 镜像文件校验。
- 电子资料归档。

实验要完成：

- 对文件分块计算摘要。
- 对文件摘要生成签名。
- 将签名保存为独立 `.sig` 文件。
- 使用原文件、签名文件和公钥验证签名。
- 篡改原文件或签名文件，观察验证失败。

对应代码文件为 `file_signature.py`，主程序调用位置在 `main.py` 的 `experiment_3`。

## 2. 实验原理

文件可能很大，不能总是一次性读入内存。因此本实验采用分块读取文件的方式计算 SHA256 摘要：

```text
文件块1 -> Hash.update()
文件块2 -> Hash.update()
...
最后一块 -> Hash.finalize()
```

得到文件摘要后，对摘要执行 RSA-PSS 签名：

```text
File -> SHA256 -> FileDigest -> Sign(SK_A, FileDigest) -> Signature
```

签名不直接写入原文件，而是保存到独立签名文件中。验证时重新计算原文件摘要，再用公钥验证签名。

## 3. 签名文件格式

本实验使用 JSON 保存独立签名文件，便于观察和写报告：

```json
{
  "format": "detached-file-signature-v1",
  "sign_alg": "RSA-PSS",
  "hash_alg": "SHA256",
  "created_at": "2026-04-22T03:00:00+00:00",
  "file_digest_hex": "...",
  "signature_b64": "..."
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `format` | 签名文件格式版本 |
| `sign_alg` | 签名算法 |
| `hash_alg` | 文件摘要算法 |
| `created_at` | 签名生成时间 |
| `file_digest_hex` | 文件摘要十六进制展示值 |
| `signature_b64` | Base64 编码后的签名值 |

## 4. 核心函数

### `digest_file(file_path, hash_alg="SHA256")`

分块读取文件并计算摘要：

```python
for chunk in iter(lambda: file_obj.read(1024 * 1024), b""):
    digest.update(chunk)
```

每次读取 1MB，适合处理较大文件。

### `sign_file(private_key, file_path, sign_path)`

流程为：

1. 调用 `digest_file()` 计算文件摘要。
2. 使用 `RSA-PSS + Prehashed(SHA256)` 对摘要签名。
3. 将算法、摘要、签名和时间写入 `.sig` 文件。

### `verify_file_signature(public_key, file_path, sign_path)`

流程为：

1. 读取 `.sig` 文件。
2. 重新计算当前文件摘要。
3. 取出签名文件中的 `signature_b64` 并解码。
4. 使用公钥验证当前文件摘要和签名是否匹配。
5. 返回 `True` 或 `False`。

### `build_file_signature_report(file_path, sign_path, verify_result)`

整理实验报告需要的字段：

- 文件路径。
- 文件大小。
- 签名文件大小。
- 文件摘要片段。
- 验签结果。

## 5. 实验流程

1. 创建测试文件 `test_small.txt`，内容包含 `value=98`。
2. 调用 `sign_file(SK_A, "test_small.txt", "test_small.txt.sig")` 生成签名文件。
3. 调用 `verify_file_signature(PK_A, "test_small.txt", "test_small.txt.sig")` 验证原文件。
4. 创建篡改文件 `test_small_tampered.txt`，将 `98` 改为 `99`。
5. 使用原签名文件验证篡改文件，观察失败。
6. 创建篡改签名文件 `test_small_tampered.sig`，翻转签名值中的 1 字节。
7. 使用原文件和篡改签名文件验证，观察失败。
8. 调用 `build_file_signature_report()` 生成报告数据。

## 7. 测试用例与预期结果

| 用例 | 操作 | 预期结果 | 原因 |
|---|---|---|---|
| C1 | 生成 `test_small.txt.sig` | 成功 | 私钥可以为文件摘要生成签名 |
| C2 | 原文件 + 原签名验证 | 通过 | 文件摘要与签名匹配 |
| C3 | 文件内容从 `98` 改为 `99` | 失败 | 当前文件摘要改变 |
| C4 | 签名文件任意 1 字节被修改 | 失败 | 签名值被破坏 |

## 8. 结果分析

文件分离式签名不会改变原文件内容，而是通过独立 `.sig` 文件保存签名信息。验证方只需要拿到原文件、签名文件和发送方公钥，就可以判断文件是否来自对应签名者，以及文件内容是否被修改。

文件内容被修改后，即使只改动一个字符，重新计算出的文件摘要也会不同，原签名无法验证通过。签名文件本身被篡改后，签名数学结构被破坏，同样无法通过验证。

## 9. 报告可写结论

分离式数字签名适合软件包发布和离线文件校验。签名文件独立保存，既不改变原文件，也能通过公钥验证文件完整性和来源。实验中篡改原文件或篡改签名文件都会导致验证失败，说明该模式能够有效检测文件内容和签名数据的非法修改。
