# 实验七：数字信封 + 数字签名综合实验

## 1. 实验目标

本实验实现一个综合安全消息包，将数字信封和数字签名结合起来，提供：

- 机密性：只有 Bob 能解密消息。
- 完整性：密文或 Tag 被篡改会被检测。
- 身份认证：接收方能确认消息由 Alice 签发。
- 字段绑定：算法标识、发送者、接收者、密文、会话密钥等关键字段都被签名保护。

对应代码文件为 `secure_signature.py` 中的：

- `build_secure_envelope()`
- `verify_secure_envelope_signature()`
- `open_secure_envelope()`
- `tamper_secure_envelope()`

## 2. 实验原理

数字信封是一种混合加密结构：

```text
随机会话密钥 K
Ciphertext = AES-GCM(K, plaintext)
EncryptedKey = RSA-OAEP(PK_B, K)
```

这样既利用 AES 的高效加密能力，也利用 RSA 公钥加密安全传输会话密钥。

本实验在数字信封外层再加入数字签名：

```text
Sig_outer = Sign(SK_A, envelope_fields)
```

签名覆盖密文、加密会话密钥、算法标识、发送者、接收者、时间戳、nonce 和 Tag。任何关键字段被修改，签名都会失效。

## 3. 安全包结构

安全信封结构如下：

```python
{
    "format": "secure-envelope-v1",
    "algorithm_suite": "RSA-OAEP-SHA256+AES-256-GCM",
    "sender_id": "Alice",
    "receiver_id": "Bob",
    "created_at": "...",
    "nonce_b64": "...",
    "encrypted_key_b64": "...",
    "ciphertext_b64": "...",
    "tag_b64": "...",
    "sign_alg": "RSA-PSS",
    "hash_alg": "SHA256",
    "signature_b64": "..."
}
```

字段说明：

| 字段 | 作用 |
|---|---|
| `format` | 包格式版本 |
| `algorithm_suite` | 加密算法套件 |
| `sender_id` | 发送者标识 |
| `receiver_id` | 接收者标识 |
| `created_at` | 创建时间 |
| `nonce_b64` | AES-GCM nonce |
| `encrypted_key_b64` | RSA 加密后的 AES 会话密钥 |
| `ciphertext_b64` | AES-GCM 密文 |
| `tag_b64` | AES-GCM 认证标签 |
| `sign_alg` | 外层签名算法 |
| `hash_alg` | 外层摘要算法 |
| `signature_b64` | 外层签名 |

## 4. 外层签名绑定字段

函数 `_envelope_signed_fields()` 明确规定签名覆盖字段：

```python
{
    "format": secure_envelope["format"],
    "algorithm_suite": secure_envelope["algorithm_suite"],
    "sender_id": secure_envelope["sender_id"],
    "receiver_id": secure_envelope["receiver_id"],
    "created_at": secure_envelope["created_at"],
    "nonce_b64": secure_envelope["nonce_b64"],
    "encrypted_key_b64": secure_envelope["encrypted_key_b64"],
    "ciphertext_b64": secure_envelope["ciphertext_b64"],
    "tag_b64": secure_envelope["tag_b64"],
}
```

这些字段使用 canonical JSON 序列化后由 Alice 私钥签名。接收方验签时必须重建完全相同的字段集合。

注意：`signature_b64` 本身不参与签名，否则会形成循环依赖。

## 5. 打开安全信封的顺序

`open_secure_envelope()` 的处理顺序是：

1. 检查算法标识是否为预期值。
2. 使用 Alice 公钥验证外层签名。
3. 如果验签失败，直接拒绝，不解密。
4. 使用 Bob 私钥解密 `encrypted_key_b64`，恢复 AES 会话密钥。
5. 使用 AES-GCM 解密 `ciphertext_b64`。
6. AES-GCM 自动验证 `tag_b64`。
7. 如果 Tag 验证成功，返回明文和完整性通过。

这种顺序体现了“先认证再处理”的思想，可以避免对明显伪造的数据包执行解密操作。

## 6. 核心函数

### `build_secure_envelope(sender_private_key, receiver_public_key, plaintext, sender_id, receiver_id)`

构造安全信封：

1. 随机生成 AES-256-GCM 会话密钥和 nonce。
2. 用会话密钥加密明文，得到密文和 Tag。
3. 用 Bob 公钥加密会话密钥。
4. 构造安全包元数据。
5. 对关键字段集合执行 RSA-PSS 签名。
6. 返回包含加密会话密钥、密文、Tag、元数据和签名的完整包。

### `verify_secure_envelope_signature(sender_public_key, secure_envelope)`

验证外层签名：

1. 检查 `algorithm_suite` 是否匹配。
2. 重建签名字段集合。
3. Base64 解码签名。
4. 用 Alice 公钥验签。

### `open_secure_envelope(receiver_private_key, sender_public_key, secure_envelope)`

完整打开信封：

1. 先验签。
2. 后解密会话密钥。
3. 再解密密文。
4. 返回签名验证、解密和完整性检测结果。

### `tamper_secure_envelope(secure_envelope, field_name)`

用于构造篡改包：

- 对 Base64 二进制字段翻转 1 个字节。
- 对文本字段追加篡改标记。
- 返回深拷贝后的篡改包，不修改原始包。

## 7. 实验流程

1. Alice 准备明文 `M1`。
2. Alice 调用 `build_secure_envelope(SK_A, PK_B, M1, "Alice", "Bob")`。
3. Bob 调用 `open_secure_envelope(SK_B, PK_A, envelope)` 验证正常包。
4. 篡改 `ciphertext_b64`，再次打开信封。
5. 篡改 `tag_b64`，再次打开信封。
6. 篡改 `algorithm_suite`，再次打开信封。
7. 篡改 `receiver_id`，再次打开信封。
8. 使用错误发送方公钥验签。
9. 记录验签结果、解密结果和完整性结果。

## 10. 结果分析

实验七综合了前面多个实验的思想：

- 使用 AES-GCM 保护数据机密性和密文完整性。
- 使用 RSA-OAEP 保护随机会话密钥。
- 使用 RSA-PSS 将外层关键字段绑定到 Alice 身份。
- 使用元数据防止上下文被篡改。

由于密文、Tag、算法标识和接收方 ID 都在签名范围内，攻击者无法只修改某个字段而保持签名有效。即使绕过签名检查，AES-GCM 的 Tag 也能检测密文完整性破坏。

## 11. 报告可写结论

数字信封 + 数字签名方案同时实现了机密性、完整性和身份认证。随机会话密钥负责高效加密数据，接收方公钥保护会话密钥，发送方私钥对关键字段签名。实验中修改密文、Tag、算法标识、接收方 ID 或使用错误公钥都会导致验证失败，说明安全包中的关键字段已被有效绑定。
