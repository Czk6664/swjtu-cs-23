# 实验五：先签名后加密

## 1. 实验目标

本实验实现 `Sign then Encrypt`，即先对明文和元数据签名，再把明文、签名和元数据整体加密给接收方 Bob。

实验要完成：

- Alice 对明文和元数据生成签名。
- 构造内部明文包 `{plaintext, metadata, signature}`。
- 生成随机 AES 会话密钥。
- 用 AES-256-GCM 加密内部明文包。
- 用 Bob 的公钥 RSA-OAEP 加密会话密钥。
- Bob 先解密，再使用 Alice 公钥验签。
- 篡改密文、Tag、内部签名和私钥，观察失败位置。

对应代码文件为 `secure_signature.py` 中的 `sign_then_encrypt()` 和 `decrypt_then_verify()`。

## 2. 实验原理

先签名后加密的核心思想是：

```text
Sig = Sign(SK_A, plaintext + metadata)
Inner = plaintext + metadata + Sig
CipherPackage = Encrypt(PK_B, Inner)
```

接收方 Bob 执行：

```text
Inner = Decrypt(SK_B, CipherPackage)
Verify(PK_A, plaintext + metadata, Sig)
```

这种方式中，签名保护的是明文和元数据；同时签名本身也被加密隐藏在密文内部。外部观察者看不到明文、元数据细节和签名值。

## 3. 加密结构

本实验使用混合加密：

- AES-256-GCM 加密内部明文包。
- RSA-OAEP-SHA256 加密 AES 会话密钥。

原因是 RSA 不适合直接加密较大数据，而 AES 适合高效加密任意长度内容。因此常用设计是：

```text
随机生成 K
Ciphertext = AES-GCM(K, InnerPackage)
EncryptedKey = RSA-OAEP(PK_B, K)
```

最终外部包结构：

```python
{
    "format": "sign-then-encrypt-v1",
    "algorithm_suite": "RSA-OAEP-SHA256+AES-256-GCM",
    "encrypted_key_b64": "...",
    "nonce_b64": "...",
    "ciphertext_b64": "...",
    "tag_b64": "..."
}
```

内部包结构在加密前为：

```python
{
    "format": "sign-then-encrypt-inner-v1",
    "plaintext_b64": "...",
    "metadata": {...},
    "sign_alg": "RSA-PSS",
    "hash_alg": "SHA256",
    "signature_b64": "..."
}
```

## 4. AES-GCM Tag 的作用

AES-GCM 属于认证加密 AEAD 算法。它不仅提供机密性，还生成认证标签 `tag`。

解密时，如果以下任意字段被篡改：

- `ciphertext`
- `tag`
- `nonce`

AES-GCM 都会校验失败并抛出异常，程序返回解密失败。

因此实验五中，篡改外层密文或 Tag 时，流程在解密阶段失败，无法进入验签阶段。

## 5. 核心函数

### `sign_then_encrypt(sender_private_key, receiver_public_key, plaintext, metadata)`

函数流程：

1. 构造待签名数据：

   ```python
   {
       "plaintext_b64": "...",
       "metadata": metadata
   }
   ```

2. 使用 Alice 私钥签名。
3. 将明文、元数据和签名组成内部包。
4. 使用 AES-GCM 加密内部包。
5. 使用 Bob 公钥加密 AES 会话密钥。
6. 返回外部安全包。

### `decrypt_then_verify(receiver_private_key, sender_public_key, secure_package)`

函数流程：

1. 用 Bob 私钥解密 `encrypted_key_b64`，恢复 AES 会话密钥。
2. 用 AES-GCM 解密内部包。
3. 从内部包取出明文、元数据和签名。
4. 重建待签名数据。
5. 使用 Alice 公钥验签。
6. 返回解密结果、验签结果、明文和错误原因。

### `tamper_sign_then_encrypt_inner_signature(...)`

该函数是为了构造特殊测试：让解密仍然成功，但内部签名被破坏。

它的做法是：

1. 用 Bob 私钥正常解密内部包。
2. 翻转内部签名的 1 个字节。
3. 用新的 AES-GCM 会话密钥重新加密内部包。
4. 用 Bob 公钥重新加密会话密钥。

这样 Bob 能解密，但最终验签失败。

## 6. 实验流程

1. Alice 准备明文 `M1` 和元数据。
2. Alice 调用 `sign_then_encrypt(SK_A, PK_B, M1, metadata)`。
3. Bob 调用 `decrypt_then_verify(SK_B, PK_A, package)`。
4. 篡改 `ciphertext_b64`，再次解密验签。
5. 篡改 `tag_b64`，再次解密验签。
6. 篡改内部签名，重新加密后再次解密验签。
7. 使用错误私钥尝试解密。
8. 记录解密结果和验签结果。

## 7. 数据流图

```text

   |

```

## 8. 测试用例与预期结果

| 用例 | 操作 | 解密结果 | 验签结果 | 原因 |
|---|---|---|---|---|
| E1 | 正常流程 | 成功 | 通过 | 密文未变，签名匹配 |
| E2 | 篡改密文 | 失败 | 失败 | AES-GCM 完整性校验失败 |
| E2 | 篡改 Tag | 失败 | 失败 | Tag 不匹配，无法解密 |
| E3 | 篡改内部签名 | 成功 | 失败 | 明文可恢复，但签名被破坏 |
| E4 | 错误私钥解密 | 失败 | 失败 | 无法恢复 AES 会话密钥 |

## 9. 结果分析

先签名后加密的特点是签名保护明文，同时签名本身也被加密隐藏。接收方必须先解密，才能看到签名并执行验签。

篡改外层密文或 Tag 时，AES-GCM 会在解密阶段检测到完整性破坏。篡改内部签名时，由于重新加密后的密文是合法的，解密可以成功，但验签会失败。这说明加密完整性和数字签名完整性关注的是不同层次。

## 10. 报告可写结论

先签名后加密能够同时提供明文来源认证、完整性保护和机密性。签名绑定明文和元数据，加密隐藏内部签名包。实验表明，外层密文或 Tag 被篡改会导致解密失败，内部签名被篡改会导致验签失败，错误私钥无法解密会话密钥。
