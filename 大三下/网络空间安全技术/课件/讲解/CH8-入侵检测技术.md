## 一、为什么需要入侵检测？

### 1.1 安全不只是一堵墙

防火墙很重要，但它有局限：
- 内部攻击穿不过来？错了——内部人员也可以搞破坏
- 防火墙不能检测已经通过的攻击
- 新漏洞不断出现，静态规则追不上

> 形象比喻：防火墙是小区的大门保安，IDS 是小区里的巡逻队和监控摄像头。保安只管门口进出，但小偷翻墙进来、或者住户自己搞破坏，保安管不了。

### 1.2 安全工具对比

| 工具 | 主要功能 | 优点 | 缺点 |
|------|---------|------|------|
| **防火墙** | 网络访问控制 | 成本低、性能好、简单易用 | 无法检测内部攻击、对某些攻击无效 |
| **IDS** | 检测入侵行为 | 实时检测、深层分析 | 误报/漏报、配置复杂 |
| **扫描器** | 发现系统漏洞 | 主动发现隐患 | 只是发现不能防御、消耗资源 |
| **VPN** | 加密隧道通信 | 保护传输安全 | 隧道内恶意流量检测困难 |
| **防病毒** | 查杀病毒木马 | 针对性强 | 依赖特征库更新、零日无效 |

### 1.3 预防-检测-响应：三步防御

这是安全防御的基本理念：

1. **预防**：防火墙、加密、访问控制 —— 挡住攻击
2. **检测**：IDS、日志分析 —— 发现已经进来的攻击
3. **响应**：应急响应 —— 处理攻击后果

## 二、入侵检测基本概念

### 2.1 入侵的定义

**入侵**：任何试图危害计算机资源的完整性、保密性或可用性的行为。

入侵的分类：

| 类型 | 说明 |
|------|------|
| **外部渗透** | 未授权用户从外部入侵 |
| **内部渗透** | 授权用户越权访问 |
| **不法行为** | 合法用户做非法的事 |

### 2.2 IDS 的定义与功能

**IDS（Intrusion Detection System）** = 入侵检测系统。

六大功能：
1. **监视和分析**用户和系统活动
2. **审计**系统的配置和脆弱性
3. **评估**关键系统和数据文件的完整性
4. **识别**已知的攻击模式
5. **统计分析**异常行为
6. **对异常行为做出响应**（自动/报警）

### 2.3 IDS 的作用

- 检测出安全系统的**入侵行为或异常现象**
- 监控网络、系统中的操作
- 对入侵事件**自动响应**
- 审计跟踪管理
- 评估关键系统和数据的完整性

## 三、入侵检测模型（理论部分）

### 3.1 Denning 通用入侵检测模型（1987）

最早的、最有影响力的入侵检测模型。六个组件：

| 组件 | 作用 |
|------|------|
| **主体（Subject）** | 活动的发起者，通常指用户 |
| **对象（Object）** | 资源实体，如文件、命令、设备等 |
| **审计记录（Audit Record）** | 记录主体对对象的操作：<主体, 动作, 对象, 异常条件, 资源使用, 时间戳> |
| **活动档案（Profile）** | 保存主体活动的正常行为特征，用于检测异常 |
| **异常记录（Anomaly Record）** | 记录检测到的异常情况 |
| **活动规则（Activity Rule）** | 判断动作是否异常，更新档案，输出报警 |

> Denning 模型的核心思想：建立用户/系统的"正常行为基线"，偏离基线就是异常。

### 3.2 IDM 层次化模型

将入侵检测分为**两个层次**：

| 层次 | 功能 |
|------|------|
| **安全审计（下层）** | 采集审计事件 → 数据预处理 → 安全审计分析 → 报警信号 |
| **安全管理（上层）** | 进行安全功能管理（选择性配置审计方法和信息等） |

### 3.3 SNMP-IDSM 管理式模型

将入侵检测引入**网络管理**体系：

- MIB（Management Information Base）：存放信息库
- Agent：收集审计数据，执行入侵分析
- Manager：接收数据，配置审计策略
- 分为**积极**和**消极**两种处理方式

### 3.4 CIDF 通用架构（重点）

**CIDF**（Common Intrusion Detection Framework）定义了 IDS 的四大组件：

| 组件 | 功能 | 类比 |
|------|------|------|
| **事件产生器（E-box）** | 从网络/系统中采集事件数据 | 监控摄像头 |
| **事件分析器（A-box）** | 分析数据，判断是否入侵 | 视频分析员 |
| **响应单元（R-box）** | 对入侵做出响应（报警/阻断） | 保安队 |
| **事件数据库（D-box）** | 存储中间数据和最终数据 | 录像存储 |

## 四、入侵检测技术分类

### 4.1 两大检测范式

| | 异常检测（Anomaly Detection） | 特征检测（Misuse/Signature Detection） |
|--|------|------|
| **原理** | 建立正常行为模型，偏离模型 = 入侵 | 建立攻击特征库，匹配特征 = 入侵 |
| **优点** | 能检测未知攻击 | 误报率低，速度快 |
| **缺点** | 误报率高，需要训练 | 无法检测未知攻击（零日） |
| **别名** | 基于行为/统计 | 基于知识/规则/签名 |

### 4.2 异常检测的具体技术

| 技术 | 原理 | 特点 |
|------|------|------|
| **统计异常检测** | 收集用户/系统正常活动的统计数据，建立统计模型 | 量化度量、独立于系统 |
| **HMM（隐马尔可夫模型）** | 建立正常系统调用序列的概率模型 | 适合序列分析 |
| **神经网络** | 学习正常行为模式，自动分类异常 | 自学习能力强，适合大数据 |
| **免疫系统方法** | 模拟生物免疫：自我/非我识别 | 新颖但计算量大 |
| **遗传算法** | 用遗传进化方法搜索最优检测规则 | 适合规则优化 |
| **SVM（支持向量机）** | 找到最优分割超平面，区分正常/异常 | 小样本效果好 |

### 4.3 特征检测的具体技术

| 技术 | 原理 | 特点 |
|------|------|------|
| **专家系统** | 将安全专家的知识编码为 if-then 规则 | 成熟但维护难 |
| **攻击签名** | 将攻击表示为特定签名/模式 | 快速匹配 |
| **模式匹配** | 在网络流量中搜索特定字节序列 | 精确但数据库需持续更新 |
| **状态转换分析** | 将攻击建模为状态机（初始→中间→入侵） | 可视化攻击过程 |

> 状态转换分析（STAT）很直观：把攻击过程画成从"正常状态"到"被入侵状态"的路径图，每一步对应一个系统事件。

## 五、IDS 的分类（按数据来源）

### 5.1 主机入侵检测系统（HIDS）

- **数据来源**：主机上的系统日志、应用日志、文件变化
- **两种检测方法**：
  - **网络连接检测**：检测主机的异常网络连接
  - **主机文件检测**：监控关键系统文件的变化

| 优点 | 缺点 |
|------|------|
| 可以精确判断入侵是否成功 | 依赖主机 OS，不同系统需不同版本 |
| 可以监控加密后的流量（主机上已解密） | 可能被攻击者禁用 |
| 不需要额外硬件 | 占用主机资源 |
| 能关联到具体用户 | 无法检测网络层攻击 |

### 5.2 网络入侵检测系统（NIDS）

- **数据来源**：网络流量（在交换机/路由器上抓包分析）
- **两种检测方法**：
  - **模式匹配**：比对已知攻击特征
  - **协议分析**：按协议标准解析数据包，检查违规

| 优点 | 缺点 |
|------|------|
| 实时检测网络流量 | 无法检测加密流量 |
| 对网络性能影响小 | 高速网络下丢包 |
| 独立于 OS | 无法判断入侵是否成功 |
| 攻击者难以清除痕迹 | 对交换网络需要镜像端口 |

### 5.3 网络节点 IDS（NNIDS）

结合 HIDS 和 NIDS 的优点：
- 安装在主机上，但只检测该主机相关的网络流量
- 解决了 NIDS 检测加密流量的问题（在主机上已解密）
- 不检测本机日志（与 HIDS 的区别）

### 5.4 三者对比

| 特性 | HIDS | NIDS | NNIDS |
|------|------|------|-------|
| 数据源 | 主机日志 | 网络流量 | 本机网络流量 |
| 加密检测 | 可以 | 不可以 | 可以 |
| 部署 | 每台主机 | 网络关键节点 | 每台主机 |
| 内部攻击 | 可检测 | 不可检测 | 部分可检测 |

## 六、IDS 性能指标与响应

### 6.1 关键指标

| 指标 | 定义 | 理想值 |
|------|------|--------|
| **误报率（False Positive）** | 把正常行为判定为攻击 | 越低越好 |
| **漏报率（False Negative）** | 攻击行为没检测到 | 越低越好 |
| **检测率** | 检测到的攻击占全部攻击的比例 | 越高越好 |

> **现实困境**：降低误报率往往会增加漏报率，反之亦然。需要在两者之间找平衡。

### 6.2 IDS 响应方式

| 类型 | 方式 | 说明 |
|------|------|------|
| **主动响应** | 自动阻断连接 | 发送 TCP RST 包切断连接 |
| | 防火墙联动 | 通知防火墙添加阻断规则 |
| | 重新配置路由器 | 让可疑数据包进入"蜜罐" |
| **被动响应** | 报警通知 | 向管理员发送邮件/短信 |
| | 日志记录 | 记录详细的攻击信息 |
| | SNMP Trap | 发送网管告警 |

## 七、Snort 实战详解（重要）

### 7.1 什么是 Snort？

Snort 是世界上最流行的**开源 NIDS**，由 Martin Roesch 于 1998 年开发。

三大特点：
- 开源免费
- 轻量级
- 功能强大（能检测多种攻击）

### 7.2 Snort 的三个子系统

| 子系统 | 功能 |
|--------|------|
| **数据包解码器（Packet Decoder）** | 从网卡抓包，解析各层协议头（以太网→IP→TCP/UDP→应用层） |
| **检测引擎（Detection Engine）** | 将数据包与规则库进行匹配 |
| **日志和报警（Logger & Alert）** | 匹配成功后记录日志或发出报警 |

### 7.3 Snort 的三种工作模式

| 模式 | 说明 |
|------|------|
| **嗅探器模式** | 类似 tcpdump，只是抓包并显示 |
| **数据包记录器模式** | 抓包并记录到磁盘 |
| **网络入侵检测模式** | 抓包 + 与规则匹配 + 报警（最常用） |

### 7.4 Snort 规则语法（必考）

一条 Snort 规则分两部分：

```
规则头(Rule Header) + 规则选项(Rule Options)
```

**规则头格式**：
```
动作  协议  源IP  源端口  方向  目的IP  目的端口
```

**示例**：
```
alert tcp any any -> 192.168.1.0/24 80 (content:"attack"; msg:"Web Attack Detected"; sid:1000001;)
```

含义：当任何来源向 192.168.1.0/24 网段的 80 端口发送 TCP 包，且内容包含 "attack" 时，报警并提示 "Web Attack Detected"。

**规则头要素**：

| 要素 | 可选值 | 说明 |
|------|--------|------|
| **动作** | alert, log, pass, activate, dynamic | alert=报警+记录，log=只记录，pass=忽略 |
| **协议** | tcp, udp, icmp, ip | 检测哪种协议 |
| **方向** | `->` 或 `<>` | 单向或双向 |
| **IP/端口** | 具体值或 any | 源和目的地址 |

**常用规则选项**：

| 选项 | 作用 |
|------|------|
| `msg` | 报警消息文本 |
| `content` | 匹配数据包中的特定内容 |
| `flags` | 匹配 TCP 标志位（SYN, ACK, FIN 等） |
| `sid` | 规则唯一标识号 |
| `rev` | 规则版本号 |
| `itype` | ICMP 类型 |
| `icode` | ICMP 代码 |
| `dsize` | 数据包负载大小 |

### 7.5 检测实例

#### 检测 ICMP 大包 Ping（Ping of Death）

```
alert icmp any any -> any any (dsize:>800; msg:"ICMP Large Packet"; sid:1000002;)
```

#### 检测 NMAP TCP SYN 扫描

```
alert tcp any any -> any any (flags:S; msg:"Possible NMAP SYN Scan"; sid:1000003;)
```

#### 检测 NMAP XMAS 扫描

```
alert tcp any any -> any any (flags:FPU; msg:"Possible NMAP XMAS Scan"; sid:1000004;)
```

> XMAS 扫描同时设置 FIN+PSH+URG 标志位，像圣诞树一样"灯全亮了"。

#### 检测 NMAP NULL 扫描

```
alert tcp any any -> any any (flags:0; msg:"Possible NMAP NULL Scan"; sid:1000005;)
```

> NULL 扫描：所有标志位都不设置，像"关灯偷偷摸进来"。

## 八、高级检测技术

### 8.1 神经网络异常检测

两种常用模型：
- **MLP（多层感知器）**：标准前馈神经网络，输入→隐藏层→输出
- **CMAC（小脑模型关节控制器）**：一种联想记忆网络，适合模式分类

工作流程：
1. 收集正常网络流量数据
2. 提取特征（包大小、协议分布、连接频率等）
3. 训练神经网络学习"正常模式"
4. 实时流量偏离正常模式时触发报警

### 8.2 状态转换分析（STAT）

将攻击建模为有限状态机：
- **状态**：系统在某个时刻的安全状况
- **转换**：导致状态变化的事件/动作
- 从**初始状态**经过一系列**中间状态**到达**入侵状态**

优点：直观、可分析复杂多步攻击

## 九、IDS 部署策略

### 9.1 四种典型部署位置

| 位置 | 检测内容 | 说明 |
|------|---------|------|
| **防火墙外部** | Internet 上的所有攻击尝试 | 能看到最多攻击但噪音也最大 |
| **DMZ 区域** | 针对对外服务器的攻击 | 保护 Web/邮件等公开服务 |
| **防火墙内部** | 穿过防火墙的攻击 | 过滤了外部噪音，关注真正威胁 |
| **内部网络** | 内部攻击/异常行为 | 检测内部威胁 |

> **最佳实践**：在多个位置部署，形成纵深检测。就像在小区大门、楼道、家门口都装摄像头。

### 9.2 部署注意事项

- NIDS 需要能**镜像**流量（交换机的 SPAN 端口）
- 高速网络需要考虑**性能瓶颈**（Gbps 级别可能丢包）
- 加密流量要在**终端**或**代理**处检测
- HIDS 和 NIDS **互补部署**效果最好

## 十、商业 IDS 产品

### ISS RealSecure

ISS（Internet Security Systems）的 RealSecure 是早期知名的商业 IDS。

组件：
- **Network Sensor**：网络引擎（NIDS）
- **Server Sensor**：服务器引擎（HIDS）
- **OS Sensor**：操作系统引擎（主机级）
- **Console**：集中管理控制台

## 十一、快速记忆总结

### 检测技术对比

| | 异常检测 | 特征检测 |
|--|---------|---------|
| 原理 | 偏离正常 = 入侵 | 匹配特征 = 入侵 |
| 能否检测未知攻击 | 能 | 不能 |
| 误报率 | 高 | 低 |
| 漏报率 | 低 | 高（对新攻击） |

### IDS 三大分类

| HIDS | NIDS | NNIDS |
|------|------|-------|
| 查主机日志 | 查网络流量 | 查本机网络流量 |
| 能查加密流量 | 不能查加密流量 | 能查加密流量 |

### CIDF 四大组件

> **E-box**（产生事件）→ **A-box**（分析事件）→ **R-box**（响应）+ **D-box**（存储）

### Snort 规则记忆

> **动作 协议 源IP 源端口 -> 目的IP 目的端口 (选项)**
>
> 常用动作：alert / log / pass
> 常用选项：msg / content / flags / sid

### 关键指标

> **误报** = 冤枉好人 | **漏报** = 放过坏人
