## 一、信息的基本概念与性质

### 1.1 什么是信息？

三位大佬各给了一个定义：

| 人物 | 定义 |
|------|------|
| 香农（信息论创始人） | "信息是用以消除不确定性的东西" |
| 维纳（控制论创始人） | "信息是人们在适应外部世界……同外部世界进行交换的内容的名称" |
| 钟义信（中国学者） | "信息是事物运动的状态与方式，是事物的一种属性" |

### 1.2 信息的八大性质

| 性质 | 通俗理解 |
|------|---------|
| **依附性** | 信息不能脱离载体单独存在，要用"符号"表示，依附于物理介质 |
| **可伪性** | 信息可以伪造（所以需要鉴别和完整性保护） |
| **动态性** | 信息只有及时、新颖才有价值（过期的情报没用） |
| **可处理性** | 内容可识别，形式可转换或变换 |
| **共享性** | 信息可以无限扩散（和物质不同，给别人不会减少自己的） |
| **可传递性** | 在时间和空间上都可以传递 |
| **异步性** | 以存储方式接收，任何时间可使用 |
| **可交换性** | 两个主体间可以交换信息 |

### 1.3 信息的功能

- **基本功能**：维持和强化世界的有序性（动态性）。
- **社会功能**：维系社会生存、促进人类文明进步。
- **网络空间安全的任务**：确保信息功能的正确实现。

## 二、信息与网络空间安全

### 2.1 网络空间安全的基本属性

还是 CIA 三要素：**保密性、完整性、可用性**。

### 2.2 网络空间安全的四大特征

| 特征 | 说明 |
|------|------|
| **系统的安全** | 不是单点的，是整个系统层面的 |
| **动态的安全** | 今天安全不代表明天安全 |
| **无边界的安全** | 网络空间没有物理边界 |
| **非传统的安全** | 不同于传统军事安全 |

### 2.3 网络空间安全的范畴（四层）

1. **信息技术问题** —— 技术系统的安全问题
2. **组织管理问题** —— 人 + 技术系统 + 组织内部环境
3. **社会问题** —— 法制、舆论
4. **国家安全问题** —— 信息战、虚拟空间

## 三、网络空间安全发展五阶段（重点）

这是本章考点密集区，五个阶段一定要记清。

### 阶段 1：通信安全（COMSEC）
- **时间**：20 世纪 40-70 年代
- **核心思想**：通过密码技术解决通信保密，保证数据的保密性和完整性
- **主要关注**：传输过程中的数据保护
- **安全威胁**：搭线窃听、密码学分析
- **安全措施**：加密（如 ENIGMA 转轮密码机）

### 阶段 2：计算机安全（COMPUSEC）
- **时间**：20 世纪 70-90 年代
- **核心思想**：预防、检测和减小计算机系统未授权活动的后果
- **主要关注**：数据处理和存储时的数据保护
- **安全威胁**：非法访问、恶意代码、脆弱口令
- **安全措施**：操作系统的访问控制技术
- **标志事件**：1985 年美国发布 TCSEC（橘皮书），划分 4 等级 7 级别

### 阶段 3：信息系统安全（INFOSEC）
- **时间**：20 世纪 90 年代后
- **核心思想**：综合通信安全和计算机安全，保护"信息"在存储、处理和传输全过程
- **安全威胁**：网络入侵、病毒破坏、信息对抗
- **安全措施**：防火墙、防病毒、漏洞扫描、入侵检测、PKI、VPN 等
- **要求**：满足"等级保护规定"或"分级保护规定"

### 阶段 4：信息安全保障（IA）
- **时间**：21 世纪初，2010 年前
- **核心思想**：从技术扩展到管理，从静态扩展到动态，形成对信息、信息系统乃至业务使命的保障
- **安全威胁**：黑客、恐怖分子、信息战、自然灾难
- **安全措施**：技术安全保障体系 + 安全管理体系 + 人员意识/培训 + 认证认可

### 阶段 5：网络空间安全（CS）
- **时间**：2010 年后至今
- **核心思想**：从传统防御的 IA，发展到"威慑"为主的防御、攻击和情报三位一体
- **三大能力**：
  - 网络防御 Defense（运维）
  - 网络攻击 Offense（威慑）
  - 网络利用 Exploitation（情报）

> **一句话总结演进**：从"管好密码"到"管好系统"到"管好全局"到"攻防一体"。

## 四、安全模型（核心考点）

### 4.1 PDR 模型

由美国 ISS 公司提出，最早体现**主动防御思想**的安全模型。

- **出发点**：任何防护措施都是基于时间的，是可以被攻破的
- **核心**：给出攻防时间表
- **三要素**：
  - **保护（Protection）**：加密、鉴别、访问控制、防火墙、防病毒
  - **检测（Detection）**：入侵检测、漏洞检测、网络扫描
  - **响应（Response）**：应急响应机制

> **缺点**：难于适应网络安全环境的快速变化。

### 4.2 PDRR 模型

PDR 的进化版，增加了**恢复（Restore）**，强调自动故障恢复能力。

四要素：保护 → 检测 → 反应 → 恢复

### 4.3 PPDR 模型（重点中的重点）

在 PDR 基础上增加了**策略（Policy）**作为核心。

**四要素**：

| 要素 | 说明 |
|------|------|
| **Policy（策略）** | 模型的核心，所有防护/检测/响应都依据安全策略实施 |
| **Protection（防护）** | 访问控制、防火墙、加密、身份鉴别等 |
| **Detection（检测）** | 实时监控、检测、报警，使防护从被动演进到主动 |
| **Response（响应）** | 关闭服务、跟踪、反击、消除影响 |

**PPDR 的数学法则（必考）**：

设系统 S 的时间关系如下：
- **Pt** = 防护时间（有效防御攻击的时间）
- **Dt** = 检测时间（发起攻击到检测到的时间）
- **Rt** = 反应时间（检测到攻击到处理完成的时间）
- **Et** = 暴露时间

> **如果 Pt > Dt + Rt，那么 S 是安全的**
>
> **如果 Pt < Dt + Rt，那么 Et = (Dt + Rt) - Pt**

通俗理解：你的防线能扛的时间，要超过"发现敌人 + 消灭敌人"的总时间，系统才安全。

**PDR vs PPDR 的区别**：
- PDR 强调落实反应
- PPDR 更强调**控制和对抗**，强调系统安全的动态性
- PPDR 以安全检测、漏洞监测和自适应填充"安全间隙"为循环
- PPDR 特别考虑**人为的管理因素**

### 4.4 IATF 深度防御模型（重点）

**IATF**（Information Assurance Technical Framework，信息保障技术框架）由美国 NSA 制定。

核心理念：**深度防御（Defense-in-Depth）**

#### 三个核心要素

| 要素 | 说明 |
|------|------|
| **人（People）** | 第一位的要素，也是最脆弱的。包括意识培训、组织管理、技术管理、操作管理 |
| **技术（Technology）** | 实现信息保障的重要手段。动态技术体系：防护、检测、响应、恢复 |
| **操作（Operation）** | 构成主动防御体系。包括风险评估、安全监控、安全审计、入侵检测、响应恢复 |

#### 四个技术焦点领域（"三保护一支撑"）

| 领域 | 目标 | 主要方法 |
|------|------|---------|
| **本地计算环境** | 确保数据在客户机/服务器上的 CIA | 安全 OS、主机 IDS、防病毒、脆弱性扫描 |
| **区域边界** | 对进出区域的数据流进行控制与监视 | 防火墙、入侵检测、病毒防御、远程访问安全 |
| **网络和基础设施** | 防数据泄露、拒绝服务、传输异常 | 骨干网可用性、无线安全、VPN |
| **支撑性基础设施** | 为安全服务提供基础 | 密钥管理、证书管理、入侵检测、审计 |

> **课堂练习答案**：关于 IATF，选项 D（"IATF 强调的是以安全检测、漏洞监测和自适应填充安全间隙为循环"）是**错误的**——那是 PPDR 模型的特点，不是 IATF 的。

## 五、信息系统安全保障模型

### 5.1 信息系统安全保障的定义

在信息系统的**整个生命周期**中，从**技术、管理、工程和人员**等方面提出安全保障要求，确保信息系统的保密性、完整性和可用性，降低安全风险到可接受的程度，从而保障系统实现组织机构的**使命**。

### 5.2 三个维度

国家标准 GB/T 20274.1-2006 给出了信息系统安全保障评估框架，三个维度：

1. **安全特征**：确保机密性、完整性、可用性 → 保护资产 → 保障业务使命
2. **生命周期**：计划组织 → 开发采购 → 实施交互 → 运行维护 → 废弃
3. **保障要素**：技术、工程、管理、人员

### 5.3 四大保障要素

| 要素 | 内容 |
|------|------|
| **技术** | 密码、访问控制、网络安全、漏洞及恶意代码防护等 |
| **工程** | 信息系统安全工程、安全工程能力成熟度模型 |
| **管理** | 安全管理体系、风险管理、应急响应与灾难恢复等 |
| **人员** | 所有员工、信息系统岗位、安全专业人员 |

### 5.4 信息安全 vs 安全保障的区别

| | 信息安全 | 安全保障 |
|--|---------|---------|
| 重点 | 保护、防御 | 保护、检测和响应、攻击后的修复 |
| 目的 | 防止攻击的发生 | 始终保证维持特定水平的可用性、完整性、真实性、机密性和抗抵赖性 |

## 六、国内外网络空间安全保障实践

### 6.1 国外趋势

- 关键基础设施是保障的最核心内容
- **战略**：各国发布网络安全战略
- **组织**：设立网络安全协调机构
- **军事**：成立网络战司令部
- **外交**：信息安全成为国际谈判内容
- **科技**：寻求突破性技术创新

### 6.2 美国网络空间安全

- **四个关键文件**：PDD63（1998）→ 国家计划 V1.0（2000）→ 行政令 13231（2001）→ 保护网际空间的国家战略（2003）
- **CNCI（网络"曼哈顿计划"）**：三道防线 + 十二项提议
  - 第一线：减少漏洞，预防入侵
  - 第二线：增强反间能力，供应链安全
  - 第三线：研发、教育、先进技术
- **十二项提议包括**：可信互联网连接、网络入侵检测/防护、态势感知、网络反间、供应链安全等
- **重点保护对象**：18 项关键基础设施（银行和金融被所有国家列为关键基础设施）
- **组织机构**：网络安全协调官（"网络沙皇"）、DHS、NSA、DOD、FBI、CIA、NIST 等

### 6.3 我国网络空间安全保障

**发展阶段**：

| 时期 | 阶段 | 主要工作 |
|------|------|---------|
| 2001-2002 | 启动 | 国家信息化小组重组；网络与信息安全协调小组成立 |
| 2003-2005 | 逐步展开 | 出台指导政策；召开首次全国信息安全保障会议；发布国家信息安全战略 |
| 2006至今 | 深化落实 | 法律法规、标准化、等级保护和风险评估取得新进展 |

**基本思路**：维护国家利益 → 突出保障重点 → 从法律/管理/技术/人才多方面构建保障体系

**六大保障体系**：
1. 法律法规与政策环境
2. 组织机构及管理体系
3. 技术与产业支撑平台
4. 基础设施
5. 标准与规范
6. 人才培训教育体系

**《国家网络空间安全战略》（2016）** —— 九大战略任务：捍卫主权、维护国家安全、保护关键基础设施、加强网络文化、打击犯罪、完善治理、夯实基础、提升防护能力、强化国际合作

### 6.4 等级保护制度

- 1994 年《计算机信息系统安全保护条例》首次提出
- 2003 年中办发 27 号文明确建立等级保护制度
- 2007 年《信息安全等级保护管理办法》
- 《网络安全法》第 21 条：国家实行网络安全等级保护制度

## 八、应急响应（实战部分）

### 8.1 什么是应急响应？

应急响应（Incident Response）是指一个组织为了应对各种安全事件所做的准备以及事后所采取的措施。

**意义**（两方面）：
- **未雨绸缪**：风险评估、安全计划、安全意识培训、预警
- **亡羊补牢**：事后把损失降到最小（备份、病毒检测、后门清除、系统恢复、追踪取证）

### 8.2 安全事件分类

| 事件类型 | 说明 |
|---------|------|
| 计算机病毒 | 能自我复制的破坏程序 |
| 蠕虫 | 网络蠕虫感染 |
| 木马 | 控制端 + 被控端 |
| 僵尸网络 | 一对多的被控网络 |
| 域名劫持 | DNS 解析到错误地址 |
| 网络仿冒 | 假冒电子交易站点（钓鱼） |
| 网页篡改 | 替换网页内容 |
| 网页挂马 | 网站上插入恶意代码 |
| 拒绝服务 | 使目标停止服务 |
| 后门漏洞 | 留下再次进入的程序 |
| 非授权访问 | 未经许可访问资源 |
| 垃圾邮件 | 未经许可的批量邮件 |

### 8.3 安全事件分级

| 级别 | 名称 | 标准 |
|------|------|------|
| 四级 | 一般 | 未造成业务中断或中断 < 10 分钟，无数据损坏 |
| 三级 | 较大 | 中断 10-30 分钟，无数据损坏 |
| 二级 | 重大 | 中断 30-60 分钟，或数据部分损坏（可通过备份恢复） |
| 一级 | 特别重大 | 中断 > 60 分钟，或数据损坏无法恢复，或重要数据泄露 |

> 特殊时期（重大活动、赛事等）发生的事件**级别上提一级**。

### 8.4 应急响应六阶段流程（重点）

```
准备 → 检测 → 抑制 → 根除 → 恢复 → 跟进
```

| 阶段 | 关键工作 |
|------|---------|
| **准备** | 调研分析、确定目标和范围、制定预案和方案、组建团队、工具准备 |
| **检测** | 确定检测对象和范围、判断是否为安全事件、确定处理方案 |
| **抑制** | 隔离和处理故障系统/区域，限制影响范围，保证业务连续性 |
| **根除** | 确定根除方案，消除安全威胁的根源 |
| **恢复** | 重建系统、数据备份/恢复、安装新 OS、配置基线、上线测试 |
| **跟进** | 吸取教训、审计抑制和根除效果、完善安全计划、发布经验总结 |

### 8.5 常见应急事件处置

#### 勒索病毒处置

1. **了解现状**：文件被加密？无法启动？桌面有勒索信息？
2. **了解发病时间**：文件加密时间、新文件出现时间
3. **了解系统架构**：IP、端口、操作系统、中间件等
4. **确认感染者**：定位被感染主机
5. **处置**：
   - 未感染：关闭 SSH/RDP、改密码、备份隔离、禁止 U 盘
   - 已感染：立即隔离（拔网线）、禁用 U 盘、保留现场

> 勒索病毒攻击特点：无 C2 服务器加密流行、攻击目标转向政企机构、针对关键基础设施、攻击目的多样化、平台化运营。

#### 挖矿木马处置

1. **特征**：CPU/GPU 异常占用过高、有对矿池地址的解析
2. **处置**：断网或 ACL 隔离 → 结束恶意进程 → 提取样本 → 删除木马
3. **防御**：安装杀软、补丁更新、严格口令策略、代码审计

#### DDoS 事件处置

- **SYN Flood**：大量虚假地址的 SYN 请求，使用抗 DDoS 设备
- **ACK Flood**：发送大量 ACK 标志位包，需要抗 D 设备防护
- **ICMP Flood**：大量 ICMP 请求消耗资源
- **UDP Flood**：向未开放端口发送大量 UDP 数据包
- **DNS Flood**：短时间内大量 DNS 请求

> 注意：流量大时，防火墙必须在抗 DDoS 设备后面，否则未净化流量会使防火墙过载。

## 九、课堂练习答案汇总

1. **IATF 哪个说法错误？** —— 选 D。"以安全检测、漏洞监测和自适应填充安全间隙为循环"是 PPDR 的特点，不是 IATF 的。
2. **ISPP 定义了什么？** —— 选 A。某种类型信息系统的与实现无关的一组系统级安全保障要求。
3. **ISST 是从什么角度描述的？** —— 从信息系统安全保障的**建设方（厂商）**角度。

## 十、快速记忆总结

### 安全发展阶段口诀

> 通信 → 计算机 → 信息系统 → 信息保障 → 网络空间

### 安全模型对比

| 模型 | 核心思想 | 要素 |
|------|---------|------|
| PDR | 主动防御，攻防时间表 | 保护、检测、响应 |
| PDRR | 增加恢复能力 | 保护、检测、反应、恢复 |
| PPDR | 策略为核心的动态安全 | 策略、防护、检测、响应 |
| IATF | 深度防御，多层防护 | 人、技术、操作 + 四个焦点领域 |

### PPDR 公式

> **安全条件：Pt > Dt + Rt**
> 暴露时间：Et = (Dt + Rt) - Pt

### 应急响应六步

> **准备 → 检测 → 抑制 → 根除 → 恢复 → 跟进**
