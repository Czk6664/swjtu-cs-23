## 一、防火墙基本概念

### 1.1 定义
> 防火墙是一种**高级访问控制设备**，置于**不同网络安全域之间**，通过安全策略来**控制（允许、拒绝、监视、记录）**进出网络的访问行为。

**关键点：**
- 它是两个安全域之间通信流的**唯一通道**。
- 根据**访问控制规则**（源/目的 IP、协议、端口等）决定放行还是拦截。

> 比喻：小区大门的保安，所有进出都要检查。

### 1.2 为什么需要？（三个原因）
1. **阻止来自不可信网络的攻击**（最重要）。
2. **保护内部信息**不被窃取/篡改/删除。
3. **维护信誉**（尤其银行、证券）。

## 二、防火墙发展历程

| 代 | 技术 | 时间 |
|----|------|------|
| 第一代 | 包过滤（依附路由器）| 20世纪80年代 |
| 第二代 | 电路层防火墙 | 1989（贝尔实验室）|
| 第三代 | 应用层防火墙（代理）| 90年代初 |
| 第四代 | 状态检测（动态包过滤）| 1994（CheckPoint）|
| 第五代 | 自适应代理 | 1998（NAI）|

**执行标准**：GB/T 18019（包过滤）、GB/T 18020（应用级）、GB/T 20281（技术要求和测试评价方法）等。

## 三、防火墙核心技术（四种类型，必考）

| 类型 | 工作层 | 检查什么 | 建连接状态表 | 还原会话 |
|------|--------|---------|:---:|:---:|
| **包过滤** | 网络层 | 只看**报头** | ✗ | ✗ |
| **应用代理** | 应用层 | 只看**数据**（应用层）| ✗ | ✗ |
| **状态检测** | 2~4 层 | 报头 + **连接状态** | ✓ | ✗ |
| **完全内容检测** | 2~7 层 | 报头 + 状态 + **应用层内容** | ✓ | ✓ |

### 3.1 包过滤（Packet Filter）
- **网络层**检查，只看报头：IP、端口、协议类型。
- **优点**：规则简单、处理快、易配置、对用户透明。
- **缺点**：不识别应用层、不维持连接状态、前后报文无关、不能防 IP 欺骗、静态策略可能成漏洞。

### 3.2 应用代理（Application Proxy）
- **应用层**检查，能对应用内容过滤（如禁止 FTP 的 `put`）。
- **优点**：安全性好，所有数据在应用层检查。
- **缺点**：支持应用有限、对用户不透明、性能差。
- **自适应代理**：结合代理的安全性 + 包过滤的高速度。

### 3.3 状态检测（Stateful Inspection）
- **2~4 层**，核心是**建立状态连接表**，把数据当成一个个**会话**跟踪。
- 检查每个包不仅看规则表，还看**是否符合会话当前状态**。
- **优点**：性能高、支持大量应用、内核级实现。
- 克服了包过滤"只看单包、不管状态"的缺点。

### 3.4 完全内容检测（Complete Content Inspection）
- **2~7 层**，**还原应用层协议并分析内容**。
- 能防**混合型安全威胁**，网络层/应用层/会话保护都强。

## 四、防火墙体系结构（必考，重点 DMZ）

| 结构 | 组成 | 特点/弱点 |
|------|------|----------|
| **过滤路由器** | 1 个路由器(ACL) | 唯一通道，但被攻陷难发现、无日志 |
| **双宿主主机** | 1 台双网卡堡垒主机 | 能维护日志，但堡垒主机被入侵则内网全暴露 |
| **被屏蔽主机** | 屏蔽路由器 + 堡垒主机 | 两道屏障，但进入堡垒主机后内网仍受威胁 |
| **被屏蔽子网(DMZ)** | 2 个路由器 + 堡垒主机 + 周边网络 | **最安全**，但成本高、配置复杂 |

### 被屏蔽子网 / DMZ（DeMilitarized Zone，重点）

- 在内外网之间建一个**被隔离的子网（周边网络）**，用**两台路由器**（外部 + 内部）夹起来，堡垒主机放中间。
- **四个部件**：周边网络、外部路由器、内部路由器、堡垒主机。
  - **外部路由器**：第一道屏障，过滤外网对周边/内网的访问。
  - **内部路由器**：第二道屏障，复制外部路由器的内网过滤规则（防失效）。
  - **堡垒主机**：放在周边网络，对外提供 Web/FTP，对内提供代理。

**核心价值**：即使攻击者攻破 DMZ 里的堡垒主机，由于内部路由器隔离，他**无法监听到内部网络信息**。

**企业三区典型部署：**
```
内部网络(可信,私有IP) ── 内部路由器 ── DMZ(Web/FTP/Mail/DNS) ── 外部路由器 ── Internet
```
**典型策略**：外网不能访问内网；内网可按权限访问 Internet；内外用户**只能访问 DMZ 指定服务器的指定服务**。

## 五、防火墙的功能

### 五个基本功能（必背）
1. 过滤进出数据。
2. 管理进出访问行为。
3. 封堵禁止的业务。
4. 记录信息内容和活动（日志）。
5. 网络攻击检测和告警。

### 其他功能
- **NAT（网络地址转换）**、隐藏内部 IP/结构、流量日志审计、连单独网段对外提供 Web/FTP、集中安全管理、**VPN**。
- 扩展功能：防病毒、IP/MAC 绑定、用户认证、带宽管理(QoS)、双机热备（高可用）、负载均衡、与 IDS 联动等。

### NAT 详解
- **作用**：内部私有地址 ↔ 公网地址转换。
- **好处**：隐藏内部结构、内网用私有 IP、解决公网地址不足（IP 复用）。
- **MAP（地址/端口映射）**：把公网地址+端口映射到内部服务器（如 `MAP 199.168.1.2:80 TO 202.102.1.3:80`），让公开服务器用私有地址对外提供服务。

## 六、防火墙接入方式

| 方式 | 相当于 | 特点 |
|------|--------|------|
| **路由接入** | 路由器 | 连接不同网段，要配 IP |
| **透明接入** | 网桥 | 内部主机配置不用改，不用配 IP |
| **混合接入** | 路由+透明 | 大多数防火墙都支持，按需选择 |

## 七、防火墙性能五大指标（必背）

| 指标 | 含义 | 衡量 |
|------|------|------|
| **吞吐量** | 不丢包能达到的最大速率 | 越大越好 |
| **时延** | 输入帧最后1比特到达 → 输出帧第1比特输出的时间 | 越小越好 |
| **丢包率** | 因资源不足该转发却没转发的帧百分比 | 越小越好 |
| **背靠背** | 全速发包出现第一个丢包时发送的帧数 | 体现缓冲能力 |
| **并发连接数** | 穿越防火墙同时建立的最大连接数 | 越大越好 |

## 八、防火墙的局限性（必考）

1. **防外不防内**——难防内部攻击或滥用。
2. 不能防**绕过/未经过防火墙**的攻击（如内部私自拨号上网）。
3. 只实现**粗粒度**访问控制。
4. 难管理配置，易造成漏洞。
5. 基于报头检测，**无法阻断通过开放端口流入的有害流量**（不是蠕虫/黑客攻击的解决方案）。
6. 对 **0day 攻击**无能为力。

> 正因如此，需要 IDS、WAF 来补充。

### 两个争议
- **胖 vs 瘦**：胖=功能大而全（性能降低、自身安全弱）；瘦=功能少而精，靠多厂商联动。趋势是构建**联动统一的动态安全防护体系**。
- **硬件架构**：X86（灵活）、NPU（网络处理器，编程灵活但开发难）、ASIC（专用芯片，千兆线速但缺乏灵活性）。最佳组合：通用 CPU + 可编程 ASIC 各司其职。

## 九、WAF：Web 应用防火墙（必考）

### 9.1 WAF 是什么？
- 专门保护 **Web 应用** 的防火墙。
- 防护：**SQL 注入、XSS、XML 注入、Web DDoS** 等。重点防 SQL 注入，也叫"SQL 防火墙"。
- **本质**：防应用层攻击，技术上更应叫 **Web IPS**。

### 9.2 为什么传统防火墙防不住 Web 攻击？
- 传统防火墙工作在网络层/传输层，**不分析应用层内容**。
- SQL 注入、XSS 藏在**正常的 HTTP/HTTPS 请求**里（80/443 端口本就开放），传统防火墙看不出问题。

### 9.3 部署
- 串行接入在 **Web 服务器前面**，要求高性能，需 HA、Bypass 功能。

### 9.4 检测技术
1. **代理服务**：双向代理，中断直连，能抑制 DDoS。
2. **特征识别**：靠攻击"指纹"（如 SQL 注入的 `1=1`、Shellcode）。缺点：特征库庞大、易误报、对 0day 无效。
3. **算法识别**：对攻击类型归类做模式化，进行**语义理解**（而非"长相"）。
4. **模式匹配**：把攻击归纳成模式匹配（IDS 传统技术）。
5. **自学习技术**：学习正常访问模式，偏离的就预警/阻断（如账号一般无特殊字符、密码一般不超 20 位，SQL 注入会突破这些模式）。

### 9.5 最大挑战：识别率
（漏报和误报的平衡，难以测量）

### 9.6 基于机器学习的 Web 异常检测
- 传统规则集难应对 **0day**。
- 新思路：不识别"入侵行为"，而是建模"**正常流量**(Profile)"，不符合的就是异常——"以不变应万变"，更难绕过。
- 方法：统计学习（参数长度、字符分布、访问频率，用切比雪夫不等式/卡方检验）、文本分析（**HMM 隐马尔科夫模型**）、单分类（**one-class SVM**，如 McPAD 用 N-Gram 向量化）、聚类。

## 十、入侵检测系统 IDS（必考）

### 10.1 IDS 是什么？
- 监控系统/网络，识别**违反安全策略的行为和攻击迹象**。
- 是**防火墙的补充**——防火墙挡门口，IDS 在里面巡逻，发现内部和绕过防火墙的攻击。
- 主要做**检测和告警**（能主动阻断的叫 IPS）。

### 10.2 Denning 模型
入侵检测奠基模型，核心：通过**审计记录**识别异常和攻击。

### 10.3 CIDF 通用框架（四组件）
| 组件 | 作用 |
|------|------|
| 事件产生器 | 采集数据、产生事件 |
| 事件分析器 | 分析、发现攻击 |
| 事件数据库 | 存储事件 |
| 响应单元 | 做出反应 |

### 10.4 异常检测 vs 误用检测（核心对比）

| | 异常检测 | 误用/特征检测 |
|------|---------|--------------|
| 思想 | 建**正常行为模型**，识别偏离 | 匹配**已知攻击特征** |
| 检测未知攻击(0day) | **能** | **不能** |
| 主要缺点 | **误报率高** | 漏报未知、需更新特征库 |

> 记忆：异常检测"你不正常我报警"（能抓新攻击但易误伤）；误用检测"你像通缉犯我抓"（准但只抓已知）。

### 10.5 HIDS vs NIDS（核心对比）

| | HIDS（主机）| NIDS（网络）|
|------|-----------|-----------|
| 部署 | 单台主机上 | 网络节点（监听网段）|
| 特点 | 能映射到具体用户、能看**加密通信解密后**内容；占主机资源 | 监控整个网段，但**看不懂加密通信**内容 |

还有**混合型（分布式）**入侵检测。

### 10.6 Snort
- 著名**开源 NIDS**。
- 通过**规则**检测，**规则由规则头和规则选项组成**。
- 构成：嗅探包、预处理、检测引擎、日志/告警。

## 十一、三类设备对比总结

| 设备 | 位置 | 作用 | 防什么 |
|------|------|------|--------|
| **防火墙** | 网络边界 | 访问控制 | 控制进出流量 |
| **WAF** | Web 服务器前 | 防应用层攻击 | SQL 注入、XSS |
| **IDS** | 网络/主机内部 | 检测告警 | 内部/绕过攻击 |

> 互补关系：防火墙挡门、WAF 护 Web、IDS 巡逻——组合成纵深防御。

## 十二、本章小结

- 防火墙 = 安全域之间的**唯一通道 + 访问控制设备**，五大功能、五大性能指标。
- 四种核心技术：**包过滤(网络层)、应用代理(应用层)、状态检测(2-4层,建状态表)、完全内容检测(2-7层)**。
- 四种结构：过滤路由器 < 双宿主 < 被屏蔽主机 < **被屏蔽子网(DMZ,最安全)**。
- **NAT** 隐藏内部结构 + IP 复用。
- 局限性：**防外不防内**、防不住绕过/0day。
- **WAF** 补防火墙的应用层短板（防 SQL 注入/XSS）。
- **IDS** 补防火墙的内部检测短板：**异常检测 vs 误用检测**、**HIDS vs NIDS**、Snort。
