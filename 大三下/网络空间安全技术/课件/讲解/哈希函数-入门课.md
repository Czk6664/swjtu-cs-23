## 一、一句话理解：哈希 = 把任意内容压成固定长度摘要

> 哈希函数把"**任意长度的内容**"压成"**固定长度的摘要**"。

你可以把摘要看成内容的"**短指纹**"，但它**不是原文本身**。

例子（无论原始内容多长，摘要长度都固定）：
| 输入 | 哈希后（摘要）|
|------|------|
| 文本"你好，哈希函数！" | `50db5f95c8c1…` |
| 图片 photo.png (4.8MB) | `b8a9d0470ea2…` |
| 程序包 lab1.zip (128MB) | `0fd4bb71d8e6…` |
| 学号 2025112345 | `17ee8d6ac5ad…` |

日常说的"哈希值""摘要""digest"，就是这串短结果。

---

## 二、别和"加密""编码"混淆（重点）

这三个概念最容易搞混，一定要分清：

| | 哈希 | 加密 | 编码 |
|------|------|------|------|
| 输入→输出 | 原文 → 摘要 | 原文 → 密文 | 数据 → 另一种表示 |
| 可逆性 | **通常不可逆** | 有密钥可逆 | **完全可还原** |
| 目的 | **校验 / 索引** | **保密** | 表示转换 |
| 例子 | SHA-256 | AES、RSA | Base64、UTF-8 |

**最常见的误解**：想把内容"藏起来"时去用哈希。
**正确做法**：
- 需要**保密** → 用**加密**。
- 需要**验证内容** → 用**哈希**。
- 只是换个表示 → 用编码。

## 三、好哈希函数的 5 个特性（必记）

| # | 特性 | 说明 |
|---|------|------|
| 1 | **任意长度输入** | 一篇论文和一串学号都能哈希 |
| 2 | **固定长度输出** | 如 SHA-256 始终输出 256 位 |
| 3 | **确定性**（同样输入→同样输出）| 否则无法比较或定位 |
| 4 | **雪崩效应**（输入改一点→摘要大变）| 便于发现篡改 |
| 5 | **难逆推 / 难碰撞** | 安全场景必需 |

**雪崩效应例子：**
```
OpenAI-2025 → d7fa28287222217a…
OpenAI-2026 → 2b10233e76f1f365…
```
只改了一个字符，摘要却完全不同。

## 四、哈希的 4 大用途

### 用途 1：完整性校验（最常见）
检查"内容有没有变"：
1. 发布方公布：文件 + 摘要（如 SHA-256）。
2. 接收方下载后对同一文件再算一次哈希。
3. 两边摘要**一致 → 没变**；**不一致 → 损坏或被篡改**。

> 下载软件时常看到的 SHA-256 校验值就是干这个的。哈希负责"**验有没有变**"，不是"把原文藏起来"。

### 用途 2：密码存储（重点）
服务器**不该保存明文密码**！正确姿势：

```
用户密码 + 随机salt → Argon2id（或 bcrypt/scrypt）→ hash
数据库只保存：salt + hash（不是明文）
```

**登录验证**：用户重新输密码 → 取出该用户的 salt → 用同样算法再算一次 → **只比较 hash 是否一致**。

**别这么做：**
- ✗ 存明文密码。
- ✗ 只用普通快速哈希（如直接 MD5）存密码。

**推荐**：Argon2id（带盐的慢哈希/自适应哈希）；没有时再考虑 bcrypt/scrypt。

> **为什么要"慢哈希" + "加盐"？** 慢哈希让暴力破解变慢；加盐让攻击者无法用预先算好的"彩虹表"批量破解。

### 用途 3：哈希表（数据结构）
- 哈希函数把 key 映射到数组**槽位**，让"找东西"变快。
- 例：`hash(学号2025112345) → 槽位3 → 张三记录`。
- **碰撞**：两个 key 落到同一槽位，需用**拉链法、开放寻址**等处理。
- 平均情况查找很快；坏情况（碰撞多）会变慢。

### 用途 4：安全系统的底层积木
- **数字签名**：先对长消息取哈希，再对**摘要**签名（更快、适合大文件）。
- **Git / 内容寻址**：对象内容一变，哈希名就变，能精确定位对象。
- **Merkle 树 / 区块链**：底层任一叶子改动，整条向上的哈希都变化，便于整体校验。
- 共同点：**先压缩，再验证 / 定位 / 链接**。

## 五、哈希的边界与风险（常见误区）

| 误区 | 纠正 |
|------|------|
| "哈希 = 加密" | 哈希**通常不可逆**，做摘要与验证；要保密用加密 |
| "摘要相同绝不可能" | 输出空间有限，**碰撞理论上必然存在**；目标是"**极难找到**" |
| "任何 hash 都适合安全场景" | **SHA-1 已不安全**别再用于抗碰撞场景；密码存储别用普通快速哈希 |

> **碰撞**不是"绝不可能"，而是"应该在现实中极难构造"。

## 六、带走这 5 句话

1. 哈希函数把**任意长度输入**压成**固定长度摘要**。
2. 同样输入得同样输出；**改一点，摘要大变**（雪崩）。
3. 验**文件完整性**，优先想到 **SHA-256** 这类安全哈希。
4. 存**密码**，要用**带盐的 Argon2id / bcrypt / scrypt**，而不是明文或普通快速哈希。
5. 想**保密**用**加密**；想**快速按 key 查找**想到**哈希表**。

**场景 → 首选思路：**
| 场景 | 首选 |
|------|------|
| 文件有没有变 | SHA-256 等安全哈希 |
| 密码怎么存 | Argon2id / bcrypt / scrypt |
| 字典/索引怎么快查 | 哈希表 |
| 内容要保密 | 加密（不是哈希）|

> 一句话收尾：**哈希函数是计算机世界里的"短指纹"——擅长校验、索引和链接结构，但不负责替代加密。**

## 七、与课程的关联

- 哈希是 **CH4 数据完整性机制** 的核心（消息摘要）。
- 哈希是 **CH4/CH5 数字签名** 的基础（先哈希再签名）。
