Spark的设计动机：MapReduce到Spark
4
Hadoop MapReduce 推动了离线大数据处理，但它的执行模型偏“批处理+磁盘中转”
• 对日志清洗这类单次扫描任务，MapReduce 够用
• 对机器学习、交互式查询、图计算等迭代优化任务，中间结果反复落盘会非常慢
 Spark 核心思想
• 尽量把中间结果保留在内存，减少磁盘I/O
• DAG执行引擎
• 统一批处理与流处理

Spark：DAG 执行引擎
6
p Spark 把一连串Transformation 看成一个有向无环图（DAG）
p 节点是数据集/计算结果
p 边表示依赖关系
p 执行流程：
1. 先有逻辑DAG
2. 再拆成物理执行Stage
p 依据Shuffle 边界，把DAG 切成多个Stage
p Stage 内部尽量流水执行
p 好处：系统可以观察全局依赖，不只盯着单个Map 或Reduce

Spark 运行架构
8
p Spark 运行架构包括：
p 集群资源管理器(Cluster Manager)
p 运行作业任务的工作节点(Worker Node)
p 每个应用的任务控制节点(Driver)
p 每个工作节点上负责具体任务的执行进程(Executor)
p 与Hadoop MapReduce 相比，Spark 所采用的Executor 有两个优点：
p 利用多线程来执行具体的任务，减少任务的启动开销。
p Executor 中有一个BlockManager 存储模块，会将内存和磁盘共同作为存储设备，有效减少IO 开销。

Executor的工作模式：长期驻留
12
pExecutor 是运行在工作节点上的进程
p负责接收Driver 下发的Task 并实际执行
p管理本地 Cache 与 Shuffle 数据。
p长期驻留的优势：
p如果每个小任务都创建/销毁一次进程，分布式调度开销会很大
p长期驻留Executor，而不是每个任务临时起进程，可以减少频繁启动进程的开销。

Dependency
Dependency：
pRDD 之间通过 Dependency 连接

p窄依赖： 子分区只依赖少量父分区，适合流水执行，如 map、filter

1  from pyspark.sql import SparkSession
 2  
 3  spark = SparkSession.builder \
 4  
.appName("RDDWordCount") \

.master("local[*]") \

.getOrCreate()

 8  sc = spark.sparkContext

from pyspark.sql import SparkSession
from pyspark.sql.functions import explode, split
spark = SparkSession.builder.appName("StructuredStreamingWC").getOrCreate()
lines = (spark.readStream
.format("socket")
.option("host", "localhost")
.option("port", 9999)
.load())
words = lines.select(explode(split(lines.value, " ")).alias("word"))
counts = words.groupBy("word").count()
query = (counts.writeStream
.outputMode("complete")
.format("console")
.option("checkpointLocation", "chk/wc")
.start())
query.awaitTermination()
• readStream 建立流式数据源。
• select / groupBy / count 与批处理写法相似
• writeStream 指定输出模式和Sink。
• checkpointLocation 用于故障恢复。
Structured Streaming 的优势是用类似批处
理的API 处理无界数据流。
