云计算的处理对象：大数据
什么是大数据
海量数据或巨量数据，其规模巨大到无法通过目前主流的计算机系
统在合理时间内获取、存储、管理、处理并提炼以帮助使用者决策。
大数据4V+1C特征
Volume (数据量大)：PB/EB 级别成为常态 。
Velocity (快速)：数据产生与处理要求极速响应 。
Variety (多样)：结构化、半结构化、非结构化混合 。
Value (价值密度低)：需从海量沙砾中淘金 。
Complexity (复杂度高)：分析难度呈指数上升

云计算的定义
根据NIST (美国国家标准与技术研究院) 定义：
云计算是一种计算模型，允许无处不在的、便捷的、按需的网络访问
具备共享的可配置计算资源池（包括网络、服务器、存储、应用和服务）
资源能够用最小的管理代价或服务提供商的交互实现快速配置和发布
“Cloud computing is a model for enabling convenient, on-
demand network access to a shared pool of configurable 
computing resources (e.g., networks, servers, storage, 
applications, and services) that can be rapidly provisioned 
and released with minimal management effort or service 
provider interaction. ”

云核心技术栈：计算
云怎么把一台物理机切分给多个用户？
虚拟化技术 (Virtualization)
 通过 Hypervisor 层，将一台物理机分成多台拥有独立操作系统的虚拟机 
隔离性极强，安全性高，但相对笨重（每个VM都要跑完整的OS）
容器技术 (Containers - 如 Docker)
多个容器共享同一个宿主机的操作系统内核，只隔离应用及其依赖库
极致轻量、启动达到秒级/毫秒级，现代云原生架构的基石

云核心技术栈：存储
云计算怎么存储庞杂数据？
分布式存储 (Distributed Storage)
将海量数据分散存储在多台服务器节点上，通过网络将其组合成一个巨大的逻
辑磁盘
极高的吞吐量和容错率（多副本机制）
对象存储 (Object Storage)
Amazon S3 / 阿里云 OSS
抛弃了传统文件系统的目录树结构，采用扁平化命名空间。数据和元数据打包
成一个对象，通过唯一的 URL (API) 进行访问。
容量几乎无限扩展，适合存储非结构化数据（图片、视频、备份文件）

发展趋势：云计算与高性能计算（HPC）融合
高性能计算(HPC, High-Performance Computing)：
超强算力：利用超级计算机或计算集群来解决极其复杂的计算问题
节点通过低延迟网络连接而成
例如，模拟天气变化，它会把大气层切成无数小方块，每个核心算一个方块
为什么云计算和HPC需要融合？
算力需求爆发：AI 大模型（如 ChatGPT）的训练爆发
现代 AI 训练既需要 HPC 级别的超强算力与极低延迟网络，又需要云计算的
海量存储、极速弹性和随用随停的商业模式

云计算弹性算力优势：串行与并行对比
matrix_multiply_chunk(args) : 计算一个分块的矩阵乘法（供进程池调用） 
serial_multiply(A, B)` 串行计算整个矩阵乘法 
parallel_multiply(A, B, num_workers): 并行计算，将矩阵按行分块分配给多个进程
np.vstack(args)：将数据（矩阵块）垂直拼接
def parallel_multiply(A, B, num_workers):
# 1. 将大型矩阵拆解为 num_workers 个独立的子块
  chunks = np.array_split(A, num_workers)
# 2. 模拟调用云端 API，横向拉起 num_workers 个计算实例
  with multiprocessing.get_context('fork').Pool(processes=num_) as pool:
# 3. 将任务分发给各个实例并行计算workers
    results = pool.map(matrix_multiply_chunk, [(chunk, B) for chunk in chunks])
return np.vstack(results)

算力弹性的物理极限：阿姆达尔定律
阿姆达尔定律 (Amdahl's Law)
加速比受限于程序中串行部分的比例。即使无限增加处理器数量，加速比也有
上限 S_max = 1 / f（f 为串行比例）
加速比=优化后的性能/未优化的系统性能
