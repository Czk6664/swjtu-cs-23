**2) 采用存储程序工作方式**

这是冯·诺依曼体系结构的**核心思想之一**——“存储程序”概念。其含义是：**程序和数据一样，都可以被存储在计算机的存储器中，并由计算机自动执行。**

#### 内容解析：

1. a、事先编制程序
   - 意思是：用户需要先编写好程序（即一系列指令），这是计算任务的逻辑步骤。
   - 手写标注：“写” → 强调“编写”这个动作。
2. b、将程序存储于计算机的存储器之中
   - 程序不是直接运行，而是先加载到内存（存储器）中。
   - 手写标注：“存” → 强调“存储”这个过程。
   - 这一点非常重要：程序和数据一样都以二进制形式存在存储器中，实现了“程序可修改、可重用”。
3. c、计算机在运行时将自动地连续地从存储器中依次取出指令加以执行
   - 计算机启动后，控制器会自动从存储器中按顺序读取指令，然后交给运算器执行。
   - 手写圈出“运行时” → 强调“自动执行”的过程。
   - “依次取出指令”体现了程序的**顺序执行特性**（虽然现代计算机有跳转、分支等机制，但基础仍是顺序执行）。

✅ 总结：这三点共同构成了“**存储程序工作方式**”，是现代计算机工作的基本原理。

> 🌟 关键词：**编程序 → 存储 → 自动执行**

## 一、原码（Sign-Magnitude）

### 定义：

- **最高位为符号位**：0 表示正数，1 表示负数。
- 其余位表示数值的绝对值（真值）。

### 示例（8位）：

- +5 → `0000 0101`
- -5 → `1000 0101`

### 范围（n位）：

- 正数：0 到 2^{n-1} - 1
- 负数：-0 到 -(2^{n-1} - 1)
- **存在 +0 和 -0 两个零**（如 0000 0000 和 1000 0000）

### 缺点：

- 加减法复杂（需判断符号）
- 零不唯一

------

## 二、反码（Ones' Complement）

### 定义：

- 正数：与原码相同。
- 负数：符号位为1，数值位按位取反。

### 示例（8位）：

- +5 → `0000 0101`
- -5 → `1111 1010`（对 0000 0101 取反，符号位保持1）

### 范围（n位）：

- 同原码：- (2^{n-1} - 1) 到 + (2^{n-1} - 1)
- **仍有 +0（000...0）和 -0（111...1）**

### 运算特点：

- 减法可转为加法，但需“循环进位”（end-around carry）
- 仍不理想，现代计算机不用

------

## 三、补码（Two's Complement）✅（主流表示法）

### 定义：

- 正数：与原码相同。
- 负数：反码 + 1

### 示例（8位）：

- +5 → `0000 0101`
- -5 →
  原码：1000 0101 →
  反码：1111 1010 →
  补码：1111 1011

> 快速求法：从右往左，保留第一个1及右边所有位，其余取反。

### 范围（n位）：

- **-2^{n-1} 到 + (2^{n-1} - 1)**
- 8位：-128 到 +127
- 16位：-32768 到 +32767

✅ **优点**：

- 零唯一（000...0）
- 加减法统一（无需区分符号）
- 硬件实现简单

### 补码运算规则：

- 直接相加，忽略最高位进位（模 2^n 运算）
- 例：8位下，127 + 1 = -128（溢出）

------

## 四、溢出（Overflow）

### 何时发生？

- 当运算结果超出表示范围时。

### 判断方法（补码加法）：

1. 符号位进位法

   ：

   - 若符号位进位 ≠ 最高位数值位进位 → 溢出

2. 结果符号异常

   ：

   - 正 + 正 = 负 → 溢出
   - 负 + 负 = 正 → 溢出

### 示例（8位补码）：

- 127 + 1 = 128 → 实际结果为 `1000 0000` = -128（溢出！）
- (-64) + (-65) = -129 → 超出 -128，结果为 127（溢出）

> 注意：**进位 ≠ 溢出**！无符号数看进位，有符号数看溢出。

------

## 五、BCD码（Binary-Coded Decimal）

### 定义：

- 用 **4位二进制** 表示 **1位十进制数字（0～9）**
- 每4位只能是 0000 ～ 1001（即0～9），1010～1111 无效

### 示例：

- 十进制 25 → BCD: `0010 0101`
- 十进制 9 → BCD: `1001`

### 类型：

#### 1. **非压缩BCD码（Unpacked BCD）**

- 每个十进制数字占一个字节（8位），高4位为0
- 例：25 → `0000 0010` `0000 0101`

#### 2. **压缩BCD码（Packed BCD）** ✅

- 两个十进制数字压缩在一个字节中
- 高4位：十位；低4位：个位
- 例：25 → `0010 0101`（1字节）
- 优点：节省存储空间

### BCD码运算（以压缩BCD为例）：

- **不能直接用二进制加法**！需调整
- 规则：
  - 若低4位 > 9 或 有低4位进位 → +6 调整
  - 若高4位 > 9 或 有高4位进位 → +60H（即高4位+6）

#### 示例：25 + 38 = 63

text

编辑







```
1  0010 0101  (25)
2+ 0011 1000  (38)
3------------
4  0101 1101  → 低4位=1101(13)>9 → +6
5+       0110
6------------
7  0110 0011  = 63 ✓
```

> CPU通常提供 **DAA（Decimal Adjust after Addition）** 指令自动调整

  - **控制字符（0～31, 127）**：不可打印（如换行LF=10, 回车CR=13）

### 一、CPU 的功能（1.1）

这部分介绍了 CPU 的四大核心功能：

#### ✅ 1. 指令控制

- **作用**：保证机器按程序规定的顺序取出并执行指令。
- **关键词**：“取指”、“顺序执行”。
- 这是程序执行的基础，由控制器负责。

> 📌 注意：图中“执行**某**”可能是笔误，应为“执行**指令**”。

#### ✅ 2. 操作控制

- **作用**：CPU 根据每条指令生成对应的操作信号，并发送给相关部件，使其按指令要求工作。
- 实质上是“指挥”各个硬件单元协同工作的过程。

#### ✅ 3. 时间控制

- **作用**：对各种操作的时间进行定时，确保各部件在正确的时间点完成任务。
- 例如：取指阶段、译码阶段、执行阶段等都有严格时序控制。

#### ✅ 4. 数据加工

- **作用**：对数据进行算术运算（如加减乘除）和逻辑运算（如与、或、非、比较等）。
- 主要由 **ALU（算术逻辑单元）** 完成。

### 二、CPU 的基本组成（1.2）

#### 🔹 历史构成：

- 早期 CPU 主要由两大部分组成：
  - **运算器**（Arithmetic Logic Unit, ALU）
  - **控制器**（Control Unit）
- 随着集成电路发展，现代 CPU 芯片还集成了其他组件，如：
  - **Cache（高速缓存）**：解决 CPU 和主存速度不匹配的问题，提高访问效率。

#### 🔹 运算器（ALU）的作用：

- 执行所有算术运算（如 +、−、×、÷）
- 执行所有逻辑运算（如 AND、OR、NOT、比较）
- 是“数据加工”的核心部件

#### 🔹 控制器的作用：

- 协调整个计算机系统的运行，相当于“大脑”。
- 具体职责包括：
  1. **从内存中取出一条指令**，并指出下一条指令的位置（通过 PC 程序计数器实现）
  2. **对指令进行译码**，产生相应的操作控制信号，送往相应部件
  3. **指挥 CPU、内存、I/O 设备之间的数据流动方向**

### 三、CPU 的基本模型（结构图解析）

这是一个典型的 CPU 内部结构示意图，包含多个寄存器和功能模块。我们来逐个分析：

#### 🧱 主要组成部分：

| 名称                        | 英文缩写 | 功能                                                         |
| --------------------------- | -------- | ------------------------------------------------------------ |
| **程序计数器**              | PC       | 存储下一条要执行指令的地址；自动递增以支持顺序执行           |
| **地址寄存器**              | AR       | 临时存放由 PC 提供的地址，用于访问存储器                     |
| **数据缓冲寄存器**          | DR       | 暂存从内存读出或写入的数据/指令                              |
| **指令寄存器**              | IR       | 保存当前正在执行的那条指令                                   |
| **累加器**                  | AC       | 通用寄存器，常用于存放中间结果（尤其在算术运算中）           |
| **状态条件寄存器**          | PSW      | 存储运算结果的状态标志（如零标志 ZF、进位标志 CF 等），供分支判断使用 |
| **算术逻辑单元**            | ALU      | 执行所有算术和逻辑运算                                       |
| **指令译码器**              | —        | 将 IR 中的指令翻译成控制信号                                 |
| **操作控制器 & 时序产生器** | —        | 根据译码结果生成具体控制信号，并按照时钟节拍发出控制脉冲     |

#### 🔁 数据流与控制流说明：

1. **取指阶段**：
   - PC → AR（把指令地址送入地址寄存器）
   - AR → ABUS（地址总线）
   - 存储器 → DR（读取指令）
   - DR → IR（指令进入指令寄存器）
2. **译码阶段**：
   - IR → 指令译码器 → 生成控制信号
3. **执行阶段**：
   - 控制信号驱动 ALU、DR、AC 等部件完成运算
   - 结果可能写回 DR 或存储器
4. **时钟同步**：
   - 时钟信号控制整个 CPU 的节奏，确保每个步骤按时发生
5. **反馈机制**：
   - ALU 的运算结果会反馈到 PSW（如设置标志位），影响后续判断（如条件跳转）

#### ✅ Cache（高速缓存）

- 位于 CPU 和主存之间
- 速度快、容量小，用来缓存频繁访问的数据和指令
- 缓解“CPU 快、主存慢”的矛盾

#### ✅ 寄存器的作用

- 所有寄存器都是“临时存储单元”，但比内存快得多
- 关键寄存器：
  - **PC**：决定程序执行顺序
  - **IR**：当前指令
  - **DR**：数据中转站
  - **AR**：地址中转站
  - **AC**：计算用的“工作台”
  - **PSW**：记录运算状态

#### ✅ 控制器的核心流程

#### 3. 读写控制引脚

| 引脚                                                         | 功能             | 有效电平     |
| ------------------------------------------------------------ | ---------------- | ------------ |
| **ALE** (Address Latch Enable)                               | 地址锁存允许信号 | 高电平有效 ✅ |
| - 当 ALE 为高时，将 AD₀～AD₁₅ 上的地址信息锁存到外部地址锁存器中，实现地址分离 |                  |              |

| **IO/M\*** | I/O 或存储器访问选择 | 输出、三态 | | - 高电平 → 访问 I/O 端口（提供 16 位 I/O 地址） | | - 低电平 → 访问内存（提供 20 位存储器地址） |

| **WR\*** (Write) | 写控制信号 | 低电平有效 ✅ | | - 有效时，CPU 向存储器或 I/O 写入数据 |

| **RD\*** (Read) | 读控制信号 | 低电平有效 ✅ | | - 有效时，CPU 从存储器或 I/O 读取数据 |

| **DEN\*** (Data Enable) | 数据允许信号 | 低电平有效 ✅ | | - 表示数据总线上正在传送数据 |

| **DT/R\*** (Data Transmit/Receive) | 数据发送/接收方向控制 | | - 高电平 → 数据由 CPU 发出（发送） | | - 低电平 → 数据输入 CPU（接收） |

------

#### 4. 总线请求与响应信号

| 引脚                        | 功能                                            |
| --------------------------- | ----------------------------------------------- |
| **HOLD** (Hold Request)     | 外部设备（如 DMA 控制器）请求使用系统总线的信号 |
| **HLDA** (Hold Acknowledge) | CPU 响应 HOLD 请求，表示同意释放总线            |

> 🔁 工作流程：
>
> - 外设发 HOLD → CPU 检测到后，在完成当前操作后发出 HLDA → 放弃总线控制权 → 外设接管总线

------

#### 5. READY 信号（准备就绪）

- **功能**：用于解决 CPU 与慢速外设之间的速度匹配问题。

- 工作方式

  ：

  - 若 READY = 1 → 设备已准备好，正常执行数据传输。
  - 若 READY = 0 → 插入等待状态 TW，直到 READY 变为 1。

- ✅ 实现了异步通信中的“等待机制”。

## 🔍 二、逐图解析

### ✅ 图1：中断请求和响应信号（续1）

#### ➤ NMI（非屏蔽中断请求）

- **引脚号：17**

- **类型：输入，上升沿触发**

- 特点

  ：

  - 不受中断允许标志 IF 控制
  - 只要电平由低变高（正跳变），CPU 就会在当前指令周期结束后响应
  - 常用于处理紧急事件（如电源故障、硬件错误等）

- ✅ 用途：不可被软件屏蔽，优先级最高

#### ➤ INTR（可屏蔽中断请求）

- **引脚号：18**

- **类型：输入，高电平有效**

- 条件响应

  ：

  - INTR = 1 且 IF = 1（中断允许位为1）
  - CPU 在每个指令周期最后一个 T 状态检测该信号
  - 满足条件则在当前指令执行完后响应中断

- ✅ 用途：外部设备（如键盘、打印机）发出的数据就绪通知

#### ➤ INTA（中断响应信号）

- **引脚号：24**

- **类型：输出，低电平有效**

- 功能

  ：

  - 当 CPU 响应 INTR 中断时，会发出两个负脉冲（INTA*）
  - 第一个脉冲：通知外设“我收到你的中断请求”
  - 第二个脉冲：要求外设将中断类型码送入数据总线

- ✅ 目的：获取中断向量号（中断服务程序入口地址）

> 💡 补充知识：
>  8086 支持最多 256 种中断（0～255），每种对应一个中断服务程序。

### 📌 一、8086/8088 CPU 工作模式

#### 1. 工作模式由硬件决定

> “8086 / 8088 的工作模式完全是由硬件决定的。”

- 这意味着通过外部电路（如引脚信号）配置 CPU 是运行在“最小模式”还是“最大模式”，而不是软件控制。
- 目的是适应不同规模的系统需求。

#### 2. 最小模式（Minimum Mode）

- 适用于简单系统：**只有一个 8086/8088 微处理器**。
- 所有总线控制信号都直接由 CPU 产生。
- 系统中不需要额外的总线控制器芯片，逻辑电路简单。

#### 3. 最大模式（Maximum Mode）

- 用于中等或大型系统，包含多个处理器：
  - 主处理器：8086/8088
  - 协处理器：
    - **8087**：数值运算协处理器（支持浮点、三角函数等）
    - **8089**：输入/输出协处理器（负责 I/O 操作）

> ✅ 说明：这是早期 PC 架构中实现高性能计算的重要手段。

### 📌 二、CPU 如何与内存通信？

#### 图 1.3：CPU 从内存读取数据的过程

text







```
1CPU ──── 地址线 ────→ 内存单元（地址为3）
2       │
3       ├── 数据线 ←─── 08（来自3号单元的数据）
4       │
5       └── 控制线 ←─── 读命令（如MREQ, RD）
```

- **地址线**：CPU 发送要访问的存储单元地址（例如地址3）。
- **数据线**：双向传输数据（读时从内存到 CPU，写时从 CPU 到内存）。
- **控制线**：发送控制信号，如 `RD`（读）、`WR`（写）、`MREQ`（内存请求）等。

📌 关键理解：

> CPU 通过三条总线完成对内存的操作：
>
> - **地址总线**：指定位置
> - **数据总线**：传送数据
> - **控制总线**：发出操作指令

### 📌 三、8086/8088 CPU 寄存器结构

#### （1）通用寄存器组（8个16位）

| 寄存器 | 功能                                                      |
| ------ | --------------------------------------------------------- |
| AX     | 累加器（算术运算主用），可拆分为 AH（高8位）、AL（低8位） |
| BX     | 基址寄存器（可作数据寄存器，也可存放地址）                |
| CX     | 计数寄存器（字符串、循环、移位操作计数）                  |
| DX     | 数据寄存器（乘除法辅助累加器，I/O 接口地址）              |

> 💡 特别强调：
>
> - **CX** 在循环和移位中常用作计数器。
> - **DX** 在多字节乘除法中作为高位辅助寄存器。

#### （2）指针与变址寄存器（4个）

| 寄存器 | 功能                              |
| ------ | --------------------------------- |
| SP     | 堆栈指针 → 存放当前堆栈顶偏移地址 |
| BP     | 基址指针 → 常用于堆栈区基地址     |
| SI     | 源变址 → 字符串操作中源地址       |
| DI     | 目的变址 → 字符串操作中目标地址   |

> 🔁 变址寄存器具有自动修改功能（如每次传1字节后 +1），便于批量处理。

#### （3）段寄存器（4个）

| 寄存器 | 含义                                      |
| ------ | ----------------------------------------- |
| CS     | 代码段 → 存放程序指令的段基址             |
| DS     | 数据段 → 当前使用的数据段                 |
| SS     | 堆栈段 → 堆栈区域的段基址                 |
| ES     | 附加段 → 第二个数据段（常用于字符串操作） |

> ⚠️ 注意：
>
> - 8086 使用 **分段机制**，最大寻址空间为 1MB（20位地址）。
> - 实际物理地址 = 段基址 × 16 + 偏移地址
> - 所以 CS:IP 组合指向当前执行指令的位置。

### 📌 五、标志寄存器 FLAGS（16位）

> 该寄存器记录最近一次运算的结果特征及 CPU 控制状态。

#### 分类：

| 类型         | 标志位                 | 作用             |
| ------------ | ---------------------- | ---------------- |
| **状态标志** | CF, PF, AF, ZF, SF, OF | 表示运算结果特征 |
| **控制标志** | IF, DF, TF             | 控制 CPU 行为    |

#### 具体含义：

| 标志                          | 名称     | 说明                                  |
| ----------------------------- | -------- | ------------------------------------- |
| **CF (Carry Flag)**           | 进位标志 | 加法进位 / 减法借位；无符号数溢出判断 |

| **OF (Overflow Flag)**        | 溢出标志 | 有符号数运算是否溢出                  |
| **IF (Interrupt Flag)**       | 中断允许 | 是否允许中断发生                      |
| **DF (Direction Flag)**       | 方向标志 | 字符串操作方向（正向/反向）           |
| **TF (Trap Flag)**            | 单步标志 | 开启单步调试模式                      |

> ✅ 示例：
>
> - 若 `ADD AL, BL` 后 ZF=1，则表示结果为0。
> - 若 `SUB AX, BX` 后 CF=1，则表示 AX < BX（无符号比较）。

## 📌 图 1：分段的基本规则

### 🔹 核心要点：

- 在编程时，将存储器划分为若干个 **段（Segment）**
- 每个段最大可为 **64KB（65536 字节）**
- 这样做的原因是：**段内地址可以用 16 位表示**

> ✅ 为什么？
>
> - 8086 CPU 的寄存器都是 16 位的
> - 要访问 1MB 空间需要 20 位地址，但无法用一个 16 位寄存器直接表达
> - 所以采用“分段 + 偏移”的方式解决

------

### 🔹 段的起始地址限制

> ⚠️ PC 机对段的起始地址有严格限制：
>
> - **不能从任意地址开始**
> - 必须从 **“小段”（Paragraph）的首地址** 开始

#### 小段（Paragraph）定义：

- 从 0 地址开始，每 **16 个字节** 为一小段
- 即：地址必须是 **16 的倍数**
- 例如：`0000H`, `0010H`, `0020H`, ..., `00F0H`, `0100H`, ...

> 💡 数学上讲：
>
> - 段起始地址 = `XXXX0H`（最后一位为 0）
> - 也即：段地址 × 16 = 物理地址偏移量

> ✅ 示例：
>
> - 合法段起始地址：`0000H`, `0010H`, `0020H`, `0100H`, `1000H`
> - 非法段起始地址：`0001H`, `0002H`, `000FH` → 不是 16 的倍数

------

## 📌 图 2：存储器地址的分段 —— 为什么分段？

### 🔹 背景知识：

- **8086/8088 CPU 有 20 根地址总线**：A₁₉ ~ A₀

- 可访问的最大内存容量：

  220=1,048,576 B=1 MB

### 🔹 问题提出：

- 所有用于存放地址的寄存器（如 CS、DS、SS、IP 等）都是 **16 位**
- 如何用 16 位寄存器生成 20 位物理地址？

### 🔹 解决方案：**存储器地址分段（Segmentation）**

- 把 1MB 存储空间划分为多个 **段（Segment）**
- 每个段大小为 **1～64KB**，连续的字节单元
- 每个段是一个独立的逻辑单位，可以存放代码、数据、堆栈等

> ✅ 优点：
>
> - 利用 16 位寄存器实现 20 位寻址
> - 支持程序模块化设计（代码段、数据段分离）
> - 提高内存管理灵活性

------

## 📌 图 3：段地址和偏移地址

### 🔹 定义：

| 名称                           | 含义                                 |
| ------------------------------ | ------------------------------------ |
| **段地址（Segment Address）**  | 表示一个段的起始位置（首地址）       |
| **偏移地址（Offset Address）** | 在该段内部，相对于段起始地址的偏移量 |

> ✅ 举个例子：
>
> - 若某段起始于 `1000H`
> - 某个字节在该段内的第 100 个位置，则其偏移地址为 `0064H`
> - 实际物理地址 = `1000H × 10H + 0064H = 10064H`

### 🔹 关键说明：

- 当偏移量为 `0` → 对应段的 **第一个字节**

- 当偏移量为

  0FFFFH
  ```

   

  → 对应段的

   

  最后一个字节

  - 因为每个段最多 64KB = 65536 字节
  - 最大偏移值 = 65535 = `0FFFFH`

## 📌 图 4：物理地址的形成

### 🔹 计算公式：

物理地址=段地址×10*H*+偏移地址

> ✅ 说明：

- `× 10H` 相当于左移 4 位（乘以 16），因为段地址是以 16 字节为单位划分的
- 例如：
  - 段地址：`1000H`
  - 偏移地址：`0100H`
  - 物理地址 = `1000H × 10H + 0100H = 10000H + 0100H = 10100H`

### 🔹 数据结构示意：

text







```
1       15                   0
2      ---------------------
3      |     16位段地址     |   ← 左移4位（×10H）
4      ---------------------
5            +
6       15                   0
7      ---------------------
8      |    16位偏移地址    |
9      ---------------------
10            =
11       19                   0
12      ---------------------
13      |     20位物理地址    |
14      ---------------------
```

> ✅ 总结：

- 16 位段地址 + 16 位偏移地址 → 组合成 20 位物理地址
- 是 8086 实模式下最核心的寻址机制

## 📌 图 5：段地址与段寄存器

### 🔹 段寄存器的作用：

在实模式下，不同类型的段使用不同的段寄存器：

| 段类型                  | 段寄存器 | 功能                           |
| ----------------------- | -------- | ------------------------------ |
| 代码段（Code Segment）  | CS       | 存放当前执行指令所在段的段地址 |
| 数据段（Data Segment）  | DS       | 存放程序使用的数据段地址       |
| 堆栈段（Stack Segment） | SS       | 存放堆栈区域的段地址           |
| 附加段（Extra Segment） | ES       | 通常用于字符串操作的目标地址   |

> ✅ 示例图解：

- CS = `0150H` → 代码段从 `01500H` 开始
- DS = `4200H` → 数据段从 `42000H` 开始
- SS = `1CD0H` → 堆栈段从 `1CD00H` 开始
- ES = `B000H` → 附加段从 `B0000H` 开始

> 🔄 注意：

- 每个段最大 64KB
- 各段之间 **允许部分重叠甚至完全重叠**
- 分配由操作系统负责（除非用户手动设置）

------

## 📌 图 6：隐含段和偏移寄存器

### 🔹 缺省的段+偏移组合（16位模式）

| 段   | 偏移寄存器           | 主要用途              |
| ---- | -------------------- | --------------------- |
| CS   | IP                   | 指令寻址（取指令）    |
| SS   | SP 或 BP             | 堆栈寻址（压栈/出栈） |
| DS   | BX, DI, SI 或 16位数 | 数据寻址（读写数据）  |
| ES   | DI                   | 字符串目标地址寻址    |

> ✅ 说明：

- 编程时不用显式指定段地址，CPU 自动选择对应的段寄存器
- 例如：`MOV AX, [BX]` → 默认使用 DS 段，即 `(DS):(BX)`
- 如果想改用其他段，需用段超越前缀（如 `ES:`）

------

### 🔹 缺省的段+偏移组合（32位模式）

| 段   | 偏移寄存器                                | 主要用途                                  |
| ---- | ----------------------------------------- | ----------------------------------------- |
| CS   | EIP                                       | 指令寻址                                  |
| SS   | ESP 或 EBP                                | 堆栈寻址                                  |
| DS   | EAX, EBX, ECX, EDX, EDI, ESI, 8位或32位数 | 数据寻址                                  |
| ES   | EDI                                       | 字符串目标寻址                            |
| FS   | 不缺省                                    | 一般寻址（如 Windows 中用于线程局部存储） |
| GS   | 不缺省                                    | 一般寻址（如 Linux 中用于进程信息）       |

> ✅ 说明：

- 在保护模式下，FS 和 GS 可用于访问特殊数据结构
- 多数现代操作系统利用 FS/GS 来快速访问当前线程或进程上下文

## ✅ 总结归纳表

| 类别                     | 内容                                                         |
| ------------------------ | ------------------------------------------------------------ |
| **分段目的**             | 解决 16 位寄存器访问 20 位地址的问题                         |
| **最大段大小**           | 64KB（65536 字节）                                           |
| **段起始地址要求**       | 必须是 16 字节对齐（即 ×10H）                                |
| **物理地址计算**         | `物理地址 = 段地址 × 10H + 偏移地址`                         |
| **段寄存器作用**         | - CS: 代码段 - DS: 数据段 - SS: 堆栈段 - ES: 附加段          |
| **逻辑地址 vs 物理地址** | - 用户编程使用逻辑地址（段:偏移） - CPU 实际访问使用物理地址 |
| **缺省寻址组合**         | - CS:IP → 指令 - SS:SP/BP → 堆栈 - DS:BX/DI/SI → 数据 - ES:DI → 字符串目标 |

## 🧠 学习建议

1. **记住公式**：

   > **物理地址 = 段地址 × 10H + 偏移地址** 这是 8086 寻址的核心！

2. **理解“段”不是固定划分**：

   - 段是逻辑概念，程序员可以自由定义
   - 不一定非得占满 64KB，也可以只用一部分

3. **掌握段寄存器对应关系**：

   - CS → 指令
   - DS → 数据
   - SS → 堆栈
   - ES → 字符串目标

4. **注意段重叠现象**：

   - 允许不同段共享同一块内存
   - 提高内存利用率，但也可能造成冲突（需谨慎）

5. **练习典型题目**：

   - 已知 CS=1000H, IP=0100H，求下一条指令的物理地址？

     - 答案：`1000H × 10H + 0100H = 10100H`

   - 若 DS=2000H, BX=100H，那么

      

     ```
     [BX]
     ```

      

     的物理地址是多少？

     - 答案：`2000H × 10H + 100H = 20100H`
