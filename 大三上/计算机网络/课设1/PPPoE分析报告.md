## 三、PPPoE各阶段数据包头部字段分析

### 3.1 重要说明

**注意**: 本次捕获的数据包中**没有发现PPPoE Discovery阶段的报文**。

这是因为:
1. PPPoE连接在抓包开始前就已经建立
2. PPPoE Discovery阶段(PADI, PADO, PADR, PADS)只在连接建立时发生一次
3. 本次抓包捕获的是已建立PPPoE会话后的数据传输

### 3.2 PPPoE协议理论分析

虽然本次抓包未捕获到PPPoE Discovery阶段,但根据PPPoE协议标准,各阶段的典型数据包头部字段如下:

#### **PPPoE Discovery阶段数据包格式**

```
以太网帧头部 (14字节):
┌─────────────────────────────────────────────────────────┐
│ 目的MAC地址 (6字节) │ 源MAC地址 (6字节) │ 类型 (2字节) │
│ Destination MAC     │ Source MAC        │ 0x8863       │
└─────────────────────────────────────────────────────────┘

PPPoE Discovery头部 (6字节):
┌──────────────────────────────────────────────────────┐
│ VER │ TYPE │ CODE │ SESSION_ID │ LENGTH │
│ (4位)│ (4位)│(1字节)│  (2字节)   │(2字节) │
└──────────────────────────────────────────────────────┘
```

**字段含义**:

1. **目的MAC地址 (Destination MAC)** - 6字节
   - 含义: 目标设备的物理地址
   - PADI阶段: ff:ff:ff:ff:ff:ff (广播)
   - 其他阶段: 对端的MAC地址

2. **源MAC地址 (Source MAC)** - 6字节
   - 含义: 发送设备的物理地址
   - 用于标识发送方

3. **以太网类型 (EtherType)** - 2字节
   - 0x8863: PPPoE Discovery
   - 0x8864: PPPoE Session
   - 含义: 标识上层协议类型

4. **版本 (VER)** - 4位
   - 值: 1
   - 含义: PPPoE协议版本号

5. **类型 (TYPE)** - 4位
   - 值: 1
   - 含义: PPPoE报文类型

6. **代码 (CODE)** - 1字节
   - 0x09: PADI (PPPoE Active Discovery Initiation)
     - 客户端发起,广播寻找PPPoE服务器
   - 0x07: PADO (PPPoE Active Discovery Offer)
     - 服务器响应,提供服务
   - 0x19: PADR (PPPoE Active Discovery Request)
     - 客户端请求建立会话
   - 0x65: PADS (PPPoE Active Discovery Session-confirmation)
     - 服务器确认,分配Session ID
   - 0xa7: PADT (PPPoE Active Discovery Terminate)
     - 终止会话

7. **会话ID (SESSION_ID)** - 2字节
   - Discovery阶段: 0x0000
   - Session阶段: 非零值,唯一标识会话
   - 含义: PPPoE会话标识符

8. **长度 (LENGTH)** - 2字节
   - 含义: PPPoE负载数据的长度(字节)

#### **PPPoE Session阶段数据包格式**

```
以太网帧头部 + PPPoE Session头部 + PPP头部 + IP数据包
┌────────────────────────────────────────────────────────┐
│ 以太网头部 (14字节)                                     │
├────────────────────────────────────────────────────────┤
│ PPPoE Session头部 (6字节)                               │
│ VER=1, TYPE=1, CODE=0x00, SESSION_ID, LENGTH           │
├────────────────────────────────────────────────────────┤
│ PPP头部 (2字节)                                         │
│ Protocol: 0x0021 (IP), 0xc021 (LCP), 0x8021 (IPCP)    │
├────────────────────────────────────────────────────────┤
│ IP数据包及上层协议数据                                  │
└────────────────────────────────────────────────────────┘
```

**PPPoE Session阶段字段含义**:

1. **CODE字段**: 0x00 (Session阶段固定为0)
2. **SESSION_ID**: 由PADS报文分配的会话ID,用于标识此PPPoE连接
3. **PPP Protocol字段**:
   - 0x0021: IPv4数据包
   - 0xc021: LCP (链路控制协议)
   - 0x8021: IPCP (IP控制协议)
   - 0xc023: PAP (密码认证协议)
   - 0xc223: CHAP (挑战握手认证协议)

## 四、登录凭证分析

### 4.1 分析结果

**结论**: **无法在明文中获取用户名和密码信息**

### 4.2 原因分析

通过分析3137个数据包,发现了3个可能包含登录相关信息的数据包:

#### **数据包 #103**
- 源地址: 10.169.16.44:64543
- 目的地址: 40.126.35.64:443
- 协议: **HTTPS (TLS加密)**
- 目标域名: **login.live.com** (Microsoft登录服务)

**十六进制内容分析**:
```
0000: 16 03 03 00 e0 01 00 00 dc 03 03 69 23 19 6e 35
0010: 31 4a ad 60 25 09 06 4d 62 0b 70 6c ca e8 89 31
...
0080: 6f 67 69 6e 2e 6c 69 76 65 2e 63 6f 6d 00 05 00
      l  o  g  i  n  .  l  i  v  e  .  c  o  m
```

- 这是一个**TLS Client Hello**报文
- 可以看到明文的域名 "login.live.com"
- 但实际的用户名密码在TLS握手完成后的加密数据中传输

#### **数据包 #130**
- 源地址: 40.126.35.64:443
- 目的地址: 10.169.16.44:64543
- 这是服务器返回的**TLS Server Hello**和**证书**
- 包含DigiCert颁发的SSL证书信息

#### **数据包 #1432**
- 完全加密的数据传输
- 无法解密内容

### 4.3 为什么无法获取登录信息?

1. **使用HTTPS加密传输**
   - 现代网站(包括教务处网站)都使用HTTPS协议
   - 所有数据在TLS/SSL层加密后传输
   - 即使抓包也无法看到明文内容

2. **TLS 1.2/1.3 加密**
   - 从数据包可以看到使用了TLS协议
   - 加密套件包括: c0 2c, c0 2b, c0 30等(强加密算法)
   - 没有私钥无法解密

3. **安全性保障**
   - 这正是HTTPS的设计目的
   - 保护用户的敏感信息不被窃听
   - 即使在公共网络环境下也能安全传输

## 五、总结

### 5.1 主要发现

1. **网络连接方式**: 通过PPP adapter建立宽带连接,获得IP地址 10.169.16.44

2. **访问过程**: 
   - DNS解析 → TCP连接 → TLS握手 → HTTPS数据传输
   - 涉及多个服务器和CDN节点

3. **安全性**: 
   - 教务网站使用HTTPS加密
   - 有效保护了用户的登录凭证
   - 抓包无法获取明文的用户名和密码

4. **PPPoE分析**: 
   - 本次抓包未捕获PPPoE Discovery阶段
   - 连接已在抓包前建立
   - 主要捕获的是应用层数据传输

### 5.2 网络安全启示

1. **HTTPS的重要性**: 即使在不安全的网络环境下,HTTPS也能保护数据安全
2. **加密传输**: 敏感信息必须加密传输,防止中间人攻击
3. **证书验证**: TLS证书确保了服务器身份的真实性

### 5.3 技术要点

- **DNS解析**: 将域名转换为IP地址的必要步骤
- **TCP三次握手**: 建立可靠连接的基础
- **TLS/SSL**: 现代互联网安全通信的基石
- **PPPoE**: 宽带拨号上网的常用协议
