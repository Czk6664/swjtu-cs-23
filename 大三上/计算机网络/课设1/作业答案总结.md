## 二、访问过程的阶段分析

### 问题1: 访问Web网站的过程分为哪几个阶段?

#### **阶段1: DNS解析阶段**

**任务**: 将域名 jwc.swjtu.edu.cn 解析为IP地址

**相关报文序号**:
- DNS查询: 30, 34, 42, 59, 150, 188, 192, 266, 454, 456 等
- DNS响应: 31, 35, 43, 60, 151, 189, 193, 272, 457, 458 等

**示例**:
```
报文#30: 10.169.16.44 -> 223.5.5.5 (DNS查询)
报文#31: 223.5.5.5 -> 10.169.16.44 (DNS响应)
```

**完成任务**:
- 客户端向DNS服务器发送查询请求
- DNS服务器返回域名对应的IP地址
- 解析网页所需的其他域名(CDN、静态资源等)

---

#### **阶段2: TCP连接建立阶段**

**任务**: 通过三次握手建立TCP连接

**相关报文序号**:
- TCP SYN: 11, 18, 20, 26, 32, 33, 38, 39, 44, 61 等(共111个)
- TCP SYN-ACK: 1, 41, 45, 47, 49, 55, 101, 125, 181, 274 等(共80个)

**示例**:
```
报文#11: 10.169.16.44:63016 -> 204.80.128.1:443 (SYN)
报文#101: 40.126.35.64:443 -> 10.169.16.44:64543 (SYN-ACK)
```

**完成任务**:
- 第一次握手: 客户端发送SYN
- 第二次握手: 服务器返回SYN-ACK
- 第三次握手: 客户端发送ACK
- 建立可靠的TCP连接

---

#### **阶段3: TLS/SSL握手阶段**

**任务**: 建立加密的HTTPS连接

**相关报文序号**: 51, 53, 57, 65, 74, 82, 86, 94, 103, 105 等(共20个TLS握手报文)

**示例**:
```
报文#103: 10.169.16.44:64543 -> 40.126.35.64:443 (TLS Client Hello)
报文#130: 40.126.35.64:443 -> 10.169.16.44:64543 (TLS Server Hello)
```

**完成任务**:
- 客户端发送Client Hello(包含支持的加密套件)
- 服务器返回Server Hello和数字证书
- 完成密钥交换
- 建立加密通道

---

#### **阶段4: HTTP请求/响应阶段**

**任务**: 在加密通道中发送HTTP请求并接收响应

**相关报文**: 所有443端口的加密数据传输

**完成任务**:
- 发送GET/POST请求获取网页
- 接收HTML、CSS、JavaScript等资源
- 加载网页所需的各种静态资源

---

#### **阶段5: 数据传输阶段**

**任务**: 持续的数据交互和资源加载

**完成任务**:
- 传输网页内容
- 加载图片、样式表、脚本
- 用户登录的POST请求(加密传输)

## 三、PPPoE各阶段数据包头部字段分析

### 问题2: 分析PPPoE各阶段的数据包头部字段

### **重要说明**

⚠️ **本次抓包未捕获到PPPoE Discovery阶段的报文**

**原因**:
1. PPPoE连接在开始抓包前就已经建立
2. PPPoE Discovery阶段(PADI, PADO, PADR, PADS)只在连接建立时发生一次
3. 抓包捕获的是已建立连接后的应用层数据传输

### PPPoE协议理论分析

虽然本次未捕获到PPPoE报文,但根据PPPoE协议标准,各阶段数据包格式如下:

---

### **PPPoE Discovery阶段典型数据包**

#### 数据包结构
```
+------------------+------------------+------------------+
| 以太网帧头部(14B) | PPPoE头部(6B)    | PPPoE负载        |
+------------------+------------------+------------------+
```

#### 以太网帧头部字段

| 字段 | 长度 | 示例值 | 含义 |
|------|------|--------|------|
| **目的MAC地址** | 6字节 | ff:ff:ff:ff:ff:ff | 目标设备物理地址(PADI为广播) |
| **源MAC地址** | 6字节 | 72:46:20:00:02:00 | 发送设备物理地址 |
| **类型** | 2字节 | 0x8863 | PPPoE Discovery协议标识 |

#### PPPoE Discovery头部字段

| 字段 | 长度 | 示例值 | 含义 |
|------|------|--------|------|
| **版本(VER)** | 4位 | 1 | PPPoE协议版本号,当前为1 |
| **类型(TYPE)** | 4位 | 1 | PPPoE报文类型,固定为1 |
| **代码(CODE)** | 1字节 | 0x09/0x07/0x19/0x65/0xa7 | 标识Discovery阶段的具体消息类型 |
| **会话ID** | 2字节 | 0x0000 | Discovery阶段固定为0x0000 |
| **长度(LENGTH)** | 2字节 | 变长 | PPPoE负载数据长度(字节) |

#### CODE字段详解

| CODE值 | 名称 | 含义 |
|--------|------|------|
| 0x09 | **PADI** | PPPoE Active Discovery Initiation<br>客户端广播发起连接请求 |
| 0x07 | **PADO** | PPPoE Active Discovery Offer<br>服务器单播响应,提供服务 |
| 0x19 | **PADR** | PPPoE Active Discovery Request<br>客户端单播请求建立会话 |
| 0x65 | **PADS** | PPPoE Active Discovery Session-confirmation<br>服务器确认会话建立,分配Session ID |
| 0xa7 | **PADT** | PPPoE Active Discovery Terminate<br>任意一方终止会话 |

---

### **PPPoE Session阶段典型数据包**

#### 数据包结构
```
+------------------+------------------+------------------+------------------+
| 以太网帧头部(14B) | PPPoE头部(6B)    | PPP头部(2B)      | IP数据包         |
+------------------+------------------+------------------+------------------+
```

#### PPPoE Session头部字段

| 字段 | 长度 | 示例值 | 含义 |
|------|------|--------|------|
| **版本(VER)** | 4位 | 1 | PPPoE协议版本号 |
| **类型(TYPE)** | 4位 | 1 | PPPoE报文类型 |
| **代码(CODE)** | 1字节 | 0x00 | Session阶段固定为0x00 |
| **会话ID** | 2字节 | 0x0001-0xFFFF | 由PADS报文分配的唯一会话标识符 |
| **长度(LENGTH)** | 2字节 | 变长 | PPP负载长度(字节) |

#### 以太网类型字段

| 值 | 含义 |
|----|------|
| 0x8863 | PPPoE Discovery阶段 |
| 0x8864 | PPPoE Session阶段 |

#### PPP协议字段

| 值 | 协议 | 含义 |
|----|------|------|
| 0x0021 | IPv4 | 封装IPv4数据包 |
| 0xc021 | LCP | 链路控制协议 |
| 0x8021 | IPCP | IP控制协议 |
| 0xc023 | PAP | 密码认证协议 |
| 0xc223 | CHAP | 挑战握手认证协议 |

---

### **PPPoE工作流程**

```
客户端                                    服务器
  |                                         |
  |  PADI (广播寻找服务器)                  |
  |========================================>|
  |                                         |
  |  PADO (提供服务)                        |
  |<========================================|
  |                                         |
  |  PADR (请求建立会话)                    |
  |========================================>|
  |                                         |
  |  PADS (确认,分配Session ID)             |
  |<========================================|
  |                                         |
  |  PPP LCP 协商                           |
  |<=======================================>|
  |                                         |
  |  PPP 认证 (PAP/CHAP)                    |
  |<=======================================>|
  |                                         |
  |  PPP IPCP 协商 (获取IP地址)             |
  |<=======================================>|
  |                                         |
  |  数据传输 (Session阶段)                 |
  |<=======================================>|
  |                                         |
  |  PADT (终止会话)                        |
  |========================================>|
```

---

### 无法获取登录信息的原因

#### 1. **HTTPS加密传输**
- 现代网站(包括教务网)都使用HTTPS协议
- 所有敏感数据在TLS/SSL层加密
- 即使抓包也只能看到加密后的数据

#### 2. **TLS加密强度**
- 使用TLS 1.2/1.3协议
- 加密套件: AES-256, ChaCha20等强加密算法
- 没有服务器私钥无法解密

#### 3. **安全性保障**
- 这正是HTTPS的设计目的
- 保护用户隐私和敏感信息
- 防止中间人攻击和数据窃听

---

## 五、总结

### 主要发现

1. **网络连接**: 通过PPP adapter建立宽带连接,IP: 10.169.16.44

2. **访问流程**: DNS解析 → TCP三次握手 → TLS握手 → HTTPS数据传输

3. **安全性**: 教务网使用HTTPS加密,有效保护用户登录凭证

4. **PPPoE**: 本次抓包未捕获PPPoE Discovery阶段(连接已建立)

### 网络安全启示

✅ **HTTPS的重要性**: 即使抓包也无法获取敏感信息  
✅ **加密传输**: 保护用户隐私的必要手段  
✅ **证书验证**: 确保服务器身份真实性
