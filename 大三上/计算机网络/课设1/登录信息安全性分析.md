分析时间: 2025年11月25日

---

一、问题: 能否分析到登录教务网中输入的用户名、密码等信息?

答案: 不能

---

二、详细分析

1. 教务网使用的安全协议

本次访问教务网使用的是 HTTPS 协议 (HTTP over TLS/SSL):
- 协议: HTTPS
- 端口: 443
- TLS版本: TLS 1.3
- 加密套件: TLS_CHACHA20_POLY1305_SHA256
- 密钥交换: x25519 椭圆曲线
- 哈希算法: SHA256

2. 加密保护机制

所有应用层数据(包括用户名和密码)都经过强加密:

加密算法: ChaCha20-Poly1305
- 类型: AEAD (Authenticated Encryption with Associated Data)
- 特点: 同时提供加密和认证
- 安全性: 非常高,无法暴力破解

密钥交换: x25519
- 类型: 椭圆曲线 Diffie-Hellman
- 特点: 前向保密 (Perfect Forward Secrecy)
- 说明: 即使私钥泄露,历史会话也无法解密

3. 登录数据可能所在的数据包

虽然无法解密,但根据数据包特征,登录信息最可能在以下数据包中:

可能的登录请求数据包:

- 协议: TLSv1.2 Application Data
- 方向: 客户端 → 服务器 (10.169.227.162 → 202.115.71.132)
- 源端口: 64183
- 目标端口: 443
- 长度: 1459 bytes
- 内容: 完全加密的载荷

数据包 288:
- 协议: TLSv1.2 Application Data
- 方向: 客户端 → 服务器 (10.169.227.162 → 202.115.71.132)
- 源端口: 49669
- 目标端口: 443
- 长度: 较大
- 内容: 完全加密的载荷

数据包 300-301:
- 协议: TLSv1.2 Application Data
- 方向: 客户端 → 服务器
- 端口: 49669 → 443
- 内容: 完全加密的载荷

---

四、为什么无法看到用户名和密码

1. TLS加密通道

在TCP三次握手之后,客户端和服务器进行了TLS握手:

步骤1: Client Hello (数据包 295-296)
- 客户端发送支持的加密套件列表
- 包含SNI扩展: jwc.swjtu.edu.cn
- 生成客户端随机数

步骤2: Server Hello (数据包 303)
- 服务器选择加密套件: TLS_CHACHA20_POLY1305_SHA256
- 发送服务器证书
- 生成服务器随机数

步骤3: 密钥交换 (数据包 304)
- 使用x25519进行密钥交换
- 双方计算出会话密钥
- 会话密钥只存在于内存中,不在网络上传输

步骤4: Change Cipher Spec
- 双方确认开始使用加密
- 后续所有数据都使用会话密钥加密

2. 加密后的数据特征

加密前的HTTP请求:
```
POST /login HTTP/1.1
Host: jwc.swjtu.edu.cn
Content-Length: 45
Content-Type: application/x-www-form-urlencoded

username=2023112621&password=mypassword123
```

加密后的TLS记录:
```
17 03 03 05 7d [1405字节的加密数据]
```

特点:
- 只能看到TLS记录头部
- 无法看到HTTP方法(POST/GET)
- 无法看到URL路径
- 无法看到请求头
- 无法看到请求体(用户名和密码)
- 所有内容都是随机字节

3. 无法解密的原因

需要以下条件才能解密:
- 会话密钥 (只存在于客户端和服务器内存中)
- 或者服务器私钥 (存储在服务器上,高度保密)
- 或者客户端预主密钥 (只存在于客户端内存中)

即使获得了抓包文件,也无法解密,因为:
- TLS 1.3使用前向保密
- 密钥交换使用椭圆曲线算法
- 会话密钥不在网络上传输
- 每次连接使用不同的会话密钥

六、安全性验证

这正是HTTPS设计的核心目标:

✅ 防止密码被窃听
- 即使抓包也无法获取明文密码
- 保护用户账号安全

✅ 保护用户隐私
- 所有敏感信息都经过加密
- 无法知道用户访问了哪些页面
- 无法知道用户提交了什么数据

✅ 防止中间人攻击
- 通过证书验证服务器身份
- 确保连接到真正的教务网服务器
- 防止钓鱼网站

✅ 确保数据完整性
- 使用AEAD加密模式
- 同时提供加密和认证
- 防止数据被篡改

---

七、结论

无法从数据包中直接看到用户名和密码

原因总结:

1. 协议层面
   - 教务网使用HTTPS协议
   - 所有HTTP数据都在TLS加密通道中传输
   - TLS 1.3提供强加密保护

2. 加密层面
   - 使用ChaCha20-Poly1305加密算法
   - 使用x25519密钥交换
   - 提供前向保密特性

3. 实际表现
   - 登录数据在Application Data包中
   - 所有内容都是加密的随机字节
   - 没有会话密钥就无法解密

4. 安全保障
   - 这是HTTPS协议的安全保障机制
   - 保护用户账号和隐私安全
   - 符合网络安全最佳实践

对比说明:

| 特性 | PPPoE PAP认证 | HTTPS登录 |
|------|--------------|-----------|
| 传输方式 | 明文 | 加密 |
| 用户名可见性 | 可见 | 不可见 |
| 密码可见性 | 可见 | 不可见 |
| 抓包安全性 | 不安全 | 安全 |
| 数据完整性 | 无保护 | 有保护 |
| 身份验证 | 服务器验证客户端 | 双向验证 |

本次实验体现了多层安全机制:
- 链路层: PPPoE认证 (已建立)
- 应用层: HTTPS加密 (保护登录信息)
