**2) 采用存储程序工作方式**

这是冯·诺依曼体系结构的**核心思想之一**——“存储程序”概念。其含义是：**程序和数据一样，都可以被存储在计算机的存储器中，并由计算机自动执行。**

#### 内容解析：

1. a、事先编制程序
   - 意思是：用户需要先编写好程序（即一系列指令），这是计算任务的逻辑步骤。
   - 手写标注：“写” → 强调“编写”这个动作。
2. b、将程序存储于计算机的存储器之中
   - 程序不是直接运行，而是先加载到内存（存储器）中。
   - 手写标注：“存” → 强调“存储”这个过程。
   - 这一点非常重要：程序和数据一样都以二进制形式存在存储器中，实现了“程序可修改、可重用”。
3. c、计算机在运行时将自动地连续地从存储器中依次取出指令加以执行
   - 计算机启动后，控制器会自动从存储器中按顺序读取指令，然后交给运算器执行。
   - 手写圈出“运行时” → 强调“自动执行”的过程。
   - “依次取出指令”体现了程序的**顺序执行特性**（虽然现代计算机有跳转、分支等机制，但基础仍是顺序执行）。

✅ 总结：这三点共同构成了“**存储程序工作方式**”，是现代计算机工作的基本原理。

> 🌟 关键词：**编程序 → 存储 → 自动执行**

## 一、原码（Sign-Magnitude）

### 定义：

- **最高位为符号位**：0 表示正数，1 表示负数。
- 其余位表示数值的绝对值（真值）。

### 示例（8位）：

- +5 → `0000 0101`
- -5 → `1000 0101`

### 范围（n位）：

- 正数：0 到 2^{n-1} - 1
- 负数：-0 到 -(2^{n-1} - 1)
- **存在 +0 和 -0 两个零**（如 0000 0000 和 1000 0000）

### 缺点：

- 加减法复杂（需判断符号）
- 零不唯一

------

## 二、反码（Ones' Complement）

### 定义：

- 正数：与原码相同。
- 负数：符号位为1，数值位按位取反。

### 示例（8位）：

- +5 → `0000 0101`
- -5 → `1111 1010`（对 0000 0101 取反，符号位保持1）

### 范围（n位）：

- 同原码：- (2^{n-1} - 1) 到 + (2^{n-1} - 1)
- **仍有 +0（000...0）和 -0（111...1）**

### 运算特点：

- 减法可转为加法，但需“循环进位”（end-around carry）
- 仍不理想，现代计算机不用

------

## 三、补码（Two's Complement）✅（主流表示法）

### 定义：

- 正数：与原码相同。
- 负数：反码 + 1

### 示例（8位）：

- +5 → `0000 0101`
- -5 →
  原码：1000 0101 →
  反码：1111 1010 →
  补码：1111 1011

> 快速求法：从右往左，保留第一个1及右边所有位，其余取反。

### 范围（n位）：

- **-2^{n-1} 到 + (2^{n-1} - 1)**
- 8位：-128 到 +127
- 16位：-32768 到 +32767

✅ **优点**：

- 零唯一（000...0）
- 加减法统一（无需区分符号）
- 硬件实现简单

### 补码运算规则：

- 直接相加，忽略最高位进位（模 2^n 运算）
- 例：8位下，127 + 1 = -128（溢出）

------

## 四、溢出（Overflow）

### 何时发生？

- 当运算结果超出表示范围时。

### 判断方法（补码加法）：

1. 符号位进位法

   ：

   - 若符号位进位 ≠ 最高位数值位进位 → 溢出

2. 结果符号异常

   ：

   - 正 + 正 = 负 → 溢出
   - 负 + 负 = 正 → 溢出

### 示例（8位补码）：

- 127 + 1 = 128 → 实际结果为 `1000 0000` = -128（溢出！）
- (-64) + (-65) = -129 → 超出 -128，结果为 127（溢出）

> 注意：**进位 ≠ 溢出**！无符号数看进位，有符号数看溢出。

------

## 五、BCD码（Binary-Coded Decimal）

### 定义：

- 用 **4位二进制** 表示 **1位十进制数字（0～9）**
- 每4位只能是 0000 ～ 1001（即0～9），1010～1111 无效

### 示例：

- 十进制 25 → BCD: `0010 0101`
- 十进制 9 → BCD: `1001`

### 类型：

#### 1. **非压缩BCD码（Unpacked BCD）**

- 每个十进制数字占一个字节（8位），高4位为0
- 例：25 → `0000 0010` `0000 0101`

#### 2. **压缩BCD码（Packed BCD）** ✅

- 两个十进制数字压缩在一个字节中
- 高4位：十位；低4位：个位
- 例：25 → `0010 0101`（1字节）
- 优点：节省存储空间

### BCD码运算（以压缩BCD为例）：

- **不能直接用二进制加法**！需调整
- 规则：
  - 若低4位 > 9 或 有低4位进位 → +6 调整
  - 若高4位 > 9 或 有高4位进位 → +60H（即高4位+6）

#### 示例：25 + 38 = 63

text

编辑







```
1  0010 0101  (25)
2+ 0011 1000  (38)
3------------
4  0101 1101  → 低4位=1101(13)>9 → +6
5+       0110
6------------
7  0110 0011  = 63 ✓
```

> CPU通常提供 **DAA（Decimal Adjust after Addition）** 指令自动调整

  - **控制字符（0～31, 127）**：不可打印（如换行LF=10, 回车CR=13）

### 一、CPU 的功能（1.1）

这部分介绍了 CPU 的四大核心功能：

#### ✅ 1. 指令控制

- **作用**：保证机器按程序规定的顺序取出并执行指令。
- **关键词**：“取指”、“顺序执行”。
- 这是程序执行的基础，由控制器负责。

> 📌 注意：图中“执行**某**”可能是笔误，应为“执行**指令**”。

#### ✅ 2. 操作控制

- **作用**：CPU 根据每条指令生成对应的操作信号，并发送给相关部件，使其按指令要求工作。
- 实质上是“指挥”各个硬件单元协同工作的过程。

#### ✅ 3. 时间控制

- **作用**：对各种操作的时间进行定时，确保各部件在正确的时间点完成任务。
- 例如：取指阶段、译码阶段、执行阶段等都有严格时序控制。

#### ✅ 4. 数据加工

- **作用**：对数据进行算术运算（如加减乘除）和逻辑运算（如与、或、非、比较等）。
- 主要由 **ALU（算术逻辑单元）** 完成。

### 二、CPU 的基本组成（1.2）

#### 🔹 历史构成：

- 早期 CPU 主要由两大部分组成：
  - **运算器**（Arithmetic Logic Unit, ALU）
  - **控制器**（Control Unit）
- 随着集成电路发展，现代 CPU 芯片还集成了其他组件，如：
  - **Cache（高速缓存）**：解决 CPU 和主存速度不匹配的问题，提高访问效率。

#### 🔹 运算器（ALU）的作用：

- 执行所有算术运算（如 +、−、×、÷）
- 执行所有逻辑运算（如 AND、OR、NOT、比较）
- 是“数据加工”的核心部件

#### 🔹 控制器的作用：

- 协调整个计算机系统的运行，相当于“大脑”。
- 具体职责包括：
  1. **从内存中取出一条指令**，并指出下一条指令的位置（通过 PC 程序计数器实现）
  2. **对指令进行译码**，产生相应的操作控制信号，送往相应部件
  3. **指挥 CPU、内存、I/O 设备之间的数据流动方向**

### 三、CPU 的基本模型（结构图解析）

这是一个典型的 CPU 内部结构示意图，包含多个寄存器和功能模块。我们来逐个分析：

#### 🧱 主要组成部分：

| 名称                        | 英文缩写 | 功能                                                         |
| --------------------------- | -------- | ------------------------------------------------------------ |
| **程序计数器**              | PC       | 存储下一条要执行指令的地址；自动递增以支持顺序执行           |
| **地址寄存器**              | AR       | 临时存放由 PC 提供的地址，用于访问存储器                     |
| **数据缓冲寄存器**          | DR       | 暂存从内存读出或写入的数据/指令                              |
| **指令寄存器**              | IR       | 保存当前正在执行的那条指令                                   |
| **累加器**                  | AC       | 通用寄存器，常用于存放中间结果（尤其在算术运算中）           |
| **状态条件寄存器**          | PSW      | 存储运算结果的状态标志（如零标志 ZF、进位标志 CF 等），供分支判断使用 |
| **算术逻辑单元**            | ALU      | 执行所有算术和逻辑运算                                       |
| **指令译码器**              | —        | 将 IR 中的指令翻译成控制信号                                 |
| **操作控制器 & 时序产生器** | —        | 根据译码结果生成具体控制信号，并按照时钟节拍发出控制脉冲     |

#### 🔁 数据流与控制流说明：

1. **取指阶段**：
   - PC → AR（把指令地址送入地址寄存器）
   - AR → ABUS（地址总线）
   - 存储器 → DR（读取指令）
   - DR → IR（指令进入指令寄存器）
2. **译码阶段**：
   - IR → 指令译码器 → 生成控制信号
3. **执行阶段**：
   - 控制信号驱动 ALU、DR、AC 等部件完成运算
   - 结果可能写回 DR 或存储器
4. **时钟同步**：
   - 时钟信号控制整个 CPU 的节奏，确保每个步骤按时发生
5. **反馈机制**：
   - ALU 的运算结果会反馈到 PSW（如设置标志位），影响后续判断（如条件跳转）

#### ✅ Cache（高速缓存）

- 位于 CPU 和主存之间
- 速度快、容量小，用来缓存频繁访问的数据和指令
- 缓解“CPU 快、主存慢”的矛盾

#### ✅ 寄存器的作用

- 所有寄存器都是“临时存储单元”，但比内存快得多
- 关键寄存器：
  - **PC**：决定程序执行顺序
  - **IR**：当前指令
  - **DR**：数据中转站
  - **AR**：地址中转站
  - **AC**：计算用的“工作台”
  - **PSW**：记录运算状态

#### ✅ 控制器的核心流程

#### 3. 读写控制引脚

| 引脚                                                         | 功能             | 有效电平     |
| ------------------------------------------------------------ | ---------------- | ------------ |
| **ALE** (Address Latch Enable)                               | 地址锁存允许信号 | 高电平有效 ✅ |
| - 当 ALE 为高时，将 AD₀～AD₁₅ 上的地址信息锁存到外部地址锁存器中，实现地址分离 |                  |              |

| **IO/M\*** | I/O 或存储器访问选择 | 输出、三态 | | - 高电平 → 访问 I/O 端口（提供 16 位 I/O 地址） | | - 低电平 → 访问内存（提供 20 位存储器地址） |

| **WR\*** (Write) | 写控制信号 | 低电平有效 ✅ | | - 有效时，CPU 向存储器或 I/O 写入数据 |

| **RD\*** (Read) | 读控制信号 | 低电平有效 ✅ | | - 有效时，CPU 从存储器或 I/O 读取数据 |

| **DEN\*** (Data Enable) | 数据允许信号 | 低电平有效 ✅ | | - 表示数据总线上正在传送数据 |

| **DT/R\*** (Data Transmit/Receive) | 数据发送/接收方向控制 | | - 高电平 → 数据由 CPU 发出（发送） | | - 低电平 → 数据输入 CPU（接收） |

------

#### 4. 总线请求与响应信号

| 引脚                        | 功能                                            |
| --------------------------- | ----------------------------------------------- |
| **HOLD** (Hold Request)     | 外部设备（如 DMA 控制器）请求使用系统总线的信号 |
| **HLDA** (Hold Acknowledge) | CPU 响应 HOLD 请求，表示同意释放总线            |

> 🔁 工作流程：
>
> - 外设发 HOLD → CPU 检测到后，在完成当前操作后发出 HLDA → 放弃总线控制权 → 外设接管总线

------

#### 5. READY 信号（准备就绪）

- **功能**：用于解决 CPU 与慢速外设之间的速度匹配问题。

- 工作方式

  ：

  - 若 READY = 1 → 设备已准备好，正常执行数据传输。
  - 若 READY = 0 → 插入等待状态 TW，直到 READY 变为 1。

- ✅ 实现了异步通信中的“等待机制”。

## 🔍 二、逐图解析

### ✅ 图1：中断请求和响应信号（续1）

#### ➤ NMI（非屏蔽中断请求）

- **引脚号：17**

- **类型：输入，上升沿触发**

- 特点

  ：

  - 不受中断允许标志 IF 控制
  - 只要电平由低变高（正跳变），CPU 就会在当前指令周期结束后响应
  - 常用于处理紧急事件（如电源故障、硬件错误等）

- ✅ 用途：不可被软件屏蔽，优先级最高

#### ➤ INTR（可屏蔽中断请求）

- **引脚号：18**

- **类型：输入，高电平有效**

- 条件响应

  ：

  - INTR = 1 且 IF = 1（中断允许位为1）
  - CPU 在每个指令周期最后一个 T 状态检测该信号
  - 满足条件则在当前指令执行完后响应中断

- ✅ 用途：外部设备（如键盘、打印机）发出的数据就绪通知

#### ➤ INTA（中断响应信号）

- **引脚号：24**

- **类型：输出，低电平有效**

- 功能

  ：

  - 当 CPU 响应 INTR 中断时，会发出两个负脉冲（INTA*）
  - 第一个脉冲：通知外设“我收到你的中断请求”
  - 第二个脉冲：要求外设将中断类型码送入数据总线

- ✅ 目的：获取中断向量号（中断服务程序入口地址）

> 💡 补充知识：
>  8086 支持最多 256 种中断（0～255），每种对应一个中断服务程序。

### 📌 一、8086/8088 CPU 工作模式

#### 1. 工作模式由硬件决定

> “8086 / 8088 的工作模式完全是由硬件决定的。”

- 这意味着通过外部电路（如引脚信号）配置 CPU 是运行在“最小模式”还是“最大模式”，而不是软件控制。
- 目的是适应不同规模的系统需求。

#### 2. 最小模式（Minimum Mode）

- 适用于简单系统：**只有一个 8086/8088 微处理器**。
- 所有总线控制信号都直接由 CPU 产生。
- 系统中不需要额外的总线控制器芯片，逻辑电路简单。

#### 3. 最大模式（Maximum Mode）

- 用于中等或大型系统，包含多个处理器：
  - 主处理器：8086/8088
  - 协处理器：
    - **8087**：数值运算协处理器（支持浮点、三角函数等）
    - **8089**：输入/输出协处理器（负责 I/O 操作）

> ✅ 说明：这是早期 PC 架构中实现高性能计算的重要手段。

### 📌 二、CPU 如何与内存通信？

#### 图 1.3：CPU 从内存读取数据的过程

text







```
1CPU ──── 地址线 ────→ 内存单元（地址为3）
2       │
3       ├── 数据线 ←─── 08（来自3号单元的数据）
4       │
5       └── 控制线 ←─── 读命令（如MREQ, RD）
```

- **地址线**：CPU 发送要访问的存储单元地址（例如地址3）。
- **数据线**：双向传输数据（读时从内存到 CPU，写时从 CPU 到内存）。
- **控制线**：发送控制信号，如 `RD`（读）、`WR`（写）、`MREQ`（内存请求）等。

📌 关键理解：

> CPU 通过三条总线完成对内存的操作：
>
> - **地址总线**：指定位置
> - **数据总线**：传送数据
> - **控制总线**：发出操作指令

### 📌 三、8086/8088 CPU 寄存器结构

#### （1）通用寄存器组（8个16位）

| 寄存器 | 功能                                                      |
| ------ | --------------------------------------------------------- |
| AX     | 累加器（算术运算主用），可拆分为 AH（高8位）、AL（低8位） |
| BX     | 基址寄存器（可作数据寄存器，也可存放地址）                |
| CX     | 计数寄存器（字符串、循环、移位操作计数）                  |
| DX     | 数据寄存器（乘除法辅助累加器，I/O 接口地址）              |

> 💡 特别强调：
>
> - **CX** 在循环和移位中常用作计数器。
> - **DX** 在多字节乘除法中作为高位辅助寄存器。

#### （2）指针与变址寄存器（4个）

| 寄存器 | 功能                              |
| ------ | --------------------------------- |
| SP     | 堆栈指针 → 存放当前堆栈顶偏移地址 |
| BP     | 基址指针 → 常用于堆栈区基地址     |
| SI     | 源变址 → 字符串操作中源地址       |
| DI     | 目的变址 → 字符串操作中目标地址   |

> 🔁 变址寄存器具有自动修改功能（如每次传1字节后 +1），便于批量处理。

#### （3）段寄存器（4个）

| 寄存器 | 含义                                      |
| ------ | ----------------------------------------- |
| CS     | 代码段 → 存放程序指令的段基址             |
| DS     | 数据段 → 当前使用的数据段                 |
| SS     | 堆栈段 → 堆栈区域的段基址                 |
| ES     | 附加段 → 第二个数据段（常用于字符串操作） |

> ⚠️ 注意：
>
> - 8086 使用 **分段机制**，最大寻址空间为 1MB（20位地址）。
> - 实际物理地址 = 段基址 × 16 + 偏移地址
> - 所以 CS:IP 组合指向当前执行指令的位置。

### 📌 五、标志寄存器 FLAGS（16位）

> 该寄存器记录最近一次运算的结果特征及 CPU 控制状态。

#### 分类：

| 类型         | 标志位                 | 作用             |
| ------------ | ---------------------- | ---------------- |
| **状态标志** | CF, PF, AF, ZF, SF, OF | 表示运算结果特征 |
| **控制标志** | IF, DF, TF             | 控制 CPU 行为    |

#### 具体含义：

| 标志                          | 名称     | 说明                                  |
| ----------------------------- | -------- | ------------------------------------- |
| **CF (Carry Flag)**           | 进位标志 | 加法进位 / 减法借位；无符号数溢出判断 |

| **OF (Overflow Flag)**        | 溢出标志 | 有符号数运算是否溢出                  |
| **IF (Interrupt Flag)**       | 中断允许 | 是否允许中断发生                      |
| **DF (Direction Flag)**       | 方向标志 | 字符串操作方向（正向/反向）           |
| **TF (Trap Flag)**            | 单步标志 | 开启单步调试模式                      |

> ✅ 示例：
>
> - 若 `ADD AL, BL` 后 ZF=1，则表示结果为0。
> - 若 `SUB AX, BX` 后 CF=1，则表示 AX < BX（无符号比较）。

## 📌 图 1：分段的基本规则

### 🔹 核心要点：

- 在编程时，将存储器划分为若干个 **段（Segment）**
- 每个段最大可为 **64KB（65536 字节）**
- 这样做的原因是：**段内地址可以用 16 位表示**

> ✅ 为什么？
>
> - 8086 CPU 的寄存器都是 16 位的
> - 要访问 1MB 空间需要 20 位地址，但无法用一个 16 位寄存器直接表达
> - 所以采用“分段 + 偏移”的方式解决

------

### 🔹 段的起始地址限制

> ⚠️ PC 机对段的起始地址有严格限制：
>
> - **不能从任意地址开始**
> - 必须从 **“小段”（Paragraph）的首地址** 开始

#### 小段（Paragraph）定义：

- 从 0 地址开始，每 **16 个字节** 为一小段
- 即：地址必须是 **16 的倍数**
- 例如：`0000H`, `0010H`, `0020H`, ..., `00F0H`, `0100H`, ...

> 💡 数学上讲：
>
> - 段起始地址 = `XXXX0H`（最后一位为 0）
> - 也即：段地址 × 16 = 物理地址偏移量

> ✅ 示例：
>
> - 合法段起始地址：`0000H`, `0010H`, `0020H`, `0100H`, `1000H`
> - 非法段起始地址：`0001H`, `0002H`, `000FH` → 不是 16 的倍数

------

## 📌 图 2：存储器地址的分段 —— 为什么分段？

### 🔹 背景知识：

- **8086/8088 CPU 有 20 根地址总线**：A₁₉ ~ A₀

- 可访问的最大内存容量：

  220=1,048,576 B=1 MB

### 🔹 问题提出：

- 所有用于存放地址的寄存器（如 CS、DS、SS、IP 等）都是 **16 位**
- 如何用 16 位寄存器生成 20 位物理地址？

### 🔹 解决方案：**存储器地址分段（Segmentation）**

- 把 1MB 存储空间划分为多个 **段（Segment）**
- 每个段大小为 **1～64KB**，连续的字节单元
- 每个段是一个独立的逻辑单位，可以存放代码、数据、堆栈等

> ✅ 优点：
>
> - 利用 16 位寄存器实现 20 位寻址
> - 支持程序模块化设计（代码段、数据段分离）
> - 提高内存管理灵活性

------

## 📌 图 3：段地址和偏移地址

### 🔹 定义：

| 名称                           | 含义                                 |
| ------------------------------ | ------------------------------------ |
| **段地址（Segment Address）**  | 表示一个段的起始位置（首地址）       |
| **偏移地址（Offset Address）** | 在该段内部，相对于段起始地址的偏移量 |

> ✅ 举个例子：
>
> - 若某段起始于 `1000H`
> - 某个字节在该段内的第 100 个位置，则其偏移地址为 `0064H`
> - 实际物理地址 = `1000H × 10H + 0064H = 10064H`

### 🔹 关键说明：

- 当偏移量为 `0` → 对应段的 **第一个字节**

- 当偏移量为

  0FFFFH
  ```

   

  → 对应段的

   

  最后一个字节

  - 因为每个段最多 64KB = 65536 字节
  - 最大偏移值 = 65535 = `0FFFFH`

## 📌 图 4：物理地址的形成

### 🔹 计算公式：

物理地址=段地址×10*H*+偏移地址

> ✅ 说明：

- `× 10H` 相当于左移 4 位（乘以 16），因为段地址是以 16 字节为单位划分的
- 例如：
  - 段地址：`1000H`
  - 偏移地址：`0100H`
  - 物理地址 = `1000H × 10H + 0100H = 10000H + 0100H = 10100H`

### 🔹 数据结构示意：

text







```
1       15                   0
2      ---------------------
3      |     16位段地址     |   ← 左移4位（×10H）
4      ---------------------
5            +
6       15                   0
7      ---------------------
8      |    16位偏移地址    |
9      ---------------------
10            =
11       19                   0
12      ---------------------
13      |     20位物理地址    |
14      ---------------------
```

> ✅ 总结：

- 16 位段地址 + 16 位偏移地址 → 组合成 20 位物理地址
- 是 8086 实模式下最核心的寻址机制

## 📌 图 5：段地址与段寄存器

### 🔹 段寄存器的作用：

在实模式下，不同类型的段使用不同的段寄存器：

| 段类型                  | 段寄存器 | 功能                           |
| ----------------------- | -------- | ------------------------------ |
| 代码段（Code Segment）  | CS       | 存放当前执行指令所在段的段地址 |
| 数据段（Data Segment）  | DS       | 存放程序使用的数据段地址       |
| 堆栈段（Stack Segment） | SS       | 存放堆栈区域的段地址           |
| 附加段（Extra Segment） | ES       | 通常用于字符串操作的目标地址   |

> ✅ 示例图解：

- CS = `0150H` → 代码段从 `01500H` 开始
- DS = `4200H` → 数据段从 `42000H` 开始
- SS = `1CD0H` → 堆栈段从 `1CD00H` 开始
- ES = `B000H` → 附加段从 `B0000H` 开始

> 🔄 注意：

- 每个段最大 64KB
- 各段之间 **允许部分重叠甚至完全重叠**
- 分配由操作系统负责（除非用户手动设置）

## 📌 图 6：隐含段和偏移寄存器

### 🔹 缺省的段+偏移组合（16位模式）

| 段   | 偏移寄存器           | 主要用途              |
| ---- | -------------------- | --------------------- |
| CS   | IP                   | 指令寻址（取指令）    |
| SS   | SP 或 BP             | 堆栈寻址（压栈/出栈） |
| DS   | BX, DI, SI 或 16位数 | 数据寻址（读写数据）  |
| ES   | DI                   | 字符串目标地址寻址    |

> ✅ 说明：

- 编程时不用显式指定段地址，CPU 自动选择对应的段寄存器
- 例如：`MOV AX, [BX]` → 默认使用 DS 段，即 `(DS):(BX)`
- 如果想改用其他段，需用段超越前缀（如 `ES:`）

------

### 🔹 缺省的段+偏移组合（32位模式）

| 段   | 偏移寄存器                                | 主要用途                                  |
| ---- | ----------------------------------------- | ----------------------------------------- |
| CS   | EIP                                       | 指令寻址                                  |
| SS   | ESP 或 EBP                                | 堆栈寻址                                  |
| DS   | EAX, EBX, ECX, EDX, EDI, ESI, 8位或32位数 | 数据寻址                                  |
| ES   | EDI                                       | 字符串目标寻址                            |
| FS   | 不缺省                                    | 一般寻址（如 Windows 中用于线程局部存储） |
| GS   | 不缺省                                    | 一般寻址（如 Linux 中用于进程信息）       |

> ✅ 说明：

- 在保护模式下，FS 和 GS 可用于访问特殊数据结构
- 多数现代操作系统利用 FS/GS 来快速访问当前线程或进程上下文

| **最大段大小**           | 64KB（65536 字节）                                           |

这组图片是关于 **计算机组成原理** 中“**时序信号的作用与体制**”以及“**控制方式**”的讲解内容，主要涉及 CPU 内部操作的时间协调机制。下面我将逐图进行详细分析，并总结核心知识点。

### 📌 图1：时序信号的作用和体制

#### ✅ 标题：

> **时序信号的作用和体制**

#### 🔍 内容解析：

1. 基本概念

   ：

   - 计算机各部件协同工作需要时间标志。
   - 这些时间标志通过 **时序信号** 来体现。
   - 采用多级时序体制来精确控制指令执行过程。

2. 硬布线控制器中的三级时序体制

   （重点）：

   > 主状态周期 → 节拍电位 → 节拍脉冲
   > （即：**指令周期 → 机器周期 → 时钟周期**）

   - 主状态周期（指令周期）
     - 指令从取指到执行完成的总时间。
     - 包含若干个节拍周期（CPU周期）。
     - 可用一个触发器的状态持续时间表示（例如：某个阶段保持高电平或低电平）。
   - 节拍电位（机器周期 / CPU周期）
     - 表示一个 CPU 周期的时间长度。
     - 包含若干个节拍脉冲（时钟周期）。
     - 是一种**电位信号**，在一段时间内维持稳定电平（如高电平），用于控制某一步操作。
   - 节拍脉冲（时钟周期 / T周期）
     - 最小的时间单位，由系统时钟产生。
     - 是一种**脉冲信号**，每个上升沿或下降沿触发一次动作。

3. 微程序控制器中的二级体制

   ：

   - 通常只使用两级：**节拍电位 + 节拍脉冲**
   - 不再区分“主状态周期”，因为微程序本身已经定义了每条指令的操作步骤。

4. 手写标注说明

   ：

   - 红色圈出：“包含若干个节拍周期”——强调**指令周期是由多个CPU周期组成的**。
   - 箭头指向该句，突出其重要性。

✅ **结论**：

- 在硬布线控制器中，采用 **三级时序体制** 实现更精细的控制；
- 三级结构为：**指令周期（主状态）→ 机器周期（节拍电位）→ 时钟周期（节拍脉冲）**；
- 微程序控制器简化为两级，依赖微指令序列实现控制。

------

### 📌 图2：控制方式

#### ✅ 标题：

> **控制方式**

#### 🔍 内容解析：

这是关于 **如何控制不同操作序列的时序信号的方法**，分为三种类型：

------

##### 1. **同步控制方式**

- 定义：
  - 所有指令在执行时所需的 CPU 周期数和时钟周期数都**固定不变**。
- 特点：
  - 使用统一的、固定的节拍来控制所有指令。
  - 即使某些指令不需要那么多周期，也必须等待完整周期结束。
- 示例：
  - 采用完全统一的机器周期执行各种不同的指令。
- 优点：
  - 控制简单，易于设计。
- 缺点：
  - 效率较低，浪费时间（如短指令也要等长周期）。

👉 类似于“流水线前的定时器”，所有任务按最大耗时处理。

------

##### 2. **异步控制方式**

- 定义：
  - 控制器发出某一操作控制信号后，**等待执行部件完成操作**，再发出下一个信号。
- 特点：
  - 没有固定的节拍，而是根据实际完成情况决定下一步。
  - 依靠反馈信号（如“完成”信号）来触发后续动作。
- 优点：
  - 高效灵活，能适应不同速度的部件。
- 缺点：
  - 控制逻辑复杂，难以实现高速运行。
- 应用场景：
  - 外设接口、慢速设备通信等。

👉 类似于“按需响应”，不靠时间表，靠事件驱动。

------

##### 3. **联合控制方式**

- 定义：
  - 将同步控制与异步控制结合起来使用。
- 特点：
  - 对大多数操作采用同步方式以保证效率；
  - 对个别关键或不确定的操作（如I/O）采用异步方式。
- 实际应用广泛，现代 CPU 多采用此类混合方式。

------

### ✅ 总结对比表

表格



| 控制方式 | 是否固定周期 | 是否依赖反馈 | 优点               | 缺点                 | 典型应用场景         |
| :------- | :----------- | :----------- | :----------------- | :------------------- | :------------------- |
| 同步控制 | ✅ 是         | ❌ 否         | 结构简单，容易实现 | 效率低，资源浪费     | 简单处理器、教学模型 |
| 异步控制 | ❌ 否         | ✅ 是         | 灵活高效，适应性强 | 控制复杂，延迟不可控 | I/O 接口、外设通信   |
| 联合控制 | ⚠️ 部分固定   | ⚠️ 部分反馈   | 平衡性能与灵活性   | 设计较复杂           | 现代通用 CPU         |

### 🧠 关键理解点

1. 时序体制的本质

   ：

   - 是为了协调 CPU 内部各个部件的动作顺序和时间关系。
   - 三级体制（主状态 → 节拍电位 → 节拍脉冲）是对时间的分层划分。

2. 节拍电位 vs 节拍脉冲

   ：

   - **节拍电位**：一段持续的电平（如高电平），代表一个完整的操作阶段（如“取指”阶段）。
   - **节拍脉冲**：短暂的脉冲信号，用于触发具体动作（如寄存器加载）。

3. 为什么需要多级体制？

   - 因为不同操作所需时间不同，但又不能太随意。
   - 分层次可以既保证有序性，又能灵活安排任务。

4. 控制方式的选择依据

   ：

   - 同步适合规则、快速、可预测的任务；
   - 异步适合不可预测、速度差异大的任务；
   - 联合是最优选择，兼顾效率与灵活性。

### 📌 图2：堆栈的概念与作用

#### ✅ 标题：

> **指令操作码与地址码**

#### 🔍 内容解析：

##### A. 堆栈的概念

(a) 是若干个存储单元（或寄存器）的有序集合，顺序存放一组元素。
(b) 数据只能在**栈顶单元**进行存取，即“进栈”和“出栈”都只通过栈顶这个“出入口”。
(c) 存取方式为 **“先进后出”（FILO）** 或 **“后进先出”（LIFO）**。

(a) **中断处理**中至关重要：

- 保存“断点”（当前程序计数器 PC 的值）
- 保存“现场”（如寄存器状态）
- 中断返回时恢复这些信息

(b) 实现：

- 程序调用
- 子程序嵌套调用
- 递归调用（函数调用自身）

✅ **核心理解**：

> 堆栈是一种特殊的内存结构，支持 LIFO 操作，广泛应用于控制流管理（中断、函数调用）。

> ✅ 结果：AX 和 BX 内容交换完成！

### ✅ 支持的操作数类型：

- 寄存器与寄存器之间（如 `XCHG AX, BX`）
- 寄存器与存储器之间（如 `XCHG AX, [BUF]`）

> ❌ 不支持：

- 存储器与存储器之间（如 `XCHG [BUF1], [BUF2]` 是非法的！）
- 立即数不能参与交换

> 💡 特点：

- **原子性**：一次完成交换，不会被中断干扰
- **高效**：比用 `MOV` + 中间寄存器快

## 🧩 图片2 & 3：**输入/输出指令 IN / OUT**

### ✅ 标题：

> **4、累加器专用传送指令：输入指令 IN / 输出指令 OUT**

### 🔹 功能概述：

> 实现 CPU 与 I/O 端口之间的数据传输。

- `IN`：从外部设备读取数据 → 送入 **累加器 AL 或 AX**
- `OUT`：将累加器中的数据 → 发送到外部设备

> ⚠️ 注意：**只能使用 AL 或 AX 作为数据通道！**

------

### 🔹 指令格式：

表格



| 指令 | 格式               |
| :--- | :----------------- |
| 输入 | `IN acc, PORT/DX`  |
| 输出 | `OUT PORT/DX, acc` |

其中：

- `acc`：表示 `AL` 或 `AX`
- `PORT`：端口号（8位或16位）
- `DX`：用于间接寻址时存放端口地址

------

### 🔹 寻址方式：

表格



| 类型         | 描述                         | 可寻址范围                  |
| :----------- | :--------------------------- | :-------------------------- |
| **直接寻址** | 在指令中直接给出8位端口号    | 0 ～ 255（共256个端口）     |
| **间接寻址** | 使用 DX 寄存器指定16位端口号 | 0 ～ 65535（共65536个端口） |

------

### 🔹 示例说明：

asm

编辑







```
1IN AL, 09H        ; 从端口 09H 读取字节 → AL
2OUT 40H, AL       ; 将 AL 的内容写入端口 40H
3IN DX, 0600H      ; 从端口 0600H 读取字 → DX
4OUT DX, AX        ; 将 AX 的内容写入由 DX 指定的端口
```

> 📌 解释：

- 第一条：`IN AL, 09H` —— 直接寻址，读端口 09H 到 AL
- 第二条：`OUT 40H, AL` —— 直接寻址，写 AL 到端口 40H
- 第三条：`IN DX, 0600H` —— 先把 0600H 放入 DX，再读该端口到 DX
- 第四条：`OUT DX, AX` —— 把 AX 的值写入 DX 指定的端口

------

### 🔹 注意事项（重点！）：

1. ✅ 

   输入/输出指令只能使用 AL 或 AX 接收或发送数据。

   - ❌ 如 `IN BX, 09H` 是非法的！

2. ✅ 

   使用短格式指令（直接寻址），必须将端口地址放入 DX 中。

   - 例如：`IN DX, 0600H` 表示“从 DX 指向的端口读取”，所以 DX 必须先赋值为 0600H

3. ✅ **输入/输出指令不影响标志位。**

## 🧩 图片4：**有效地址传送指令 LEA**

### ✅ 标题：

> **(1) 有效地址传送指令 LEA**

### 🔹 语句格式：

asm

编辑







```
1LEA OPD, OPS
```

- `OPD`：目的操作数（通常是寄存器）
- `OPS`：源操作数（内存变量或表达式）

### 🔹 功能：

> 计算 `OPS` 所在的**偏移地址（有效地址 EA）**，并将这个地址送入 `OPD` 寄存器。

> ⚠️ 关键点：不是取内容，而是取**地址**！

> 即：
>
> text
>
> 编辑
>
> 
>
> 
>
> 
>
> ```
> 1(OPD) ← 偏移地址 of OPS
> ```

### 🔍 示例解析：

已知 `(DS) = 2000H`，执行以下代码：

asm

编辑







```
1MOV BX, 0100H     ; (BX) = 0100H
2MOV SI, 0210H     ; (SI) = 0210H
3LEA BX, 1234H[BX+SI] ; (BX) = ?
```

> 计算过程：

- 偏移地址 = `BX + SI + 1234H` = `0100H + 0210H + 1234H` = `1544H`
- 所以 `(BX)` ← `1544H`

> ✅ 最终结果：`BX = 1544H`

> 💡 这相当于：

asm

编辑







```
1MOV BX, OFFSET 1234H[BX+SI]
```

### 🔹 补充知识：

- `LEA BX, NUM` 与 `MOV BX, OFFSET NUM` 效果相同
- 都是将变量 `NUM` 的**偏移地址**送入 BX

> ⚠️ 区别于 `MOV BX, NUM`：后者是取数值，前者是取地址！

## 🧩 图片1：加法指令 ADD 与 ADC

### ✅ 标题：

> **1. 加法指令**

### 🔹 (1) 加法指令 `ADD`

#### ▶️ 指令格式：

asm

编辑







```
1ADD DST, SRC
```

- 功能：将源操作数 `SRC` 加到目的操作数 `DST` 上。
- 即：`(DST) ← (DST) + (SRC)`
- **不影响 CF（进位标志）？** ❌ 实际上它会影响！

> ⚠️ 关键点：
> 执行后，根据结果设置标志位：
>
> - **CF**：最高位是否有进位（无符号溢出）
> - **OF**：有符号溢出（同号相加得异号）
> - **ZF**：结果是否为0
> - **SF**：结果符号位（最高位）
> - **AF**：低4位是否有进位（半进位）
> - **PF**：结果中1的个数是否为偶数

> 💡 教师手写注释：“源 + 目 → 目”，强调是“目的操作数”被更新。

------

### 🔹 (2) 带进位加法指令 `ADC`

#### ▶️ 指令格式：

asm

编辑







```
1ADC DST, SRC
```

- 功能：把 `SRC` 和当前 **CF 标志位的值（0 或 1）一起加到 DST 上**
- 即：`(DST) ← (DST) + (SRC) + CF`

> ✅ 应用场景：实现**多字节加法**（例如双字加法）

#### 🔍 示例分析：无符号双字加法

asm

编辑







```
1MOV AX, 4652H     ; (AX) = 4652H
2ADD AX, 0F0FOH    ; (AX) = 4652H + 0F0FOH = 3742H, CF=1 （因为有进位）
3MOV DX, 0234H     ; (DX) = 0234H
4ADC DX, 0F0FOH    ; (DX) = 0234H + 0F0FOH + CF(1) = 0F325H, CF=0
```

> ✅ 解读：

- 第一次加法：`4652H + F0F0H = 13742H`，但 AX 只能存 16 位 → 低位 3742H 存入 AX，高位进位使 CF=1
- 第二次带进位加法：`0234H + F0F0H + 1 = F325H`，没有更高位进位 → CF=0

> 🎯 这样就实现了两个 32 位数（DX:AX）的加法！

## 🧩 图片2：`ADD AX, CX` 的标志位分析

### ✅ 题目：

> 分析以下指令执行后 AX、CX 寄存器和标志寄存器中各状态位的值。

asm

编辑







```
1ADD AX, CX
```

### 🔹 初始值：

- `(AX) = 022AH`
- `(CX) = 14E8H`

### 🔹 二进制计算过程：

text

编辑







```
1       0000 0010 0010 1010   B   → 022A H
2+      0001 0100 1110 1000   B   → 14E8 H
3---------------------------------
4       0001 0111 0001 0010   B   → 1712 H
```

> ✅ 结果：`(AX) = 1712H`，`(CX)` 不变（仍为 14E8H）

### 🔹 各标志位分析：

表格



| 标志位 | 含义              | 判断依据                                   | 值    |
| :----- | :---------------- | :----------------------------------------- | :---- |
| **CF** | 最高位进位        | 无进位                                     | **0** |
| **AF** | 低四位进位        | 低四位：`1010 + 1000 = 10010` → 有进位     | **1** |
| **ZF** | 结果是否为0       | 结果 ≠ 0                                   | **0** |
| **SF** | 符号位（最高位）  | 最高位为0（正数）                          | **0** |
| **PF** | 1的个数是否为偶数 | 结果 `1712H` 的二进制中有 **6个1**（偶数） | **1** |
| **OF** | 有符号溢出        | 两正数相加结果仍是正数，无溢出             | **0** |

> ✅ 总结：
> 执行后：
>
> - `(AX) = 1712H`
> - `(CX) = 14E8H`
> - 标志位：`CF=0, AF=1, SF=0, ZF=0, PF=1, OF=0`

已知 `CF = 1`

asm

编辑

## 🧩 图片6：比较指令 CMP

### ✅ 指令格式：

asm

编辑







```
1CMP OPD, OPS
```

- 功能：执行 `(OPD) - (OPS)`，但**不保存结果**
- **只影响标志位**，用于后续条件转移判断

> 💡 类似 `SUB`，但不回送差值

#### 🔍 示例：

asm

编辑







```
1CMP AL, 50      ; (AL) - 50，仅影响标志位
2JB BELOW        ; 若 (AL) < 50，则跳转到 BELOW
3SUB AL, 50      ; 若 (AL) >= 50，则做减法
4INC AH          ; 并增加 AH
5BELOW:
```

> ✅ 工作流程：

1. `CMP AL, 50` → 计算 AL - 50，设标志位
2. 如果 AL < 50，则 CF=1，执行 `JB BELOW`
3. 否则继续执行 `SUB AL, 50` 等语句

> ✅ 常见条件转移指令配合使用：
>
> 表格
>
> 
>
> | 条件 | 指令        | 说明              |
> | :--- | :---------- | :---------------- |
> | 小于 | `JB` / `JL` | 无符号/有符号小于 |
> | 大于 | `JA` / `JG` | 无符号/有符号大于 |
> | 等于 | `JE` / `JZ` | 相等或零          |

### **1. 乘法指令（MUL 和 IMUL）**

#### （1）无符号数乘法指令 `MUL`

- **功能**：实现两个无符号数相乘。

- 格式

  ：

  ```
  MUL src
  ```

  - `src` 可以是寄存器或存储单元，但不能使用立即数或段寄存器。

- 操作方式

  ：

  - 字节乘法：`(AL) * (src)` → `AX`
  - 字乘法：`(AX) * (src)` → `DX:AX`（高字在 DX，低字在 AX）

- 注意

  ：

  - 被乘数默认在 `AL` 或 `AX` 中。
  - 只影响标志位 `CF` 和 `OF`。

> 示例：

asm

编辑







```
1MOV AL, 0B4H
2MOV BL, 11H
3MUL BL    ; 结果：AX = 0F74H
```

#### （2）有符号数乘法指令 `IMUL`

- **功能**：对带符号二进制数进行乘法运算。
- **格式**：`IMUL SRC`
- **操作方式与 MUL 类似**，但处理的是补码表示的有符号数。
- **结果不同**：因为要考虑符号位。

> 示例：

asm

编辑







```
1MOV AL, 0B4H   ; AL = -76（补码）
2MOV BL, 11H    ; BL = 17
3IMUL BL        ; AX = 0FAF4H（负数结果）
```

### **2. 除法指令（DIV 和 IDIV）**

#### （1）无符号除法指令 `DIV`

- **格式**：`DIV OPS`

- 功能

  ：

  - 字节除法：`(AX)/(OPS)` → 商在 `AL`，余数在 `AH`
  - 字除法：`(DX,AX)/(OPS)` → 商在 `AX`，余数在 `DX`

- **注意**：若除数为0或商溢出，会触发0号中断。

> 示例：计算 `0400H / 0B4H`

asm

编辑







```
1MOV AX, 0400H
2MOV BL, 0B4H
3DIV BL     ; AL = 05H（商），AH = 7CH（余数）
```

#### （2）有符号除法指令 `IDIV`

- **格式**：`IDIV OPS`

- **功能**：同 DIV，但用于有符号数。

- 特点

  ：

  - 余数的符号与被除数相同。
  - 也支持字节和字操作。

> 示例：`0400H / 0B4H`（有符号）

asm

编辑







```
1MOV AX, 0400H
2MOV BX, 0B4H
3IDIV BX     ; AL = 0F3H（商），AH = 24H（余数）
```

### **3. 符号扩展指令**

为了将较小的数据类型（如字节）扩展为更大的类型（如字或双字），需要保留符号位，否则会导致错误。

#### （1）字节转字：`CBW`

- 功能

  ：将 

  ```
  AL
  ```

   的符号位扩展到 

  ```
  AH
  ```

  。

  - 若 `AL` 最高位为0（正数），则 `AH = 00H`
  - 若 `AL` 最高位为1（负数），则 `AH = FFH`

- **格式**：`CBW`

- **示例**：

asm

编辑







```
1MOV AL, 0A5H     ; AL = A5H (负数)
2CBW              ; AX = FFA5H
3ADD AL, 70H      ; AL = 25H
4CBW              ; AX = 0025H（正数）
```

#### （2）字转双字：`CWD`

- 功能

  ：将 

  ```
  AX
  ```

   的符号位扩展到 

  ```
  DX
  ```

  。

  - 正数 → `DX = 0000H`
  - 负数 → `DX = FFFFH`

- **格式**：`CWD`

- **示例**：

asm

编辑







```
1MOV AX, 0FA48H   ; AX = FA48H（负数）
2CWD              ; DX = FFFFH
```

> ⚠️ 注意：这两条指令都不带操作数，只能作用于累加器中的隐含数据。

### **4. 十进制调整指令（BCD码相关）**

BCD码是一种用二进制编码的十进制数，分为两种形式：

表格



| 类型        | 描述                                                         |
| :---------- | :----------------------------------------------------------- |
| 压缩BCD码   | 每个字节包含两位十进制数，共4位一组（例如：`59H` 表示 5 和 9） |
| 非压缩BCD码 | 每个字节只表示一位十进制数，低位4位有效，高位无效            |

由于 BCD 码只用了 16 种组合中的 10 种（0～9），其余为“无效码”，因此在运算后必须进行**十进制调整**。

------

#### （1）压缩BCD码调整指令

- 加法调整

  ：

  ```
  DAA
  ```

  （Decimal Adjust after Addition）

  - 功能：把 `AL` 中的和调整为合法的压缩BCD码。
  - 规则：
    1. 若 `AL` 低4位 > 9 或 `AF=1` → 加 `06H`
    2. 若 `AL` 高4位 > 9 或 `CF=1` → 加 `60H`
    3. 若两者都满足 → 加 `66H`

> 示例：`59 + 68 = 127`

text

编辑







```
1  59  → 0101 1001
2+ 68  → 0110 1000
3-------
4 127  → 1100 0001（非法！）
5+ 0110 0110（66H）
6-------
7   1  0010 0111 → 127（正确）
```

- 减法调整

  ：

  ```
  DAS
  ```

  （Decimal Adjust after Subtraction）

  - 类似 DAA，但改为减 `06H` 或 `60H`。

> ⚠️ 注意：`DAA` 和 `DAS` 必须紧跟在 `ADD`/`ADC` 或 `SUB`/`SBB` 后使用，且不影响 `OF` 标志。

------

#### （2）非压缩BCD码调整指令

- 加法调整

  ：

  ```
  AAA
  ```

  （ASCII Adjust after Addition）

  - 数据放在 `AH`（高位）、`AL`（低位）

  - 功能：

    - 如果 

      ```
      AL
      ```

       低4位 > 9 或 

      ```
      AF=1
      ```

      ：

      - `AL += 6`
      - `AH += 1`
      - `AF = CF = 1`
      - 清零 `AL` 高4位

    - 否则：

      - `CF = AF = 0`
      - 清零 `AL` 高4位

> 示例：

asm

编辑







```
1MOV AL, 0FH    ; AL = 0000 1111
2MOV AH, 00H
3ADD AL, 0BH    ; AL = 0001 1000 (18)
4AAA            ; AL = 0000 0010, AH = 0000 0001 → 结果为 12
```

------

## 一、逻辑指令（Logic Instructions）

逻辑指令对字节或字数据进行按位的运算操作。

### 1. 逻辑与（AND）

- **指令格式**：`AND DST, SRC`

- **功能**：`(DST) ← (DST) ∧ (SRC)`（按位与）

- 标志影响

  ：

  - `CF = OF = 0`
  - 影响 `SF`（符号标志）、`ZF`（零标志）、`PF`（奇偶标志）
  - `AF`（辅助进位标志）无定义

> ✅ 注：`AND` 是基本的按位与操作，常用于屏蔽某些位。

------

### 2. 逻辑或（OR）

- **指令格式**：`OR DST, SRC`
- **功能**：`(DST) ← (DST) ∨ (SRC)`
- **标志影响**：同 `AND` 指令（即影响 SF、ZF、PF，CF=OF=0）

> ✅ 注：`OR` 常用于设置某几位为 1。

------

### 3. 逻辑非（NOT）

- **指令格式**：`NOT OPR`
- **功能**：`(OPR) ← ¬(OPR)`（按位取反）
- **标志影响**：不改变任何标志位

> ✅ 注：仅对操作数本身取反，不影响标志寄存器。

------

### 4. 异或（XOR）

- **指令格式**：`XOR DST, SRC`
- **功能**：`(DST) ← (DST) ⊕ (SRC)`
- **标志影响**：同 `AND`

> ✅ 注：`XOR` 可用于清零（如 `XOR AX, AX`），也可用于比较、加密等。

------

### 5. 测试（TEST）

- **指令格式**：`TEST OPR1, OPR2`
- **功能**：执行 `(OPR1) ∧ (OPR2)` 的按位与操作
- **结果处理**：不保存结果，只根据结果设置条件标志（SF、ZF、PF 等）
- **用途**：判断某位是否为 1，常用于条件跳转前的检测

> ✅ 注：相当于“只做 AND 不存结果”。

------

## 二、移位指令（Shift Instructions）

移位指令分为：

- **方向**：左移 / 右移
- **类型**：逻辑移位 / 算术移位 / 循环移位
- **次数**：一次移位 / 多次移位（由 CL 寄存器指定）

------

### （1）逻辑左移（SHL）

- **指令格式**：`SHL OPD, 1` 或 `SHL OPD, CL`

- 功能

  ：

  - 将操作数向左移动指定位数
  - 最高位移入 CF（进位标志）
  - 低位补 0

- 示例分析

  ：

  asm

  编辑

  

  

  

  ```
  1MOV BL, 4        ; (BL) = 00000100B
  2MOV CL, 2
  3SHL BL, CL       ; 左移 2 位 → (BL) = 00010000B = 16H
  ```

  结果：

  ```
  BL = 16
  ```

  ，相当于乘以 

  2222

  。

- **注意**：可能溢出！

------

### （2）算术左移（SAL）

- **指令格式**：`SAL OPD, 1` 或 `SAL OPD, CL`
- **功能**：与 `SHL` 完全相同
- **说明**：虽然名字叫“算术”，但行为和逻辑左移一致

> ⚠️ 注意：在 x86 中，`SAL` 和 `SHL` 是完全等价的，只是命名不同。

------

### （3）逻辑右移（SHR）

- **指令格式**：`SHR OPD, 1` 或 `SHR OPD, CL`

- 功能

  ：

  - 向右移动指定位数
  - 最低位移入 CF
  - 高位补 0

- **适用场景**：无符号数除以 2 的幂次

------

### （4）算术右移（SAR）

- **指令格式**：`SAR OPD, 1` 或 `SAR OPD, CL`

- 功能

  ：

  - 向右移动指定位数
  - 最低位移入 CF
  - **最高位保持不变**（即符号位不变）

- **特点**：适用于有符号数的除法（保留符号）

- **图示说明**：最高位循环填充，保证负数仍为负数

> ✅ 示例：若原数为负（最高位为 1），右移后仍为负。

------

### （5）循环左移（ROL）

- **指令格式**：`ROL OPD, 1` 或 `ROL OPD, CL`

- 功能

  ：

  - 向左移动指定位数
  - 最高位同时进入最低位和 CF

- 示例

  ：

  asm

  编辑

  

  

  

  ```
  1MOV AX, 1234H    ; AX = 0001001000110100B
  2MOV CL, 8
  3ROL AX, CL       ; 左移 8 位 → 高低字节交换
  ```

  结果：

  ```
  AX = 3412H
  ```

- **用途**：字节交换、位重组

------

### （6）循环右移（ROR）

- **指令格式**：`ROR OPD, 1` 或 `ROR OPD, CL`

- 功能

  ：

  - 向右移动指定位数
  - 最低位进入最高位和 CF

- **用途**：类似 ROL，但方向相反

------

### （7）带进位的循环左移（RCL）

- **指令格式**：`RCL OPD, 1` 或 `RCL OPD, CL`

- 功能

  ：

  - 将操作数连同 CF 标志一起向左循环移位
  - 即：CF → 最低位，其余位左移，最高位 → CF

- **用途**：实现多位移位、数据串行传输

------

### （8）带进位的循环右移（RCR）

- **指令格式**：`RCR OPD, 1` 或 `RCR OPD, CL`

- 功能

  ：

  - 将操作数连同 CF 标志一起向右循环移位
  - 即：CF ← 最低位，其余位右移，最高位 ← CF

- **用途**：多字节移位、大数运算、CRC 计算等

------

## 总结对比表（关键点）

表格



| 指令         | 类型       | 补位方式     | 是否影响 CF | 特点                    |
| :----------- | :--------- | :----------- | :---------- | :---------------------- |
| `SHL`, `SAL` | 左移       | 低位补 0     | 是          | 相当于乘以 2^n          |
| `SHR`        | 右移       | 高位补 0     | 是          | 无符号除以 2^n          |
| `SAR`        | 右移       | 高位补符号位 | 是          | 有符号除以 2^n          |
| `ROL`, `ROR` | 循环       | 两端相连     | 是          | 位循环                  |
| `RCL`, `RCR` | 带进位循环 | 包含 CF      | 是          | 支持跨寄存器/多字节操作 |

## 教学重点提炼

1. **逻辑指令**主要用于位级操作，如掩码、设置、清零、测试等。

2. 移位指令

   广泛应用于：

   - 快速乘除（左移 ×2，右移 ÷2）
   - 数据打包/解包
   - 位操作优化
   - 算法中的位处理（如哈希、加密）

3. **标志位变化**非常重要，尤其在条件跳转中。

4. **循环移位 + CF** 能实现更复杂的位操作，比如将一个字的高位移到另一个寄存器的低位。

## 实际应用建议

- 使用 `SHL` 实现快速乘法（避免使用乘法指令）
- 使用 `SAR` 实现有符号整数除法
- 使用 `ROL/ROR` 进行字节交换或位旋转
- 使用 `RCL/RCR` 实现多字节数据的串行移位（如通信协议）

## 🎯 教学主题：串操作指令（String Instructions）

### 一、与 `REP` 配合工作的指令

#### （1）`REP` 重复串操作

- **作用**：前置前缀，用于控制串操作指令的重复次数。

- 执行逻辑

  ：

  - 每次执行一条串指令后，`(CX) ← (CX) - 1`
  - 当 `(CX) = 0` 时停止重复

- **使用场景**：常用于批量数据传输或初始化

- 示例

  ：

  asm

  编辑

  

  

  

  ```
  1REP MOVSB   ; 将源串中 CX 个字节复制到目的串
  ```

> ✅ 注意：`REP` 只能与 `MOVSB/W`, `STOSB/W`, `LODSB/W` 等串指令配合使用。

------

#### （2）`MOVSB` / `MOVSW` —— 字符串传送指令

表格



| 指令    | 类型   | 功能                              |
| :------ | :----- | :-------------------------------- |
| `MOVSB` | 字节级 | 将 `[SI]` 指向的字节传送到 `[DI]` |
| `MOVSW` | 字级   | 将 `[SI]` 指向的字传送到 `[DI]`   |

##### 功能详解：

- 数据从 **源地址 DS:SI** 传送到 **目标地址 ES:DI**

- 自动更新指针：

  - 若 

    ```
    DF = 0
    ```

    （方向标志为0），则 SI 和 DI 

    递增

    - 字节：+1；字：+2

  - 若 `DF = 1`，则 SI 和 DI **递减**

> 🔁 示例：

asm

编辑







```
1MOV SI, OFFSET source
2MOV DI, OFFSET dest
3MOV CX, 10
4REP MOVSB   ; 复制10个字节
```

------

#### （3）`STOSB` / `STOSW` —— 存入串指令

表格



| 指令    | 类型 | 功能                  |
| :------ | :--- | :-------------------- |
| `STOSB` | 字节 | 把 AL 的值存入 `[DI]` |
| `STOSW` | 字   | 把 AX 的值存入 `[DI]` |

##### 功能详解：

- 将寄存器中的值写入由 DI 指向的目的串
- 修改 DI 指针：
  - `DF=0` → DI 增量（+1 或 +2）
  - `DF=1` → DI 减量
- **不改变 SI**，因为没有读取源数据

> 💡 应用：内存清零、填充数组

asm

编辑







```
1MOV AX, 0
2MOV CX, 100
3REP STOSW   ; 用0填充100个字的空间
```

#### （4）`LODSB` / `LODSW` —— 从源串取数指令

表格



| 指令    | 类型 | 功能                      |
| :------ | :--- | :------------------------ |
| `LODSB` | 字节 | 把 `[SI]` 中的字节送入 AL |
| `LODSW` | 字   | 把 `[SI]` 中的字送入 AX   |

##### 功能详解：

- 从 DS:SI 指向的位置读取数据
- 数据进入 AL 或 AX
- 更新 SI 指针：
  - `DF=0` → SI 增量
  - `DF=1` → SI 减量

> 💡 应用：遍历字符串或数组

asm

编辑







```
1MOV SI, OFFSET array
2MOV CX, 5
3LODSB       ; 读第一个字节到 AL
4; ...
```

### 二、与 `REPE/REPZ` 和 `REPNE/REPNZ` 联合工作的指令

这类指令结合 **条件判断** 来决定是否继续重复，常用于字符串比较和查找。

#### （1）`REPE/REPZ` —— 相等时重复

- **含义**：只要两个操作数相等（ZF=1），就继续执行
- **终止条件**：当 `(CX)=0` 或 `ZF=0`（即不相等）时结束

> ✅ 用途：字符串匹配、查找连续相同字符

#### （2）`REPNE/REPNZ` —— 不相等时重复

- **含义**：只要两个操作数不相等（ZF=0），就继续执行
- **终止条件**：当 `(CX)=0` 或 `ZF=1`（即相等）时结束

> ✅ 用途：查找某个特定值在数组中的位置

------

#### （3）`CMPSB` / `CMPSW` —— 串比较指令

表格



| 指令    | 类型 | 功能                         |
| :------ | :--- | :--------------------------- |
| `CMPSB` | 字节 | 比较 `[SI]` 与 `[DI]` 的字节 |
| `CMPSW` | 字   | 比较 `[SI]` 与 `[DI]` 的字   |

##### 功能详解：

- 执行 `(DS:SI) - (ES:DI)` 并设置标志位（ZF, SF, OF 等）
- **结果不保存**，只影响标志位
- 更新 SI 和 DI：
  - `DF=0` → 增量
  - `DF=1` → 减量

> 🔁 示例：

asm

编辑







```
1MOV SI, OFFSET str1
2MOV DI, OFFSET str2
3MOV CX, 10
4REPE CMPSB   ; 如果所有字节都相等，则继续
5; 若提前发现不等，ZF=0，循环停止
```

------

#### （4）`SCASB` / `SCASW` —— 串扫描指令

表格



| 指令    | 类型 | 功能              |
| :------ | :--- | :---------------- |
| `SCASB` | 字节 | 比较 AL 与 `[DI]` |
| `SCASW` | 字   | 比较 AX 与 `[DI]` |

##### 功能详解：

- 将 AL/AX 与 `[DI]` 中的数据做减法比较
- 设置标志位，但不保存结果
- 更新 DI：
  - `DF=0` → DI 增量
  - `DF=1` → DI 减量

> 🔁 示例：

asm

编辑







```
1MOV AL, 'A'
2MOV DI, OFFSET buffer
3MOV CX, 100
4REPNE SCASB   ; 查找字符'A'，直到找到或CX=0
5; 若找到，则ZF=1，DI指向该位置
```

## 🎯 主题：**控制转移指令（Control Transfer Instructions）**

### 一、无条件转移指令（Unconditional Jump）

> ✅ 功能：不依赖任何条件，直接改变程序执行顺序。
>
> ❌ 特点：不影响标志位（CF, ZF, SF, OF 等）

#### （1）段内转移指令（Intra-segment Jump）

表格



| 类型         | 指令格式                        | 功能说明                                                     |
| :----------- | :------------------------------ | :----------------------------------------------------------- |
| **短转移**   | `JMP SHORT OPR`                 | 跳转范围 ±128 字节，使用 **8位带符号位移量** `(IP) ← (IP) + 8位位移量` |
| **近转移**   | `JMP NEAR PTR OPR`              | 跳转范围 ±32K 字节，使用 **16位带符号位移量** `(IP) ← (IP) + 16位位移量` |
| **间接转移** | `JMP WORD PTR OPR` 或 `JMP OPR` | 使用寄存器或内存单元中的值作为有效地址 EA `(IP) ← (EA)`      |

##### 示例：

asm

编辑







```
1JMP SHORT label     ; 短跳转到标号 label
2JMP NEAR PTR [BX]   ; 从 BX 指向的地址取偏移量
3JMP BX              ; 将 BX 中的值作为新 IP 值
```

> 🔍 注意：`WORD PTR` 是类型限定符，表示操作数是一个字（16位），用于明确寻址方式。

#### （2）段间转移指令（Inter-segment Jump）

表格



| 类型           | 指令格式            | 功能说明                                                     |
| :------------- | :------------------ | :----------------------------------------------------------- |
| **远直接转移** | `JMP FAR PTR OPR`   | 改变 CS 和 IP - `(IP) ← OPR 的段内偏移` - `(CS) ← OPR 的段地址` |
| **远间接转移** | `JMP DWORD PTR OPR` | 从内存中读取一个双字（4字节）： - 低16位 → IP - 高16位 → CS  |

##### 示例：

asm

编辑







```
1JMP FAR PTR next_seg    ; 跳到另一个代码段
2JMP DWORD PTR [SI]      ; SI 指向的内存处存放了新的 CS:IP
```

> ⚠️ 区别：

- `FAR PTR`：目标地址由指令显式给出（如标签）
- `DWORD PTR`：目标地址从内存中获取（间接）

### 二、条件转移指令（Conditional Jump）

> ✅ 功能：根据前一条指令设置的**状态标志位**决定是否跳转。
>
> 💡 常用标志位：ZF（零标志）、SF（符号标志）、CF（进位标志）、OF（溢出标志）、PF（奇偶标志）
>
> 📌 所有条件转移都是 **相对寻址、双字节指令**，只能实现 **段内短转移（±128 字节）**

#### （1）基于单个标志位的转移（共10条）

表格



| 指令              | 条件                      | 对应标志位 |
| :---------------- | :------------------------ | :--------- |
| `JZ / JE`         | 结果为零（相等）          | ZF = 1     |
| `JNZ / JNE`       | 结果不为零（不相等）      | ZF = 0     |
| `JS`              | 结果为负                  | SF = 1     |
| `JNS`             | 结果为正                  | SF = 0     |
| `JO`              | 溢出                      | OF = 1     |
| `JNO`             | 无溢出                    | OF = 0     |
| `JP / JPE`        | 奇偶位为1（偶数个1）      | PF = 1     |
| `JNP / JPO`       | 奇偶位为0（奇数个1）      | PF = 0     |
| `JB / JNAE / JC`  | 低于/不高于或等于/进位为1 | CF = 1     |
| `JNB / JAE / JNC` | 不低于/高于或等于/进位为0 | CF = 0     |

> ✅ `JE` 和 `JNE` 是常用比较后跳转的指令，常用于 `CMP` 后判断是否相等。

#### （2）无符号数比较转移（基于 CF 和 ZF）

这类指令适用于 **无符号整数比较**（例如：`0x10 < 0xFF`）

表格



| 指令              | 条件  | 标志位组合   |
| :---------------- | :---- | :----------- |
| `JB / JNAE / JC`  | A < B | CF=1 且 ZF=0 |
| `JNB / JAE / JNC` | A ≥ B | CF=0 或 ZF=1 |
| `JBE / JNA`       | A ≤ B | CF=1 或 ZF=1 |
| `JNBE / JA`       | A > B | CF=0 且 ZF=0 |

> 🔍 例子：

asm

编辑







```
1CMP AX, BX
2JB less_than        ; 如果 AX < BX，则跳转
3JA greater_than     ; 如果 AX > BX，则跳转
```

#### （3）带符号数比较转移（基于 SF、ZF、OF）

这类指令适用于 **有符号整数比较**（例如：-5 < 3）

表格



| 指令        | 条件  | 说明                          |
| :---------- | :---- | :---------------------------- |
| `JL / JNGE` | A < B | SF ≠ OF（即符号位与溢出不符） |
| `JNL / JGE` | A ≥ B | SF = OF                       |
| `JLE / JNG` | A ≤ B | ZF=1 或 SF ≠ OF               |
| `JNLE / JG` | A > B | ZF=0 且 SF = OF               |

> 🔍 关键点：
>
> - 使用 `CMP` 指令后，通过 `JL`, `JG` 判断带符号数大小关系
> - 这些指令利用了 **符号扩展和溢出检测** 的原理

#### （4）测试 CX 是否为零的转移指令

表格



| 指令       | 功能                                 |
| :--------- | :----------------------------------- |
| `JCXZ OPR` | 若 `(CX) == 0`，则跳转；否则顺序执行 |

> 💡 应用场景：在循环开始前检查计数器是否已归零，避免空循环。

### 三、循环控制指令（Loop Control Instructions）

共有三条，均以寄存器 **CX** 作为计数器，自动递减并判断是否继续循环。

表格



| 指令                  | 功能              | 条件                                 |
| :-------------------- | :---------------- | :----------------------------------- |
| `LOOP OPR`            | 循环              | `(CX) ≠ 0` 时跳转，`(CX) = 0` 时结束 |
| `LOOPE / LOOPZ OPR`   | 相等/为零循环     | `(ZF = 1) AND (CX ≠ 0)`              |
| `LOOPNE / LOOPNZ OPR` | 不相等/不为零循环 | `(ZF = 0) AND (CX ≠ 0)`              |

> 🔧 执行过程：

asm

编辑







```
1LOOP:
2    ... 处理代码 ...
3    DEC CX          ; 自动完成
4    JMP OPR         ; 若 CX≠0，则跳回
```

> ⚠️ 注意事项：

- 必须先给 **CX** 设置初始值（如 `MOV CX, 10`）
- 每次执行循环指令会自动将 `(CX) ← (CX) - 1`
- 不影响标志位
- 通常用于数组遍历、数据块处理等

## 📌 核心知识点提炼

### 1. **标志位的作用**

- **ZF**: 判断是否为零（相等）
- **SF**: 判断正负（符号）
- **CF**: 判断无符号比较结果（借位/进位）
- **OF**: 判断有符号溢出
- **PF**: 判断奇偶性（用于校验）

## 🎯 主题：**程序控制指令（Program Control Instructions）**

------

### 一、子程序调用及返回指令

> ✅ 功能：实现代码的模块化设计，提高可读性和复用性
> 🔍 子程序（也称过程）：具有独立功能的程序段，由主程序调用执行

#### ▶️ 调用方式分类

- **段内调用**（同一代码段）
- **段间调用**（不同代码段）
- **直接调用**（地址明确给出）
- **间接调用**（地址从寄存器或内存获取）

#### （1）调用指令 `CALL`

##### 格式：

asm

编辑







```
1CALL DST
```

其中 `DST` 可以是立即数、寄存器、内存地址等。

###### ① 段内直接调用（NEAR CALL）

- 指令格式：`CALL NEAR PTR SUBR` 或 `CALL 3000H`

- 执行动作：

  - 将当前 **IP 值压入堆栈**（保存返回地址）
  - `(SP) ← (SP) - 2`
  - `(IP) ← DST`（跳转到目标地址）

- 示例：

  asm

  编辑

  

  

  

  ```
  1CALL 3000H        ; 直接跳转到偏移量 3000H
  2CALL NEAR PTR SUBR; 调用名为 SUBR 的近过程
  ```

> 💡 `NEAR PTR` 是类型限定符，表示这是一个段内调用（仅改变 IP）

###### ② 段内间接调用

- 格式：`CALL WORD PTR [BX]` 或 `CALL DWORD PTR [SI]`

- 作用：从内存中取出一个字（或双字）作为目标地址

- 示例：

  asm

  编辑

  

  

  

  ```
  1MOV BX, OFFSET SUBR
  2CALL WORD PTR [BX]   ; 间接调用
  ```

> ⚠️ 注意：`WORD PTR` 表示取的是一个16位地址（只改 IP），`DWORD PTR` 表示取的是32位地址（改 CS 和 IP）

#### （2）返回指令 `RET`

##### 格式：

asm

编辑







```
1RET
```

- 功能：从堆栈中弹出保存的返回地址，恢复主程序执行流程

- 执行动作：

  - `(IP) ← (SS:SP)`（从堆栈读取返回地址）
  - `(SP) ← (SP) + 2`

- 示例：

  asm

  编辑

  

  

  

  ```
  1SUBR PROC
  2    ; 子程序代码
  3    RET
  4SUBR ENDP
  ```

> 🔁 完整流程：
>
> text
>
> 编辑
>
> 
>
> 
>
> 
>
> ```
> 1主程序 → CALL → 压栈(IP) → 跳转 → 执行子程序 → RET → 弹栈 → 返回主程序
> ```

> ✅ 特点：
>
> - 不影响标志位
> - 必须与 `CALL` 配对使用
> - 支持嵌套调用（通过多层堆栈）

------

### 二、中断指令

> ✅ 功能：在程序运行过程中，响应外部事件或异常情况，临时中断当前任务，转去执行专门处理程序

#### ▶️ 中断类型

表格



| 类型         | 来源                       | 触发方式                       |
| :----------- | :------------------------- | :----------------------------- |
| **外部中断** | 外部设备（如键盘、定时器） | 通过硬件引脚（INTR）请求       |
| **内部中断** | CPU 内部指令               | 如 `INT`, `INTO`, `DIV` 错误等 |

#### （1）中断指令 `INT TYPE`

- 格式：`INT n`，其中 `n` 是中断类型号（0～255）

- 功能：

  - 自动将 **标志寄存器（FLAGS）**、**CS**、**IP** 压入堆栈
  - 根据中断向量表查找对应中断服务程序入口地址
  - 转移到该地址执行中断服务程序

- 示例：

  asm

  编辑

  

  

  

  ```
  1INT 21H    ; DOS 系统调用
  2INT 10H    ; BIOS 显示服务
  ```

> 🔍 中断向量表：位于内存 `0000:0000H` 开始的 1024 字节区域，每个中断占用 4 字节（CS:IP）

#### （2）溢出中断指令 `INTO`

- 格式：`INTO`
- 功能：当上一条指令导致 **OF=1**（有符号溢出）时，触发中断
- 应用于调试、数值范围检查

> 📌 示例：

asm

编辑







```
1ADD AX, BX
2INTO           ; 若发生溢出，则触发中断
```

#### （3）中断返回指令 `IRET`

- 格式：`IRET`
- 功能：
  - 从堆栈中依次弹出：
    - `IP`
    - `CS`
    - `FLAGS`
  - 恢复原程序状态，继续执行
- 使用场景：中断服务程序结尾处

> 🔁 流程：
>
> text
>
> 编辑
>
> 
>
> 
>
> 
>
> ```
> 1正常程序 → INT → 压栈(FLAGS, CS, IP) → 执行中断服务程序 → IRET → 弹栈 → 继续原程序
> ```

> ⚠️ 区别于 `RET`：
>
> - `RET`：仅恢复 IP（用于子程序）
> - `IRET`：恢复 IP、CS、FLAGS（用于中断）

------

### 三、其他处理器控制指令

这类指令主要用于控制 CPU 的运行状态，不涉及数据操作。

#### （1）空操作指令 `NOP`

- 格式：`NOP`
- 功能：
  - 单字节指令（机器码为 `90H`）
  - 不执行任何操作，仅占时间与空间
- 用途：
  - **延时**（多个 NOP 构成微小延迟）
  - **填充代码空间**
  - **调试时插入占位符**

> 💡 实际应用：

asm

编辑







```
1DELAY:
2    NOP
3    NOP
4    NOP
5    JMP DELAY     ; 形成简单循环延时
```

> ❗ 注意：`NOP` 不影响标志位

#### （2）停机指令 `HLT`

- 格式：`HLT`
- 功能：
  - 暂停 CPU 工作，进入停机状态
  - 只有当 **中断请求发生** 时才会唤醒
- 用途：
  - 等待外部事件（如键盘输入）
  - 低功耗模式（旧系统中）
  - 操作系统中的“空闲循环”逻辑

> 🔁 执行后：
>
> - CPU 停止取指
> - 等待中断信号
> - 中断到来后，执行中断服务程序，结束后继续执行下一条指令

> ⚠️ 注意：不是永久停止，而是等待中断

#### （3）等待指令 `WAIT`

- 格式：`WAIT`
- 功能：
  - 使 CPU 进入等待状态
  - 等待 **外部总线事务完成**（如协处理器通信）
  - 也可以用来等待外部中断
- 特点：
  - 不允许使用立即数或寄存器寻址
  - 执行后，CPU 暂停直到收到中断或协处理器就绪信号
  - 中断结束后，仍返回到 `WAIT` 指令处继续等待

> 🔄 示例：

asm

编辑







```
1WAIT
2; 等待协处理器完成计算
```

> 💡 区别于 `HLT`：
>
> - `HLT`：完全停止，直到中断唤醒
> - `WAIT`：持续等待，但可响应中断并返回原位置

### **1. 数据定义伪指令（Data Definition Pseudo-instructions）**

#### **作用：**

- 定义变量的数据类型。
- 给变量赋初值或仅分配存储空间。

#### **常用伪指令：**

表格



| 伪指令 | 含义                                   |
| :----- | :------------------------------------- |
| `DB`   | 定义字节（Byte），占1字节              |
| `DW`   | 定义字（Word），占2字节                |
| `DD`   | 定义双字（Double Word），占4字节       |
| `DF`   | 定义四字（Far），占6字节（用于远指针） |
| `DQ`   | 定义四倍字（Quad Word），占8字节       |
| `DT`   | 定义十倍字（Ten Byte），占10字节       |

> ⚠️ 注意：`DF` 是“远指针”（far pointer），在实模式下用于指向其他段的地址。

------

#### **示例解析：**

asm

编辑







```
1DATA    DB 1, 2H        ; 分配两个字节：01H 和 02H
2EXPR    DW 1, 2         ; 分配两个字：0001H 和 0002H
3STR     DB 'WELCOM!'    ; 字符串，每个字符占1字节，共7字节
4S1      DW 'AB'         ; 'A'=41H, 'B'=42H → 4142H（一个字）
5S2      DD 'AB'         ; 'A'=41H, 'B'=42H → 00004142H（四个字节）
6OFFAB   DW S1           ; 将S1的偏移地址存入OFFAB
```

#### **内存布局表解析：**

表格



| 存储单元名称 | 内存中的数据 | 内存地址 |
| :----------- | :----------- | :------- |
| DATA         | 01           | 0100H    |
|              | 02           | 0101H    |
| EXPR         | 01           | 0102H    |
|              | 00           | 0103H    |
|              | 02           | 0104H    |
|              | 00           | 0105H    |
| STR          | 57 (W)       | 0106H    |
|              | 45 (E)       | 0107H    |
|              | 4c (L)       | 0108H    |
|              | 43 (C)       | 0109H    |
|              | 4F (O)       | 010AH    |
|              | 4D (M)       | 010BH    |
|              | 21 (!)       | 010CH    |

> ✅ 说明：
>
> - 字符串 `'WELCOM!'` 每个字符按 ASCII 编码存储。
> - `DW` 定义时低字节在前（小端序），如 `DW 1,2` 实际为 `01 00 02 00`。

#### **高级用法（DUP）：**

表格



| 代码                            | 说明                                       |
| :------------------------------ | :----------------------------------------- |
| `FILLER DB ?`                   | 分配一个字节，不初始化（未知值）           |
| `BUFFER DB 10 DUP(?)`           | 分配10个字节，无初值                       |
| `ZERO DW 30 DUP(0)`             | 分配30个字（60字节），全部为0              |
| `MASK DB 5 DUP('OK!')`          | 重复字符串 "OK!" 5次                       |

> 💡 `DUP` 是非常强大的工具，常用于数组、缓冲区定义。

- `EQU`：等价于（不可重新定义）
- `=`：等号（可重定义，但少用）
- `LABEL`：标记标签

```

### ✅ 图1：**段跨越前缀（Segment Override Prefix）**

#### 🔹 内容解析：

> **标题：2）段跨越前缀**

- 定义

  ：

  > 段跨越前缀用于在访问内存时**显式指定使用哪个段寄存器的段地址**，而不是默认的段。

- 作用

  ：

  - 在实模式下，CPU 默认使用某些段寄存器来计算物理地址。
    - `DS` → 数据段
    - `SS` → 堆栈段
    - `CS` → 代码段
    - `ES` → 附加段（通常用于字符串操作）

- 示例

  ：

  asm

  编辑

  

  

  

  ```
  1MOV AX, ES:[BX + SI]
  ```

  - 这条指令表示：从**附加段（ES）**中，偏移地址为 `BX + SI` 的位置读取一个字（2字节），放入 `AX` 寄存器。

> 📌 物理地址 = 段地址 × 16 + 偏移地址

表格



| 概念   | 说明                              |
| :----- | :-------------------------------- |
| 默认段 | `DS` 是数据访问的默认段           |

| 用途   | 实现跨段访问、多段数据处理        |

>
> - 多个数据段共存时，需明确访问目标段。
> - 字符串操作常用 `ES:`，因为 `ES` 是字符串指令的目标段。

### ✅ 图2 & 图3：**过程定义伪指令（PROC / ENDP）**

  asm

表格



| 属性     | NEAR 过程                | FAR 过程                     |
| :------- | :----------------------- | :--------------------------- |

## 🧮 图4：**乘法运算优化 —— 使用移位+加法替代乘法**

### 🔹 问题：

给定 `(BX) = 00F8H`，计算 `(BX) * 10 → (BX)`。

### 🔹 分析：

由于没有直接的乘法指令（或效率低），可利用：

> **10 = 8 + 2 = 2³ + 2¹**
>
> 所以：
>
> text
>
> 编辑
>
> 
>
> 
>
> 
>
> ```
> 1BX * 10 = BX * 8 + BX * 2 = (BX << 3) + (BX << 1)
> ```

但题目中是：

> ```
> (BX) * 10 = (BX) * 8 + (BX) + (BX)
> ```
>
> 即：
>
> text
>
> 编辑
>
> 
>
> 
>
> 
>
> ```
> 1BX * 10 = (BX << 3) + BX + BX
> ```

所以可以这样实现：

asm

编辑







```
1MOV AX, BX        ; 保存原始值
2SHL BX, 3         ; 左移3位，即 *8
3ADD BX, AX        ; 加上原值
4ADD BX, AX        ; 再加上一次原值
```

> ✅ 最终：`(BX) = (BX) * 10`

## 📜 图5：**完整源程序示例**

asm

编辑







```
1STACK SEGMENT STACK
2    DB 200 DUP(?)
3STACK ENDS
4
5CODE SEGMENT
6    ASSUME CS:CODE, SS:STACK
7
8BEGIN:
9    MOV BX, 00F8H
10    MOV AX, BX        ; 保存原始数据
11    MOV CL, 3         ; 左移3次（*8）
12    SHL BX, CL        ; BX = BX * 8
13    ADD BX, AX        ; BX = BX * 8 + 原始值
14    ADD BX, AX        ; BX = BX * 8 + 原始值 + 原始值
15    MOV AH, 4CH       ; 准备退出
16    INT 21H           ; 结束程序
17
18CODE ENDS
19END BEGIN

## 🧩 图1：循环程序的基本概念

### 🔹 标题：

> **3 循环程序设计**

### 🔹 内容要点：

- 有时需要重复执行一组语句 → 这类程序称为**循环程序**。
- 分类方式：
  - 按结构分：**单重循环** vs **多重循环**
  - 按控制方法分：**计数型循环**（已知次数） vs **条件型循环**（未知次数）

### 🔹 核心结论：

无论哪种形式，所有循环程序都由以下四部分构成：

#### ✅ 四大组成部分：

1. **循环初始化部分**
   → 设置循环前的准备工作：如设置循环次数、初始值、地址指针等。

2. **工作部分（循环体）**
   → 需要重复执行的核心代码块。
   → 若包含嵌套循环，则为多重循环。

3. **修改部分**
   → 修改操作数地址或控制变量（如 `BX++`, `CX--`），确保每次循环处理不同数据。

4. 循环控制部分

   → 判断是否继续循环。

   - 若循环次数已知 → 使用 **计数型循环**（如 `LOOP` 指令）
   - 若未知 → 使用 **条件型循环**（如 `JNZ`, `JGE` 等）

## 💡 图2：存储器管理的对象

### 🔹 标题：

> **存储器管理的对象**

### 🔹 主要知识点：

- **存储管理（memory management）**：操作系统对存储器的管理。
- 内存与外存因物理特性不同，管理方式也不同。
- 内存分为两种：
  - **ROM**（只读存储器）：固化写入，不可更改，通常存放BIOS等系统程序
  - **RAM**（随机存取存储器）：可读可写，断电清零 → 是**操作系统管理的重点对象**
- 内存结构：
  - 可看作一个由**字或字节为单位**组成的数组
  - 每个存储单元都有唯一的**地址**
- 内存的作用：
  - 存储**指令**和**数据**
  - 程序执行时先加载到内存
  - CPU从内存取指令 → 分析 → 取操作数 → 执行 → 结果回写内存

> ✅ **结论**：操作系统中的“存储管理”主要是指对**RAM的管理**，包括分配、保护、共享、虚拟化等。

## ⚠️ 图4：同一个地址可以表示字节或字单元

### 🔹 注意提示：

> “同一个地址既可以看作**字节单元地址**，又可看作**字单元地址**，需要根据使用情况确定。”

### 🔹 示例说明：

表格



| 类型     | 描述              | 指令 | 含义                                                         |
| :------- | :---------------- | :--- | :----------------------------------------------------------- |

| 字单元   | `(0002H) = 1234H` | ——   | 地址 `0002H` 是一个**字**的起始地址，包含两个字节： - `0002H`: 34H - `0003H`: 12H → 组成16位字 `1234H`（小端模式） |

| 操作     | 指令              | 功能                                                         |

### 🔹 核心公式：

> $$

> $$

- 总单元数：$ 2^{10} = 1024 $ 个单元
- 即：**1K 个存储单元**

| :----------- | :----------- |

| 00 0000 0001 | 001H         |

| 11 1111 1111 | 3FFH         |

> ✅ **注意**：地址范围是从 `000H` 到 `3FFH`，共 1024 个地址 → 对应 1KB 的存储空间。

| **存储器分类** | 内存（主存）、外存（辅存）                                   |
| **内存特点**   | CPU可直接访问、速度快、易失性（断电丢失）                    |
| **外存特点**   | CPU间接访问、速度慢、非易失性、长期存储                      |
| **内存组成**   | 由字节/字存储单元构成，每个有唯一地址                        |
| **编址方式**   | 按字节编址，每个字节有一个地址                               |
| **地址与数据** | 如 `(0002H) = 34H` 表示地址0002H的内容是34H                  |
| **访问方式**   | - 字节访问：`MOV AL, [0002H]` - 字访问：`MOV BX, [0002H]`（取两个字节） |
| **小端模式**   | 字的低字节放在低地址，高字节放在高地址（如 `1234H` 存为 `34H`, `12H`） |
| **存储容量**   | 地址线 n 位 → 容量 = 2n2*n* 个单元                           |

------

## 🔹 一、存储器概述

> **“存储器是计算机的重要部件，有记忆功能，用来存放指令代码和操作数。”**

- 存储器的作用：保存程序（指令）和数据（操作数）
- 分为三类：
  1. **内存（主存）** —— 主机内部，由半导体器件构成
  2. **辅助存储器** —— 外部设备，通过接口连接主机（如硬盘、U盘）
  3. **高速缓冲存储器（Cache）** —— 位于主存与CPU之间，提升访问速度

- SRAM比DRAM快但贵，DRAM容量大但需刷新

## 🔹 三、半导体存储器基本结构

![图示：半导体存储器组成框图]

包含四个核心部分：

1. 地址译码器（Address Decoder）
   - 输入：A₀～Aₙ 地址信号
   - 输出：选择特定存储单元
2. 存储矩阵（Storage Array）
   - 实际存储数据的地方，每个单元存一位或多位信息
3. 三态数据缓冲器（Tri-state Data Buffer）
   - 数据输入/输出通道，控制方向（读/写）
4. 控制逻辑（Control Logic）
   - 接收 R/W（读/写）、CS（片选）等控制信号
   - 协调整个芯片的操作

## 🔹 四、存储体与编址方式

> “容量为 2n2*n* 个存储单元 → 需要 n 条地址线”

- 每个存储单元有一个唯一地址

- 若每单元存 M 位，则总容量 = 2n×M2*n*×*M* 位

- 示例：一个 

  16字×4位16字×4位

   的芯片

  - 16=2416=24 ⇒ 需要 4 根地址线（A₀～A₃）
  - 每字4位 ⇒ 4根数据线（D₀～D₃）

## 🔹 五、外围电路详解

### 1) 地址译码电路

- 将 CPU 发来的 n 位地址信号翻译成选中某个存储单元的选择信号
- 是实现“寻址”的关键

### 2) 读/写控制电路

- 包括：
  - **三态数据缓冲器**：负责数据传输
  - **控制逻辑**：根据 CS、R/W 等信号决定是否读写
- 控制信号说明：
  - `CS`（Chip Select）：片选信号，激活该芯片
  - `R/W`：读写控制，0=写，1=读

------

## 🔹 六、地址译码方式

### ✅ 单译码方式（Single Decoding）

- 所有地址线一起送入一个译码器
- 输出一条选择线对应一个存储单元
- 适用于小容量芯片（如16字×4位）

📌 图例解析：

- A₀～A₃ → 4位地址 → 可表示 16 个地址（0～15）
- 当 A₃A₂A₁A₀ = 0000，且 CS=0, WR=1 → 读取第0号单元数据

### ✅ 双译码方式（Dual Decoding）

- 把地址分成两组：
  - 行选择线 X（X₀～X₃₁）
  - 列选择线 Y（Y₀～Y₃₁）
- 使用两个译码器分别处理行和列
- 更适合大容量芯片（如 1024×1）

📌 图例解析：

- 总共 10 位地址（A₀～A₉）
- 前5位（A₄～A₀）→ X向译码器 → 32条行线
- 后5位（A₉～A₅）→ Y向译码器 → 32条列线
- 要选中某单元，必须同时满足 X 和 Y 有效
- 如：A₄A₃A₂A₁A₀ = 00000，A₉A₈A₇A₆A₅ = 00000 → 第0号单元被选中
- 若用单译码，则需要 1024 根输出线，太复杂！

👉 **双译码优势：减少译码输出线数量，节省空间和功耗**

## 🔹 七、随机存储器（RAM）——静态存储器（SRAM）

> “SRAM 内部采用双稳态电路存储二进制信息 0 和 1。”

- 特点：
  - 不需要刷新（不像 DRAM）
  - 结构更复杂，功耗较高
  - 速度快，常用于 Cache 或寄存器
- 应用场景：CPU缓存、高速缓冲区
